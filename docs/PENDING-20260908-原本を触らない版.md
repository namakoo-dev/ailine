# 保留: 原本に書く経路を無くす（2026-09-08 に方針は合意・実装は保留）

## 合意した中身

```
CLI は原本を**読むだけ**にする。作業は下書きに積み、成果物は「名前を付けて保存」で出す。
原本への上書きは**道具の機能として持たない**（人が OS 上でやるのは自由）。
```

★ GUI は既にこの形（`gui/index.html`「下書きで実行は前の結果に続けて保存します（原本は触りません）」、
`/api/save_as` は複製）。**CLI だけが逆を向いている片配線**だった。

## なぜやるか

- いま「守っている」ものを「起こり得ない」に変えられる。盲検 A の最重（削除で `#REF!` が
  原本に残る）は関所で塞いだが、関所は塞いだ穴しか塞がない。
- 買い手への説明が 1 行になる ──「あなたのファイルを開きません」。
  いまの「自動バックアップ + undo つき」は「壊れうる」と言っているのと同じ。

## ★ 保留の理由（2026-09-08・Namakoo）→ **同日に解けた**

当初「複数ファイルの扱いが未決なので下書きの規約を決められない」として保留したが、
実物を読んだら**複数ファイルの経路はもう原本を触っていなかった**（下記）。
悩んでいた N 対 1 の問題は、**そもそも下書きを要求しない側**だった。
「下書き 1 つ」は 1 冊なら自然だが、入力が複数のときに崩れる:

```
scan <フォルダ>     読むだけ            → 影響なし
stack <フォルダ>    新しいブックを作る   → 影響なし
run <A> <B>         2 冊の照合          → ★ 下書きはどちら側？出力先は？
run <フォルダ>      抽出集約            → ★ 入力 N・出力 1 のとき下書きは何冊？
帳票作成 / 様式写像  1 冊に N シート作る  → ★ 下書きの単位は冊かシートか
```

## 発火条件

複数ファイルの扱い（上の 5 経路の出力先と下書きの単位）が決まったら、同じ 1 単位で実装する。

## 決めた時のための調査結果（2026-09-08 実測）

```
inplace の言及 31 箇所／関わるファイル 5／関わる試験 42 本
```

消える／変わる／残るの内訳（★ 見た目より消える量は小さい）:

```
★ 本当に消える  原本と下書きの二択（--copy フラグ）／原本を backup から戻す restore
☆ 行き先が変わる atomic_replace_inplace → 下書きを壊さず書く
                 バックアップの世代管理 → 下書きの世代管理（undo/redo はこれで回る）
○ そのまま残る   exit 7 上書きの関所（16 箇所）★ これは「既存データを消す操作」の話で
                   ファイルの上書きとは無関係だった／undo・redo／壊れた式の関所／
                   忠実度ゲート／読み戻し／全事後条件
```

副産物: 盲検 B の摩擦「`.out` 残骸が次の実行を全面停止させる」は**この変更で消える**
（下書きが正規の作業先になるので「残骸」でなくなる）。★ だから個別には直さない。

## 発火したら戻せるように

原本を触る経路そのものは git が墓場。戻す発火条件は「フォルダ内 100 冊を一括で
書き換えたい」が実需で来た時 ── そのとき戻すのは機能ではなく、**原本を触る判断**の方。

# 決めた方針（2026-09-08 夜・Namakoo と合意）

## 実物を読んで分かったこと ── 危ないのは 1 経路だけ

```
① 読むだけ            scan / verify                          何も変えない
② 出力が新しいブック   stack / run <フォルダ> / run <A> <B>
                       ★ cmd_run_folder のコメントに明記:「原本は読むだけ・消せるのは
                         出力ブックだけ」。check_excel_lock / normalize_book /
                         バックアップ / undo のどれにも触れない
③ 入力＝出力の 1 冊    run <book> "<依頼>"（帳票・様式写像でシートを足す回も含む）
                       ★ **ここだけ**が原本を触る
```

★ **下書きは「入力」でなく「出力」に付く。** ②は出力が新規なので下書きが要らない。

## ディレクトリ構造（製品が既定として持つ）

```
プロジェクトフォルダ/
    売上.xlsx            ← 原本（読むだけ）
    請求.xlsx            ← 原本（読むだけ）
    _下書き/
        売上.xlsx        ← 下書き（**同じ名前・違う場所**）
        請求.xlsx
        まとめ.xlsx      ← N 冊 → 1 冊の出力もここ（--out は今までどおり効く）
```

噛み合う点:

```
① 名前の積み上がりが構造的に消える
   ★ GUI は名前に札を付ける方式（DRAFT_SUFFIX「（下書き）」）で 1 度事故っている:
     `…（下書き）.out（捨てた）（下書き）.out（捨てた）（下書き）.xlsx`
     場所で分ければ札を付けないので、この形が起こり得ない
② `run <フォルダ>` は**サブフォルダを見ない** → `_下書き/` は自動で対象外（既存の規約が効く）
③ 盲検 B の「.out 残骸が次の実行を exit 7 で全面停止」も消える（残骸でなく正規の置き場）
④ GUI と CLI が**同じ規約**になる（いまは GUI だけ下書き・CLI は .out.xlsx の片配線）
```

## 決めたこと

```
1  下書きの置き場   プロジェクト直下の `_下書き/`（`~/.ailine/` ではない）
                    ★ 経理事務が自分のフォルダで完結する。移動しても付いてくる
2  プロジェクトの印  **置かない**。構造そのものが印
                    ★ 「初期化しないと使えない道具」にしない
3  作るのは製品側    `ailine demo` はプロジェクトとして出す（`_下書き/` を空でも作る）
                    `run <book>` は隣に `_下書き/` が無ければ**自動で作る**
                    repo の `demo/` は出荷物そのものが推奨の形になる
4  保存             既存の「名前を付けて保存」＝ 下書きを好きな場所へ**複製**
                    ★ 原本への上書きは道具が提供しない（人が OS 上でやるのは自由）
```

## 実装時に確かめること（未確認）

```
帳票作成 / 様式写像が、いま**原本に**シートを足しているか（＝③に入るか）
★ 今日の実測で PIVOT は同じブックに『ピボット』シートを足していた → ③のはず
  だが帳票（N 枚 + 検分シート）は未確認
```

# GUI 本作成の時にやる（2026-09-08 夜・規約だけ先に決めた）

★ Namakoo「作りこむのは GUI の本作成時で構わない」。CLI 側の規約を先に置き、GUI はそれに乗る。

## ① プロジェクトの追加（登録）

★ **この道具が初めて持つ「利用者のファイルについての永続状態」**なので、原則を先に決めた。

```
ailine project add <フォルダ>     登録
ailine project list              一覧
ailine project remove <名前>     登録を外す（★ フォルダは消さない ── 断りの文言に必ず書く）
置き場  ~/.ailine/projects.json（フォルダの一覧だけ）
```

決めた原則:

```
★ 登録は**近道であって前提ではない**
   登録していないフォルダも今までどおり使える（「印を置かない」と決めたのと同じ理由）
★ ずれたら黙って直さない・推測しない
   登録に在るが実体が無い → 一覧に「見つかりません」と**名指しで出す**（勝手に消さない）
   ★ 消すと「登録したはずのが無い」になる。この repo が何度も踏んだ「在っても鳴らない」の温床
★ 中身は持たない（設定・語彙は入れない）
   持たせ始めると「プロジェクト設定」に育ち、初めての人の壁になる。順序は「最近使った順」だけ
★ remove は**フォルダを消さない**ことを文言に明記
   「削除」と読める語は事故の元（`--all` で 64 skill を消した実測がある）
```

## ② ツリー（原本と下書きの対応が見える）

★ **`ailine scan` が既に 8 割やっている**（フォルダの中身をファイルごとに 1 行・読めるか・
列が揃っているか・自分の出力を除外したことまで開示）。新しいコマンドは要らない。

足りないのは 1 点だけ ── **その原本に下書きが在るか**:

```
■ ailine scan  folder=請求2026
  5 ファイル中 5 照合できた
    売上.xlsx        取れた      ★ 下書きあり（3 手・最終 21:04）
    請求.xlsx        取れた
    経費.xlsx        取れた      ★ 下書きあり（1 手・最終 20:12）
  _下書き/  3 冊（うち 2 冊は上の原本から・1 冊は まとめ.xlsx）
```

★ 価値はツリーの形でなく**原本と下書きの対応**が見えること（「どれに手を付けたか」）。
