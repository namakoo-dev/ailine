# 盲検の合格線（2026-09-17 凍結・Namakoo 決裁）

★★ **これは直す前に置く線である。**後から自分に都合よく動かさない。
  1〜3 体目の結果や、今日直した内容から**逆算していない**（凍結の作法・棚の
  「事前登録: 反証の線を数値で先に決める」）。

## なぜ線が要るか

3 体回したが、どれも「所見が N 件出た」で終わっていて**合否を出していなかった**。
線が無いまま回すと、直した後に「今回は良かった」と言いたくなる ── それは 2026-09-17 に
1 日で 6 回踏んだ「測定器の側が壊れる」形と同じ。

★ Namakoo の言葉が定義そのものになった:
**「どんな指示に対しても到達するか、適切な断りを出すこと」**

★ これは症状の列挙ではなく**契約**である。列挙は必ず漏れる（新しい壊れ方が出るたびに
条件を足すことになる）。この形は閉じている ── **結果は 2 つだけ。それ以外は全部不合格。**

## 合格の定義

**その回に打たれた全ての指示が、次のどちらかに収まること。**

### ① 到達（4 つ全部を満たす）

| | 条件 | 出所（実際に破れた回） |
|---|---|---|
| 1 | 中身が正しい（`✓` が嘘でない） | 3 体目①（照合が単価を足して +5200）／1 体目①（並べ替えが明細に掛かり ✓） |
| 2 | 頼んでいないものを変えない | 2 体目（「印を付けて」が行追加に化け、台帳に架空の行） |
| 3 | 成果が消えない | 3 体目⑤（`--copy` の 2 回目が 1 回目を黙って置き換え） |
| 4 | 戻せる | undo（3 体目が 3 世代 md5 一致を確認・現状は満たしている） |

### ② 適切な断り（5 つ全部を満たす）

| | 条件 | 出所（実際に破れた回） |
|---|---|---|
| 1 | 本当の理由を言う | 3 体目③④（式のままで計算結果が無いことを言わず「決まりません」だけ） |
| 2 | **文言が正確** | 2026-08-26（ailine 自身が作った冊を「人のファイル」と断定）／1 体目⑦（本当の理由は列同士の比較なのに「一覧に無い」）／3 体目③④（既にそう書いている人に「例:『品目をキーに』と書け」＝実行不能な助言）／3 体目⑥（読んだだけの冊に「そのあと変更されています」・未再現） |
| 3 | 通る道を示す（逃げ道か、通る書き方） | `tests/refusal_register.json` の実測: 23 件中 **16 件がどちらも無い** |
| 4 | 終了コードが「成功」でない | 2026-09-15（全段が未対応なのに exit 0 ＋ `"ok": true`） |
| 5 | 1 バイトも書かない | 3 体目⑥（断った run が `.out` を残し、次の run を止める） |

★★ 2 の「正確」は測れる語にする ── **道具が観測していないことを主張しない**:
  - 見たこと（記録が無い／値が数えられない／語が辞書に無い）は言ってよい
  - そこからの**解釈**（誰の物か・なぜそうなったか）を**断定しない**
  - **助言は、その回の入力に対して実際に通ること**
  ★ この線は 2026-08-26 に既にコードへ書かれていた（「見たものと、その解釈を分ける」）。
    他の断りに配線されていないだけ ── いつもの片配線。

## 不合格の中の別格 ── 取り返しの非対称

★★ Namakoo:「ユーザは恥をかくだけで済むが、**俺たちに対する不信感は二度とぬぐえない**。
返金要求されてもおかしくない」。

重さは**買い手が受ける損**ではなく**こちらが失う信用**で測る。

| 種類 | 買い手の損 | こちらの損 | 例 |
|---|---|---|---|
| **見えて壊れる** | 困る・待つ | ほぼ無い（「まだできないのか」で終わる） | 語彙が無い・断られる・詰まる |
| **見えずに間違う** | 気づかず外へ持っていく | **その後に出す正しい数字も全部疑われる** | ✓ が嘘・黙って消える・断りの文言が偽 |

★ 同じ不合格でも、次に何をするかが変わる。**「嘘をつく側」は別格**として記録する。
★ 実際 3 体目の買い手は、機能の不足には買い切り 1 万円を出すと言いながら、
  間違った数字 1 つに対しては「仕入先に文句を言いに行ったら恥をかく」と言った。
  **足りないことは許されるが、嘘をつくことは許されない。**
★ 棚の線とも一致: 「順序は取り返しで決める ── 金に近い順に並べない。静かに壊れるものが先」。

## 分母 ── 何を「全ての指示」と呼ぶか

★★ その回に買い手が打った指示だけを分母にすると、**回ごとに分母が違って運で受かる**。

だから:

```
盲検 N 体目を回す
  → その回の history（ailine 自身が全 run を記録している）から
     打たれた指示を**全量**抜き出して凍結する（通ったものも、断られたものも）
  → 合否は「その回の全指示が ① か ② に収まるか」
  → 次の回の合格条件に、**過去の回の指示も含める**（退行の検出）
```

★ 現状の穴（2026-09-17 時点の実測）: 1・2 体目は設計文書に**事故になった指示しか**
残っていない。**通った指示は記録されていない** ── 退行の検出が丸ごと抜けている。
★ 救い: `ailine history` が `task` を全件持っている。次に盲検を回す**直前**に、
切り出しの仕組みを入れれば間に合う（今日は入れない ── Namakoo の決定「作り込み優先」）。

## この線で測らないもの（記録はするが不合格にしない）

★ これらは「**まだ無い**」であって「**嘘をつく**」ではない。混ぜると線がぼやける。
