# 請求書でないものを請求書と呼ばない ── 射程を「請求書」に絞り切る 1 歩目（2026-09-15）

Namakoo の線: **「今は請求書しか対応していない。例えば他の帳票はまだ未知数だから、
まず請求書で作り込んで充足させてから他の帳票も出したい」**。

★ その線を守るために製品が最初にやるべきことは、他の帳票に対応することではない ──
**他の帳票を請求書として扱わないこと**。射程の外に出たと**言う**のが、射程を狭く保つということ。
（`ailine forms` は受領した帳票の束から請求元・宛先・請求額・請求日・請求番号を読んで一覧にする。
ここに見積書が混ざって「請求額」として載れば、締めの合計が狂い、二重払いの疑いにも混ざる。）

## §1 いま在った守り（測ってから書く）

2 つ在り、どちらも**語の有無でなく構造**で測る設計になっていた:

| 器官 | 何を見るか |
|---|---|
| `unswept_mouths` | **短いセル**が 見積書／納品書／領収書 を名乗る → 「請求書ではない帳票が混ざっています」 |
| `invoice_signals` | 請求書らしさの印を**種類の違うものが 2 つ以上**要求（合計だけでは足りない ── 見積書にも在る） |

★ 「語の有無で数えない」理由は実測で決まっている: misoca のフッタに
「無料のクラウド見積・納品・請求書サービス」が在り、語で数えると**偽陽性 29 冊**だった。

## §2 ★ 実測したら、日本の実務でいちばん普通の書き方が素通りしていた

```
見積書 納品書 領収書 受領書          → 名乗りとして検出できていた
★ 御見積書 お見積書 見積り書          → 素通り（頭の 御／お と 送り仮名 で外れる）
★ 発注書 注文書 注文請書 検収書       → 素通り（語そのものが名簿に無い）
★ 支払明細書 支払通知書 入金明細      → 素通り
★ Quotation ESTIMATE（英字単独）     → 素通り（英字は和名の後ろにしか置いていなかった）
                                        実測 17 件中 9 件が素通り
```

素通りした冊は `invoice_signals`（宛名・帯・明細の見出し）を満たすので**請求書として読まれ、
見積額が請求額として一覧に載る** ── 静かな嘘。★ 取り返しの順で最上位（買い手が払う金に触る）。

## §3 処置

- 名簿を広げた: 敬称（御／お／ご）・送り仮名（見積り／見積もり）・発注／注文／注文請／検収／
  支払明細／支払通知／入金明細・英字単独（ESTIMATE / QUOTATION / QUOTE / DELIVERY NOTE /
  RECEIPT / PURCHASE ORDER / ORDER FORM / STATEMENT）
- 「短いセルだけ見る」構造は**変えない** ── 広げても偽陽性が増えない理由は語の側でなくここに在る。
  上限だけ 12 → 16 文字（`PURCHASE ORDER` は空白を畳んで 13 文字で、正規表現は当たっているのに
  この門で外れていた）。★ 判定は `^…$` の全体一致なので、長い文章は元から当たらない
  （misoca のフッタ 26 文字の陰性対照が縛る）

### 3.1 ★★ 俺の検体 24 件では見えず、実物 87 冊だけが捕まえた

書き直しの初版は **`見積書 ESTIMATE`（和名＋英字の併記）を落としていた**。旧版の正規表現は
和名の後ろに英字を許していたのに、整理する時に消してしまった。

```
俺が書いた検体 24 陽性 / 16 陰性   → 全部通った（穴は見えない）
実物の合成 87 冊（run_organ）      → 171/171 → **170/171** に落ちて捕まえた（X03 = 見積書 ESTIMATE）
直した後                           → 171/171・誤報 0 に戻る
```

★ 併記は日本の帳票で非常に多い形なのに、**俺の検体には 1 件も無かった**。
検体は作者の思い込みをそのまま持つ（`docs/検体の要件.md` §1.1 と同じ形の再演）。
★ だから広げる変更でも**実物の分母で測る**。「陽性が増えたか」だけ見て通すと、
同時に落としたものに気づかない ── 語彙は共食いする。

## §5 まだ請求書に対して残っていること（射程を広げる前に閉じる）

★ 発火条件つきで置く（断定で「やらない」と刻まない）:

- **名乗りの無い見積書**。雛形によっては帳票名を画像やヘッダに置く冊が在る。いまの守りは
  セルの文字しか見ない。発火条件: 実物で 1 件出た日（`invoice_signals` の側を強くするか、
  「請求の語が 1 つも無い」を印にするかを測ってから決める）
- **請求書と見積書が 1 冊に同居**（シートが分かれている）。`read_book` はどのシートが請求書かを
  自分で決めるが、見積シートを選ぶ回が在りうる。発火条件: 実物で 1 件
- **PDF 経由**も**同じ名簿を通る**（測った）: `pdf_grid` は Excel を知らず `Grid` を作るだけで、
  読む器官は 1 つ（`form_read`）── 座標から組み直した格子（`columns_reconstructed=True`）でも
  `見積書 ESTIMATE` / `御見積書` を名乗りとして拾い、`請求書` では鳴らないことを直接確かめた。
  ★ 残る差は「帳票名がテキスト層に残るか」で、これは変換器の側の話（`DESIGN-20260912-PDFの帳票を読む.md`
  の『PDF が物理的に持っていない情報』の家系）。発火条件: 実物の PDF で名乗りが落ちる冊が出た日
