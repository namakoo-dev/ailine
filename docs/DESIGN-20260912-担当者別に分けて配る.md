# 担当者別に分けて配る ── 設計（2026-09-12）

## §0 射程（Namakoo 決裁）

- **配布 ＝ フォルダに並べるまで**。送信はしない（外部送信は Tier 2・LLM もローカル）
- 売り物は「分ける」でなく **分けた結果を代わりに疑う** ── 空欄・表記ゆれ・分けない行・**和の証明**
- 原本は 1 バイトも触らない

## §1 測ってから決めたこと

| 測ったこと | 出た答え |
|---|---|
| 需要の原文 | 1 行の要約しか無い（`⑤ 担当者別に分割して配布`）。「配布」の線は判断で引いた（§0） |
| 既存の op | `EXTRACT`（条件で行を抜く）・`run <フォルダ>`（抜いて 1 冊に）・`REPORT_PER_ROW`（1 冊内の帳票作成）が在る。**無いのは 列の値の数え上げ／N 冊への書き分け／部分の和＝全体の証明** |
| 実表の担当者列 | 手元 83 冊に **0**（請求書ばかり）。空欄率・ゆれ・複数担当は測れない → **採点を凍結して規則を知らない側に検体を書かせる**（束と同じ） |

## §2 決めたこと

### D1 入口 ── `ailine split <一覧.xlsx> --by 担当者 --out <フォルダ>`

- `--by` は**見出しの文字**（列番号は受けない ── 人が見出しで指す）
- 見出し行は `multifile.find_header_row` で探す（1 行目決め打ちにしない ── 09-06 に 2 回踏んだ形）
- 見出しが **2 列以上**当たる（「担当」と「営業担当」）→ **分けない**。exit 4・両方を名指し
- 見出しが無い → 分けない。見た見出しを並べる

### D2 分け方 ── 値は**原本の文字そのまま**で束ねる（正規化して束ねない）

- `山田` と `山田　` は**別の冊**になる。それが実務では誤りなら、それは**表記ゆれの所見**として名指しする（D4）。
  併合して 1 冊にするのは「代わりに決める」ことで、この製品はしない
- 空欄の行は**どの冊にも入れず**、検分に行番号で並べる（空欄は誤配より安い）
- 分けない行（合計・小計・空行・備考）── ★ 判断は 1 箇所（`_BAND_LABELS` と同じ線の語 ＋ 担当者列が空で
  金額列だけが在る行）。**合計行を誰かの冊に入れる**のが最悪の混入
- 複数担当 `山田/佐藤` ── 決めない。どの冊にも入れず、**名指しして人に返す**（検体の「迷う」と同じ扱い）

### D3 出力 ── stack と同じ配管を再利用（書き写さない）

- 各冊: 見出し行 ＋ その人の行 ＋ 出所列（`元ファイル` `元行`）── `stack.PROVENANCE_HEADERS`
- 書き手の印 `creator="ailine split"`・条件 `description={"tool":"ailine","kind":"split","by":…,"value":…}`
- ファイル名は値から**安全化**（`/` `\` `:` 全角空白 → `_`）。★ シート内の値は触らない
- 関所: 出力先に人のファイル／別コマンドの出力 → exit 7（`own_output_mark`・`--overwrite`）
- workdir に書いて検算してから移動（stack と同じ）
- 一覧の冊 `_検分.xlsx`（`ailine split` の印）: 担当者ごとの行数・金額／空欄の行／ゆれの組／分けない行／証明

### D4 疑う ── 3 種類の所見（値は作らない）

| 所見 | 何を見る | 名指し |
|---|---|---|
| 空欄 | 担当者列が空の行 | 行番号 |
| 表記ゆれ | `norm` で同じになる別の文字（`山田`／`山田　`／`ヤマダ`＝カナ変換は**しない**・異体字 `高橋`/`髙橋` は NFKC が寄せない → **測ってから**） | 組と行数 |
| 複数担当 | 区切り（`/` `・` `、`）を含む値 | 行番号と候補 |

★ 語の列挙はしない。ゆれは **`norm` が同じ**（空白・中黒の同一視・部首）でだけ束ねる。カナ↔漢字は
「同じ人だと決める」ことなので、**しない**（名指しもしない ── 決められないものを指ささない）。
検体で「ヤマダ」が出たら、それは**取り逃し**として見えたまま残す。

### D5 ★ 証明 ── 部分の和 ＝ 全体（分母を出す）

```
行:   全体 N = Σ parts + 空欄 + 分けない + 複数担当
金額: 全体 Σ = Σ parts + 空欄の金額 + 複数担当の金額   （分けない行の金額は入れない）
```

- 全体は**原本**から、部分は**書いた出力を別実装（xml_readback）で読み戻して**数える
  ── 自分の書き込みを自分の記憶で数えない
- 一致しなければ exit 5（事後条件の破れ）── 出力を残さない
- 金額の列は `--amount 金額` で指す（無ければ行数だけ証明し、金額は「数えていない」と言う）
- 金額が文字（`10,000円`）の行 → 数えず名指し（読み替えない）

### D6 やらないこと

| やらない | 理由 | 発火条件 |
|---|---|---|
| 送信 | §0 | ── |
| 併合（山田＝山田　） | 代わりに決めることになる | 実需で「ゆれを寄せて」が来た時、**確認つき**で |
| 複数ブックの一括 | 1 冊で測っていない | 1 冊が通ってから |
| 担当者の列の推測（見出し無し） | 見出しで指すのが線 | ── |

## §4 実測（予測を凍結してから書いた）

予測（検体を見る前）: 誤配 0・混入 0 は設計で保証（決められない行は配らない）。
落ちるのは 不親切（ゆれの名指し・特にカナと異体字）と、見出し行の探索。

実測（検体 6 冊・宣言 93 行・実装はサブエージェント → 俺が採点し直した）:

```
正 93 ／ ★誤配 0 ／ ★混入 0 ／ 漏れ 0 ／ 証明の嘘 0 ／ 偽の疑い 0 ／ 分けた 0
不親切 3 ── 佐藤/佐藤様（敬称）・高橋/髙橋（異体字）・ヤマダ/山田（カナ）= D4 が「しない」と決めた種類そのもの
S04（担当と営業担当の 2 列）は分けずに断った（exit 4）。見出しが 1 行目でない 5 冊すべて当てた。
```

★ 実装の初版は **混入 2**（S05: 担当者の列が 1 列目で、合計のラベルがその列に入り『合計』という人の冊が出来た）。
実装者はそこを「合計の語が行のどこかに在れば、担当者が埋まっていても配らない」に**広げて**直したが、
俺の探針で `設計費／合計商事／山田／1000` が山田の冊から**消えた**（`7月合計分` も）。受け取った人は消えた行に
気づけない ── 誤爆は「⚠ 1 個」では済まない。合計行と見る形を 2 つに**狭めた**:
(a) 担当者が空で語が在る／(b) 担当者の列そのものが語。番人で縛った。

### 4.1 実装で決めた線（ASSUMED を読んで採ったもの）
- `--amount` の見出しが 2 列に当たる時も分けない（証明の分母を推測で作らない）
- 関所は「配る先フォルダの .xlsx 全部」を見る（人の資料が混ざった所へ配らない・`--overwrite`）
- `--sheet` は名前で・無ければ exit 4（黙って 1 枚目に落とさない）
- 他シート（非表示含む）は開示するだけ（判断しない）
- `ailine verify` は split の出力に「対応外」と正直に返す（`unmarked` に混ぜない・forms と同じ線）

### 4.2 やっていないこと
- 独立の検算（配る冊 1 冊では和が閉じない）── 発火条件: 配った先で「合っているか」の問い合わせが来た時
- `ailine ops` の複数ファイル一覧に split を載せる（forms も未掲載・別便）



## §5 実表が来た ── 陽性対照が初めて実データで確かめられ、穴が 1 つ埋まった（2026-09-12）

`tests/fixtures/forms/担当者一覧_表記ゆれ.xlsx`（17 行・社名は合成・Namakoo 提供）。
★ 人名の姓を 1 つ合成名に差し替えている ── 機密語の番人（`secretscan`）が実名の姓を検出して commit を止めた。**ゆれの形（半角空白／全角空白の有無）は原本のまま**。

### 5.1 陽性対照（これまで合成検体でしか見ていなかった）

```
--by 担当者名 → lookalike [['緑川 誠', '緑川誠'], ['渡辺涼', '渡辺　涼']]   ★ 実データで鳴った
```

### 5.2 埋めた穴 ── 法人格の書き方だけが違う組

`--by 会社名` で **16 冊のうち 8 冊が本来 4 社**だったのに、`lookalike` が **0** だった:

| 実際 | norm | 名指しできたか |
|---|---|---|
| `㈱アルファ` / `株式会社アルファ` | `(株)アルファ` / `株式会社アルファ` | ✗ |
| `デルタ㈱` / `㈱デルタ`（前置と後置） | `デルタ(株)` / `(株)デルタ` | ✗ |
| `イータ(株)` / `イータ株式会社` | そのまま別 | ✗ |
| `ラムダ㈱` / `ラムダ株式会社` | 同上 | ✗ |

**処置**: 名指しの鍵を 2 つにした ── ① `norm` が同じ ② **法人格の書き方を落とすと同じ**（`entity_core`）。
前置も後置も落とすので語順の違いも同じ芯になる。

★ `norm` 自体には畳まない ── あちらは `_looks_like_org`・**宛先の除外**・請求元の同定にも使われ、
測っていない所まで振る舞いが動く。**名指しの鍵だけ**に閉じた。
★ 剥がすのは**書き方が複数ある法人格だけ**（株式会社/有限会社の 3〜4 表記）。`合同会社` は 1 通りしか
書かないのでゆれを作らず、`工房` `事務所` は剥がすと『あかね工房』と『あかね』が同じに見える（別の会社でありうる）。
★ 名指しは**安全側**── 別の会社が偶然同じ芯になっても出るのは ⚠ 1 行で人が捨てられる。
**併合（同じ冊に入れる）は取り返しが付かないので、しない**（D2 のまま）。

実測: 実表で 4 組すべて名指し／⑤ の検体は **93/93・偽の疑い 0 のまま**／変異 2 通り
（芯で束ねない・工房と事務所も剥がす）で赤。
