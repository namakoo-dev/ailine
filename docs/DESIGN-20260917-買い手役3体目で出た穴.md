## §2 ①の直し ── 足し算の差額は「何を足したか」を言う

```
前: ⚠ エポキシ接着剤: +5200（A 10000 / B 4800）。明細シートで内訳を確認してください。
後: ⚠ エポキシ接着剤: +5200（A 2件 計10000 / B 4800）。★ この差額は 1 件あたりの差では
    ありません（A は複数行の合計）。明細シートで 1 行ずつ比べてください。
    ⚠ サーボモータ 400W: +1000（A 62000 / B 61000）。…（1 件どうしは**不変**）
```

★★ 直したのは `side_pair` ── その docstring に答えが先に書いてあった:
「『A 186300 / B 0』の 0 が**金額 0** なのか**1 行も無い**のか読めなかった（2026-08-24 S5）」。
**同じ関数・同じ読めなさの別の形**（今度は『A 10000』が 1 件か 2 件の合計か読めない）。
実装は 1 つ・呼び手は 2 つのままで直し、番人は**両方の読めなさを 1 本で縛る**。

★ 「明細を見てください」では足りなかった ── 買い手は ⚠ を「内訳を見ろ」と読み、
**数字そのものは正しい**と信じた。何を足したのかを画面で言う。
★ 1 件しか無い側は**今までどおり黙る**（全行に読む理由の無い語を増やさない）。
変異 6 本すべて赤（うち 1 本は「全部に『件 計』と書く」直し方を赤にする陰性対照）。

## §3 ⑦の直し ── 器官は在るが配線が 1 箇所だけだった

```
前: 検収日の列を消して → 値 8 件が消えて EXIT=0 ✓ ／ 3行目を削除して → 値 11 個が消えて EXIT=0
後: 列『検収日』には値が 8 件あります（この列ごと削除します）
    削除しますか？ [y/N]: → EXIT=7・原本は 1 バイトも変わらない
      --overwrite  削除を承知して続行する（バックアップから ailine undo で戻せる）
```

★★ 関所も、削除用の聞き文「削除しますか？」も、逃げ道の文も**既に書かれていた**。
配線されていたのは `DELETE_ROWS` で「名前が複数行に当たった」1 ケースだけ。
2026-09-07 の決裁「削除は取り返しがつかないので**必ず聞く**」が、目の前に在った
1 ケースにだけ繋がっていた。直しは `if` を足すのでなく**宣言（WRITE_REMOVE）の家系ぜんぶ**へ。

★ 鳴る条件は上書きと**対称** ── 消えるものが在る時だけ（空の列・空の行は黙って消す）。
  毎回鳴る関所は読まれなくなる（1 体目「★ が毎回出るので読まなくなった」）。
★ 数えるのは**値の個数**であって行数ではない（事後表示は空欄まで数えて「15 行」と出していた）。

★★ 検体 `test_a_name_on_one_row_is_unchanged` が正しく赤になった（Namakoo 決裁 B）。
初版の「1 行しか当たらない回は今までどおり（聞かずに進む）」は、当時**削除に関所が
1 つも無かった**から正しかった。土台が動いたので縛るものを言い直す ──
「聞くか聞かないか」ではなく**どちらの理由で聞くか**（①名前が複数行に当たった／

## §5 ③④ ── 半分は俺の検体が作った幻だった

買い手:「『品目をキーに』と書いています。道具が勧めてきた例文と一字一句同じ」
「**なぜ金額が選べないのか**が最後まで分かりませんでした」。

追ったら **1 つの原因で 2 つの症状**: 『金額』が `=E2*F2` のままで計算結果を持たない →
照合の読み（`data_only=True`・計算結果が要るので正しい）では空に見える → 数値の列と
認められない → ① 金額の候補から落ちる ② 非数値なので**キーの候補に混ざる** →
「品目と金額のどちらがキーか決まらない」。

★★ そして測ったら、**この詰まり自体は検体の作りに依存していた**:

```
式のまま（openpyxl が書いた冊）  ok=False  未解決 A/key=['品目','金額'] A/amount=['数量','単価']
計算値が入っている（実際の Excel）ok=True   key_a='品目'  amount_a='金額'
```

報告をそのまま欠陥として受け取っていたら「式の列も数値とみなす」方向に手が動き、
**①で直したばかりの「自信のある嘘の数字」を自分で作り直す**ところだった。
★ **盲検は強いが、盲検の報告もまた測定器**。同じだけ疑う。
★ 実害が当たるのは**他の道具（python 製の書き出しなど）が作った冊**。狭いが実在する。

だから直すのは断る条件ではなく**断り方**（緩める方向へは倒さない）:

```
★『金額』は**式のままで計算結果が入っていない**ため、金額の列として使えません
  （Excel か LibreOffice で一度開いて保存すると値が入ります）。
```

### ★ 測っていて自分が踏んだ穴（②を追っていて出た）

README の表は `ailine verify <出力> <元>` としか書いておらず、**元がフォルダだと
言っていない**。表に従って冊を渡すと ──

    × フォルダが見つかりません: …\元.xlsx

**ファイルは在るのに「見つかりません」**なので、打ち間違いを疑って同じことを繰り返す。
★ 直した（09-22）── 何を渡せばいいかを**全部**名指しする:

    × 『元』に冊を 1 つだけ渡されました: …\元.xlsx
      出力がブックの時、『元』はこのどちらかです:
      ・縦積み・抽出の出力 → 元はフォルダ 1 つ
      ・2 冊照合の出力 → 元は冊 2 つ
      ★ 分けた冊（split）を確かめる時は、出力の側がフォルダです

★ 陰性対照: 本当に無いパスには、今までどおり「フォルダが見つかりません」。
