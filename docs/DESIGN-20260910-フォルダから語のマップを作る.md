2026-09-10・Namakoo と合意した方針を、当日の実測の上に書く。**まだ実装していない。**

```

             N 冊を先に全部読み、列の**中身の輪郭**で役割を決め、
             同じ役割に落ちた見出しの語を束ねて、その場で語のマップを作る。
             マップは成果物として人に見せ、直せて、覚えさせられる。

## 0. なぜこの形か（当日の測定）

同じ 40 冊の合成検体（`bench/folder_map/mk_invoices.py`・見出しの語 ×4〜5 通り／
飾り行 0〜2 行／列順 4 通り／金額が文字列／合計行あり／赤伝／請求ゼロ／結合セル）で、
4 つの案を**同じ答え**（検体側が持つ `_答え.json`）で採点した。

```
                                       取引先と請求額が両方当たった   うち「推測」
現状（scan / run <folder>）                    1 / 40                   ─
層1 のみ（見出し行を各冊で推定）               2 / 40                   ─
1 冊ずつ輪郭で当てる（語を読まない）          39 / 40                  17
★ 先に 40 冊読んで語のマップを作る            39 / 40                   0
```

★ 当たった数は同じでも、**根拠の質が変わる**。「一意率が低いから多分これ」（推測 17）が
「この語は 40 冊中 10 冊で同じ役割に落ちた」（推測 0）になる。人に見せて頷いてもらえる形。

★ 残る 1 冊は語でも輪郭でもなく、**見出し行の読み違い**（2 行目を 4 行目と読んだ）。
これは「40 冊中 39 冊が 4 列なのに、この冊だけ列がずれている」という**横の証拠**で
気づける位置にある（§3.4）。

### 崩れた読みも記録する（同日）

- 「層1 だけで 1 → 27 件」と口にしたが、実測は **+1**。scan の「26 件が見出し行で落ちる」は
  同時に語も違っていた。分母を確かめずに割合を言った。
- 最初の検体は列順が全冊同じだった。**位置で当たっているのか輪郭で当てているのか分けられない**
  ので、列順をバラしてから測り直した。
- 「抽出」は在ると思っていたが、フォルダの抽出は**行の絞り込み**（同じスキーマの表を条件で絞る）で、
  需要①の「項目を集める」とは**別の操作**だった。名前から中身を推測していた。

## 0f. 凍結した判断（2026-09-11・採点の前に決める）

検体を書いた側からの申し送り ──「**割 と 単＋指摘 の線引きは検体側の判断。
買い手がどちらを許すかは聞いていない。採点の前に凍結してくれ**」。Namakoo が決めた。

```
★ 食い違ったら **値を出さない（空欄）**。両側の数字は検分シートに出す

  割（値を出さない）   根拠が 2 つ以上あって食い違う
  単（値を出す＋印）   根拠が 1 つだけ（食い違ってはいない・裏が取れていないだけ）
  無（値を出さない）   根拠が無い
```

根拠:

```
① 空欄は誤値より安い ── 経理の表で、間違った金額が入っているより空いている方が直せる
② $0 条件『黙って失敗する』から最も遠い ── 空欄 + 検分の名指しは、黙っていない
③ 単 と 割 を分ける意味がここで立つ ── 単は「まだ裏が無い」、割は「矛盾している」。
   矛盾を値で出すと、人はどちらが正しいか分からないまま片方を受け取る
```

★ 凍結する ── この線引きを**採点の後で動かさない**。動かすと、数字が良くなる方へ
手が動く（割を単に格下げすれば到達率が上がる）。変えるなら理由と日付を残して測り直す。

★ `--fill-guess` のような「印つきで値も書く」口は**作らない**（この版では）。
  発火条件: 実物のフォルダで割が何件出るかを測り、人が空欄を埋め直す手間が
  「30 分で正解」を超えたとき。

### ★★ 空欄には必ず理由を添える（Namakoo 追加・同日）

**空欄だけだと「取れなかった」と「矛盾していた」が同じ顔になる。** 買い手には区別がつかず、
「この道具は空欄を返してくる」という 1 つの印象に潰れる。区分を分けた意味が画面で消える。

```
★ 空欄のセルには、必ず**その場で**理由が読めること
   出力ブック   空欄セルにコメント（セルにぶら下がる）── 表の見た目は汚さない
                隣の区分列に 割 / 無 を出す
   検分シート   1 行 1 件で「なぜ空欄か」を名指し
                割 → 両側の数字と、それぞれの番地
                無 → 何を探して見つからなかったか（ラベル名・探した範囲）
   画面         件数と、最初の数件を名指し
```

★ 実装の縛り: **空欄を書く経路は、理由を持たずに呼べない形にする**（引数で強制する）。
  「理由を後から足す」形にすると、片方の経路だけ理由なしで空欄を書く事故が必ず生える
  ── この repo が何度も踏んだ片配線（docs/開発手法.md §13）。

★ 番人①（在ること）: 空欄のセルすべてに対応する所見が検分シートに在ること。
  空欄の数 == 理由の数 でなければ赤。片方だけ増える変異で赤くなることを確かめる。

### ★★ 番人②（適切であること）── Namakoo 追加・同日

**「空欄の数 == 理由の数」は、理由が定数文字列でも満たされる。**
「見つかりませんでした」を全件に書けば通る ── この repo が繰り返し潰してきた恒真の形。
**理由が適切か**を機械で確かめる線を、実装の前に引く。

```
(a) 区分と整合している
      割 → 両側の値と、それぞれの番地が在る（片側だけなら赤）
      無 → 何を探したか（ラベル名・探した範囲）が在る
      ★ 区分から理由の形が決まるので、導出関数と同じ 1 本から出す

(b) ★ 成果物に照らして本当である（これが「適切」の核）
      理由が番地を名指ししたら、**その番地が実在する**こと
      理由が値を挙げたら、**そのセルの実際の値と一致する**こと
      理由がラベル名を挙げたら、**その語が冊のどこかに在る**こと（無 の理由なら在らないこと）
      ★ 検算は別実装で読み戻す（本体の走査結果を再利用しない ── 再利用すると恒真）

(c) 具体が入っている（定数でない）
      理由に番地・値・ラベル名のいずれも含まない所見が在ったら赤
      ★ 87 冊の理由の**異なり数**を出す。1 種類しか無ければ、それは定数

(d) 検体が期待する名指しを含んでいる
      検体側の答えに『名指し』が在る 26 冊は、その語が理由に出ていること
      ★ 残り 61 冊は検体側から採点できない ── (a)(b)(c) で見る
```

★ **機械で確かめられないもの**（正直に書く）:

```
その理由を読んだ人が、次に何をすればよいか分かるか
  → 機械は「番地が実在する」までしか言えない。**人が読むしかない**
  → 実装したら、Namakoo に実物の検分シートを 1 枚見せて判断を仰ぐ
  ★ 既存の前例: 検分シートの薄い色は「気づかない」で一度却下されている
    （src/ailine_core/inspection.py の経緯）── 画面は人が見て決める領分
```

## 1. 何を作るか（範囲）

入力    フォルダ（直下の .xlsx・サブフォルダは見ない・既存の scan と同じ規約）
依頼    「取引先と請求額を抜き出して」のように**集める項目**を挙げる

**やらないこと（この版）**: 集計（和・件数）は出さない。既存の集計 op に渡す。
明細が複数行ある冊は複数行のまま出す。★ 「1 冊 1 行にまとめて」は別の依頼。

## 2. 2 パス

```
パス①  インポート（読むだけ・LO を起動しない）
   1  各冊: 見出し行を推定（★ 冊ごとに。基準 1 冊の行番号を全冊に当てない）
   2  各冊: 各列の輪郭を取る  空率／日付らしさ／数らしさ／文字値の集合
   3  冊をまたいで束ねる      見出しの語ごとに輪郭を集める
   4  役割を決める（§3.1）    語は 1 つも読まない
   5  少数派を捨てる（§3.2）  分母が要る判断
   6  語のマップ              役割 ← {語: 冊数}

パス②  抽出
   7  依頼の項目（取引先／請求額…）をマップの役割に当てる

   9  合計行を除いて行を集め、新ブックに書く
  10  報告（§4）
```

★ 既存の `ailine scan` はパス①の 1〜2 を「基準 1 冊だけ」やっている。**基準 1 冊の方式を
「多数派の輪郭」に置き換える**のがこの設計の中心。

## 3. 判断の中身

### 3.1 役割は輪郭で決める（語を読まない）

```
備考      空率の平均 > 0.8                 全冊ほぼ空
日付      日付らしさの平均 > 0.5
金額      数らしさの平均 > 0.5             ★ 「1,000円」「¥12,000」は数として読む
取引先    文字が並び、**冊をまたいで値が散る**（union の大きさ / 冊数 > 0.5）
固定ラベル 文字が並ぶが全冊ほぼ同じ値
```

★ 「冊をまたいで散る」が要点。1 冊の中の一意率では、明細 1 行の冊で取引先と備考が
区別できない（当日の実測: 推測 17 件はほぼこれ）。**横に見て初めて分かれる。**

★ 閾値は当日の検体で置いた仮の値。**凍結して未見の検体で測る**（docs/開発手法.md §6d）。

### 3.2 少数派を捨てる（分母が要る）

```
MIN_BOOKS = max(2, N // 20)
N 冊中 MIN_BOOKS 冊未満にしか出ない見出しの語は、マップに入れない
```

理由: 見出し行を読み違えた冊は、**データの値を見出しとして持ち込む**
（当日: `大久保商店(1冊)` `5,250円(1冊)` がマップに混ざり 39→37 に落ちた）。
「40 冊中 1 冊だけの語は語でなくデータ」は、**N が在って初めて言える**。
★ 捨てた語は報告に出す（黙って捨てない）。

### 3.3 マップで引けなければ輪郭に落ち、「推測」と印す

見出しが空の列（列順が違う冊で起きた）はマップに乗らない。輪郭で拾う。
★ ただし**その冊は「推測」区分**にする。買い手の信用条件③
「取れた／取れなかった／推測で埋めた の 3 区分」を、ここで機械の値として持つ。

### 3.4 見出し行は各冊で推定し、横の証拠で疑う

```
各冊: detect_header_row（既存）で推定
横:   列数の最頻値と違う冊、役割が 1 つも当たらない冊 → 「見出し行を疑う」と報告
```

★ 当日の残 1 冊（請求書_05）は、飾り 1 行＋見出し＋明細 2 行で、推定が明細側に寄った。
**直すのは推定器でなく報告**（推定器を検体 1 つに合わせて動かさない）。
横の証拠で「この冊だけ 4 列でない」と名指しできれば、人が直せる。

### 3.5 マップは成果物

```
画面    「取引先 ← 御中(10冊)・宛先(10冊)・顧客名(9冊)・取引先(8冊)」の形で出す
直す    人が 1 行直せる（既存の attr/alias と同じ口）
覚える  次回、同じフォルダ／同じ語なら聞かずに使う（attr に載せる）
```

★ **LLM に列の役割を聞かない**。需要地図の $0 条件「同じ入力で結果が変わる」に触れる。
将来やるとしても候補の提示までで、確定は輪郭か人。

## 4. 報告（買い手の信用条件をそのまま）

```
分母             40 冊中 39 冊から取れました
名指し＋理由     請求書_05: 見出し行を 4 行目と読みました（他の 39 冊は 4 列・この冊は 1 列）
推測の区分       取れた 37 ／ 推測で埋めた 2（見出しが空の列を輪郭で拾った）／ 取れなかった 1
両側の数字       出所の明細 61 行 → 出力 61 行（合計行 10 件を除外）
捨てた語         「大久保商店」「5,250円」（1 冊にしか出ないのでデータと判断）
失うもの         罫線・塗り・数式は持ち越しません（既存の stack と同じ文言）
```

★ 当日の実測で、`scan` と `stack` は**既にこの形で報告している**（分母・名指し・
シート名の推測を明示・両側の数字）。壊れていたのは到達であって正直さではない。
ここは既存の形をそのまま使う。

## 5. 既存との接続（★ 片配線を作らない）

| 既存 | いま | この設計 |
|---|---|---|
| `multifile.evaluate_file(…, header_row, …)` | 基準の行番号を全冊に当てる | 冊ごとに推定した行を渡す（検出器は呼び出し側から**関数で**渡す ── multifile は ailine を import しない規約） |
| `cmd_scan` の基準ファイル方式 | 1 冊目が基準 | 多数派の輪郭が基準。1 冊目は特別扱いしない |
| `cmd_stack` | 同上 | 同じ 1 関数から header_row を受ける（**scan / stack / run の 3 経路を 1 本に畳む**） |
| `run <folder>`（行の絞り込み） | 別の操作 | 触らない。新しい op として「項目を集める」を足す |
| `attr` / `alias` | 語 → 実表の何か | マップの「覚える」の置き場 |

★ 2026-08-24 の教訓（同じ形の経路すべてを 1 関数に畳む・番人は 1 本の試験で全経路を縛る）
をここで使う。header_row を「冊ごと」に変えるなら、**3 経路が同じ関数から受ける**形にする。

## 6. 検体と採点

```
bench/folder_map/mk_invoices.py     40 冊を合成（崩れ 3 点を意図的に入れる）
bench/folder_map/_答え.json         ★ 検体側が持つ答え（道具の出力から作らない）
bench/folder_map/build_map.py       設計どおりの 2 パスを素の Python で通す（LO 不要・秒で終わる）
```

★ **再現の粒度**（当日 実測）: 2 回生成して突き合わせた ──
**中身（シート名・全セルの値）は完全に一致**（sha256 の先頭 `cc9d39fa0f9ab0fd`）するが、
**バイトは一致しない**（xlsx の `docProps/core.xml` に作成時刻が埋まる）。採点は 39/40 で不変。
★ だからこの 40 冊を `tests/golden/` の作法（バイト一致）で凍結すると**毎回落ちる**。
凍結するなら中身のダイジェストで縛る。

★ **限界を先に書く**: 検体は俺が作った。日付は `2026-08-xx` 固定、金額は整数か `1,000円`。
実物の請求書は和暦・`¥12,000-`・注釈つき・空セルがある。**39/40 は上限の見積もり**であって、
実物で同じ数字が出る保証ではない。実物で測る前に、この数字を看板に使わない。

事前語ゼロ      役割を決める関数に、語の定数が 1 つも無いこと（inspect で縛る）
分母依存        少数派の足切りが N に依存すること（N=2 と N=40 で閾値が変わる）

```
