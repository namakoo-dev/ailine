# 言い回しの到達 ── 事務職が打つ日本語は `run` に届いているか（2026-09-14）

Namakoo の線: **「ここが満足できないと製品として完成しない」**。
`ailine run <冊> "<日本語>"` は事務職の唯一の入口で、語彙は 30 op 在るのに、初見 30 分の
買い手役は毎回「できることが少ない」と言って 3,000 円を付けてきた。
需要センサ（`~/.ailine/misclass.jsonl`・59 件）を読むと、詰まりは 2 種類あって**買い手には
同じ断りに見える**: (A) 本当にできない ／ (B) **できるのに届かない**。
測らずに語彙を足すのは「うま味調味料の最大化」なので、まず測った。

## §1 測定器（測る前に凍結・`scratchpad/phrasing_probe_plan.md`）

- 言い回しは**役の agent 4 体が冷たい状態で書く**（総務／営業事務／1 人経理／現場の管理者・各 30）。
  `src/` も `tests/` も `ailine ops` も見せない。「この表がある。何と打つ？」だけを渡し、
  本人が**意図を平語で**添える
- 物差しは `ailine run <冊> "<言い回し>" --dry --json` ── `--dry` は LibreOffice に触れないので
  **翻訳の到達だけ**を切り出せる（run.lock を取るので直列）
- 判定は**独立した判定者 2 人**（`C:\Dev\ailine` を読ませない・公称の操作一覧だけを基準に渡す）。
  6 値: 正／誤配（★ 最重）／部分／聞き返し／断りA（範囲外）／断りB（できるのに届かない）。
  ★ 2 人が**一致した件だけ**を数字に使う（作り手が判定すると数値が 2.5 倍動いた実測が repo に在る）
- 対照: 陽性 20（`ailine ops` の「こう書く」を自然な 1 文に）＋ 陰性 3（冷蔵庫の予約・天気・メール送信）

### 2.1 誤配 16 件は 7 つの家系に割れた

| 家系 | 件 | 実例 |
|---|---|---|
| **しきい値の捏造** | 4 | 「残業が20時間超えてる人」→ `残業時間 = 0`／「10個切ってる」→ `= 0`／「在庫少ないやつ」→ `≤ 0` |
| **確認依頼を変更操作に** | 2 | 「重複がないか**見といて**」→ 重複除去（行を消す） |
| **演算子の向き** | 2 | 「出勤と退勤から実働時間」→ `出勤 − 退勤` |
| 範囲外を近い操作で代用 | 3 | 「土日に出勤してる人」→ 日付に「土」を含む行を抽出 |
| 集計と表示の取り違え | 2 | 「部署ごとにグループ化して見たい」→ 集計（明細が消える） |
| 件数 vs 合計 | 1 | 「何件受注したか」→ 数量の合計 |
| 頼んでいない操作の追加 | 1 | 「見出しを太字に」→ 太字＋勝手に背景色 gray |

救い: 既定は**新しい冊に書く**ので原本は壊れない。被害は「壊れる」でなく「黙って違う答え」。
★ 共通の形は 1 つ ── **LLM の翻訳結果を、機械が受け入れる前に接地で検査していない**。
器（`ground`／矛盾の関所）は既に在って、検査の項目が足りない。直す順は取り返しで決めた
（Namakoo 承認・2026-09-14）: ① しきい値 → ② 確認依頼 → ③ 演算子の向き・件数 → ④ 範囲外の代用 → ⑤ 余計な段。

## §3 ① 境目の数は依頼文から機械が取る（`ailine_core/threshold.py`）

原因は 2 つ、どちらも**兄弟間の片配線**:
- 比較語の辞書が「以上／以下／未満／を超える」しか知らず、口語の「超えてる」「切ってる」
  「下回る」「上回る」を拾えない → LLM の `eq` がそのまま通る
- **SET_WHERE は 09-04 に「閾値は依頼文の数字から機械が取る（LLM に確定させない）」と直して
  あったのに、兄弟の EXTRACT には届いていなかった** → LLM の `0` がそのまま通る

処方: 器官を **1 つ**（`threshold.task_numbers` ／ `threshold.ground`）にして両方が呼ぶ。
- 依頼文の数が **1 つに決まる**時だけ採る（万／千・桁区切り・全角を畳む: 「10万円」→ 100000）
- LLM の値と違えば機械が勝つ（開示つき）／数が無い・複数なら**断る**（「少ない」の境目を 0 と決めない）
- 口語は断片ガード必須（直前 10 文字に数字・「切っ」は直前が数か数え語）── 「区切って」「締め切って」を拾わない
- EXTRACT の eq（文字列）は**列に在る値だけ**受け、無ければ在る値を並べて断る（0 行の抽出が ✓ で出る穴）
- 依頼文が無い経路（DSL を直接渡すゴールデン）は接地する相手が無いので値をそのまま
  （ゴールデン `extract_ok_numeric_gte` がこれを守った ── 初版はここで赤くなった）

### 3.1 実測（予測は凍結 → 5/5 一致）

```
「残業時間が20時間超えてる人だけ教えて」 → 抽出 残業時間 超 20
「在庫数が10個切ってるの教えて」         → 抽出 在庫数 未満 10
「在庫少ないやつ出して」                 → 断り: 境目の数が依頼文にありません（例: 在庫数が10以下の行を…）
「発注しなきゃいけないもの一覧にして」   → 断り: 列『区分』に『発注』という値はありません（在る値: 『事務用品』『消耗品』『資材』）
「金額が10万円以上の行を抜き出して」     → 抽出 金額 以上 100000
凍結済み検体（operator9 の比較語 9 件・抽出 57 件）   不変
変異 7 通り                                            全部赤（SET_WHERE だけ旧 regex に戻す＝片配線の番人 を含む）
```

## §4 ② 見るだけの依頼を「減らす操作」に写さない

```
「品名が同じなのに品番が違うものがないか調べて」 → 重複除去 判定キー:品名
「品番の重複がないか見といて」                   → 重複除去 判定キー:品番
```
既定は新しい冊に書くので原本は壊れないが、出るのは「重複を**除いた**表」で、
**どれが重複だったかは分からない**（頼んだことの逆側の表）。

★ 規則は**狭く**取った ── 確認語が**抽出**（読むだけ）に着いた依頼は盲検で **9/9 正**だった。
止めるのは「確認語が在り、変更の動詞が 1 つも無い依頼 → 減らす op（重複除去・行削除・列削除）」だけ。
- 判定は `ailine_core/intent.py`（`check_only_request` / `refuse_reducing_a_check`）に 1 つ
- 関所は `verify_dsl_args` の入口に 1 箇所（単発も複合計画の段も通る道）
- 断り文は「見つけるだけの操作はありません」と正直に言い、減らしてよいときの書き方を添える
- 依頼文が無い経路（DSL 直渡し）は触らない

変異 5 通り赤（関所を外す／変更の動詞が在っても断る／抽出も止める／依頼文が無くても止める／書き方を添えない）。

## §5 ③ 引き算の向きと、件数の穴

```
「出勤と退勤の時刻から実働時間を計算する列を作って」 → 出勤 − 退勤（符号が逆）
「担当者ごとに何件受注したか件数も出して」           → 集計 担当者 × 数量の**合計**
```
- 引き算・割り算は**向きで答えが変わる**。依頼文が向きを言っていなければ**聞き返す**
  （足し算に落とさない）。向きの読みは `threshold.direction_of` ── ★ 位置ではなく**型**で読む
  （列名は文中に何度でも現れる。初版は最初の出現だけを見て、凍結検体
  「売上と原価の間に、売上から原価を引いた利益の列を作って」を読み落とした）
- 両方の向きが文に在る回（「売上から原価を引いた列と、原価から売上を引いた列」）は**選ばない**
- ★ 関所は**自分の担当だけ**を止める: 依頼文に出てこない列が混じる回は「どの列か」の食い違いで、
  既存の関所（確認・exit 7）の仕事。実測でここを踏んだ（凍結検体が 7 → 3 に変わった）
- 集計に**件数を数える器は無い**。「何件」を数量の合計で代用せず、**数えられないと言う**
  （語彙の穴は穴と言う）。合計する列を依頼文が名指ししている回は通す

変異 8 通り赤。

## §6 ★ ① が「正だった 1 件」を壊していた（実測で気づいた）

「在庫数がマイナスになってる行を教えて」は判定者 2 人とも **正** だった件だが、
①の接地が「数が無い」として断りに変えていた ── **マイナスは数を言わずに 0 を指す語**。

（この 1 件は e2e でなく「盲検の判定」を読み直して見つけた）。
