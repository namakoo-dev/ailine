# 持っていける手法 ── ailine で実証したもの

この文書は **ailine の使い方でも設計でもない**。ここで起きた事故から取り出した、
**他のプロジェクトにそのまま持っていける手順**を置く。

書き方の約束:

- **原則は一行**で書く。長い説明は事故の側に書く
- **必ず「起きたこと」を添える**。原則だけ並べると、読んだ人には一般論に見える
- **実物の在り処を指す**。ここに書いてあることは全部この repo で動いている
- ★ 一般論は書かない。**この機械の上で観測したこと**だけを書く

---

## 測る

### 1. 書く前に 1 回走らせて、出来上がりを見る

**同じ群に見えても、出力先は違う。**

- `DEDUP` は新しいシートを作る。`SPLIT_CELL` は**その場**で右に列を足す。
  同じ「行/列を動かす」群だと思って検算を書いたら、正しい出力を 4 件 × と読んだ
- 帳票（`REPORT_PER_ROW`）は N 枚に加えて**『検分』という台帳シート**も作る。
  存在すら知らなかった。推測で書いていたら 15 件全部が × になり、
  「製品が壊れている」と報告していた

★ 費用は 1 回の実行（十数秒）。**推測で書いた検算をデバッグする費用より、必ず安い。**

在り処: `bench/basic_ops_matrix.py` の各検算の docstring（外した経緯を書いてある）

### 2. 一致は、分散の上限を示さない

**2 回続けて完全に一致したので「揺れ 0」と報告した。3 回目で崩れた。**

4 回の観測は `221 / 221 / 219 / 220`。2 回の一致は「揺れが無いこと」の証明ではなく、
**2 回の観測がたまたま一致しただけ**だった。

★ 揺れうる系（LLM を含む系）では、**観測回数を先に決めて**から測る。
　 そして記録には**中央値でなく観測の列**を残す（`observed: [221,221,219,220]`）。

在り処: `tests/battery_recorded.json` の `observed`

### 3. 分母が痩せていると、機能は測れない

同じ形を 4 回踏んだ。毎回「機能が弱い」ではなく **検体の側が足りなかった**。

| 測れなかったもの | 本当の原因 |
|---|---|
| 計算列 | 数値の列が 1 本しかない表しか無かった |
| 書式（太字・けい線） | 値の格子に出ないものを読む口が無かった |
| 重複除去・セル分割 | 重複行も区切り入りセルも表に無かった |
| 集計・帳票・参照埋め | 分類が 2 行以上ある表・雛形シート・対応表が無かった |

★ 「この機能が弱い」と思ったら、**まず分母を疑う**。

### 4. 難しい検体を足して数字が上がるなら、検体が甘い

190 件で 97.9% → 221 件で 96.4% → 230 件で 95.7%。**下がったのが健全だった。**
下がった分は、それまで測れていなかった言い方を分母に入れたぶんだ。

### 5. 検体の数字は「偶然の関係が無いこと」まで見て選ぶ

- 内線を `101 / 202 / 303` にしたら `303 = 101+202` になり、
  合計行の番人が最下行を合計と誤検出した（**番人は正しく、検体が悪かった**）
- 集計の表で経理を 1 行だけにすると「経理の合計 = 元の行の値」になり、
  **集計せずその行を写しただけでも通る**。経理を 2 行にして潰した

★ 意味が正しいだけでは足りない。**恒真になる数の組み合わせが無いか**を見る。

### 6. 断りを分母に載せる

判定が `成功 / 断り / 失敗` の 3 値だと、**断りが正しいかは人が読む**ことになる。
つまり「**断るはずの依頼が通ってしまっても、数字が 1 も動かない**」。

★ いちばん危ない向きの事故（語彙に無い操作を黙って別の操作として実行する）が
　 素通りする。`MustRefuse("理由に含まれるべき言葉")` を検体に置けるようにして、
　 「断るはず」を分母へ入れた。実際にその形の穴が 1 件見つかった。

在り処: `bench/basic_ops_matrix.py` の `class MustRefuse`

### 6b. 記録は、記録される側に偏る（生存者バイアス）

**断りが 1 件も記録されていなかった。**

道具は 3 週間ぶんの実行記録（7,000 行以上）を持っていて、
「同じ依頼が過去に何で通ったか」を思い出す材料にしていた。
ところが**断って終わった run は 1 行も書いていなかった**（断りを返す箇所が 32 あって、
そのどれも記録していない）。

結果、台帳の上では「ナットを削除して」は 47 回すべて成功に見える。
実測では **5 回に 1 回**、別の操作に化けて断られていた。
★ **いちばん知りたい「何を何と取り違えたか」が、ちょうど抜け落ちる形**だった。

★ 記録を分析に使う前に、**何が記録されていないか**を先に数える。
★ そして `成功フラグ` は「適用できた」であって「意図どおり」ではない ──
　 間違った操作でも、適用が済めば成功として残る。

### 7. 主張の範囲を切る。ただし隠さない

「壊していない率が満点」という主張は、**語彙の中で受けた依頼**についてのものだ。
「語彙に無い」と文書に明記した操作を同じ分母に混ぜると、主張の意味が変わる。

★ だから別枠にする ── **同じ画面・同じ紙に必ず併記する**。
　 分けるのは主張の範囲を正しく切るためで、数字を良く見せるためではない。
★ 逆に、**語彙の中にあるのに失敗する**検体は本体の分母に残す。そこは範囲の中の穴だ。

在り処: `bench/basic_ops_matrix.py` の `GAP_OPS`

## 守る

### 8. 番人を書いたら、壊した版で赤くなるかを試す

**在るのに、その事故の形では鳴らない番人**が何度も出た。書いた直後に必ず変異試験を掛ける。

今日それで 3 回救われた:

- 白名簿を**数字だけ**で持ったため、ある紙のために許した `93` が**別の紙でも通った**
  → `(文書, 数字)` の対に直した
- 検算の `str(None)` が `"None"` で真になり、空行を「空でない」と読んでいた
  （最初の変異試験は `""` しか試しておらず、**`None` を試していなかった**）
- 「数値でなければ失敗」と書いた検算が、`=SUM(...)` の式を全部 × と読んでいた

★ 変異試験は「番人が **1 件でも** 落とすか」でなく、**落とすべき形を列挙して全部試す**。

在り処: `tests/test_bench_checks_are_calibrated.py`（測定器そのものの試験・27 本）

### 8b. 判定には三項が要る ── 依頼 / 宣言 / 実体

**二項だと、欠けた項を代用して恒真になる。**

実際に起きたこと: 在庫表（品名・棚・数量・備考）に「**原価**の列を削除して」と頼むと、
模型が対象を `備考` に差し替え、機械は「実在する列だから」と通し、
**✓ 機械検証済み**を出して備考を消した。4/4 で再現。⚠ ですらなかった。

- **宣言**（備考を消す）と **実体**（備考が消えた）は一致している → 事後条件は通る
- 欠けていたのは **依頼**（原価と言った）と **宣言** の照合

★ 「言われたとおりにやったか」は、**実体だけ見ても分からない**。
　 三項目を渡していない検算は、`if` を足しても塞げない ── **項を渡すしかない**。

★ 関所は在ったのに鳴らなかった。絞り込みが「〜**で**」の形しか掴まなかったからだ。
　 直し方は助詞の当て推量ではなく、**宣言で分ける**こと ──
　 「この op は列を新しく作るか」は既に宣言に書いてあり、作る op なら
　 存在しない名前を言うのが正しい。手で列挙しない（列挙は漏れる）。

### 9. 数字は記録に縛る。人が手で探すと落とす

文書に散った数字を手で直そうとして、**同じ日に 2 度**古い数字を見落とした。
1 箇所直して安心した紙に、**2 つ目が同じページに在った**。

置いた番人は 2 本、どちらも記録（JSON）に繋いである:

- **古い分母の禁止** ── 「N 件中」の N が記録の件数でも白名簿でもなければ赤
- **主張の禁止** ── 記録の失敗が 0 でない間、どの文書も
  「壊していない率が満点」の類の言い回しを書けない（禁じる文言は試験側に列挙してある）

★ **印（`<!-- MARK -->`）は印の中しか守らない。** 周りの地の文は別の番人が要る。

在り処: `tests/test_battery_number_is_current.py`, `tests/_doc_numbers.py`

### 10. 白名簿は「値」でなく「(場所, 値)」の対で持つ

数字だけの白名簿は、**ある紙のための許可が全部の紙に効いてしまう**。
そして増やすときは、**なぜ歴史として残すのかを白名簿自身に書く**（宣言駆動）。

### 11. 記録には内部の恒等式を持たせる

`意図どおり + 断り + 失敗 = 検体数` を番人に要求させたら、
**回ごとの数字を継ぎ接ぎした記録**を実際に捕まえた。
三つ組は 1 回の実測から丸ごと採るしかなくなる。

### 12. 消えたものは差分に出ない

テストが全部緑でも、**名前が 1 つ消えたことは誰も教えてくれない**
（それを呼ばないテストは緑のままだから）。だから**顔ぶれを数え上げる側**を置く。

- 公開面の凍結（`import` して見える全名前と署名を記録と突き合わせ）
- 書き換えスクリプトは、**書く前に**「消えた定義が無いこと」を検算する

★ 実際に `ast.parse` は通るのに関数が 2 つ消える書き換えを 2 回書き、
　 2 回ともこの検算が止めた（ファイルは無傷）。

在り処: `tests/test_public_surface_is_frozen.py`


### 12b. 番人は、引用と主張を区別できない

**この文書自身が番人に捕まった。** 「こういう文言を禁じる番人を置いた」と説明するために
禁じた文言をそのまま引用したら、番人はそれを**古い主張**として赤くした。

選択肢は 2 つあった ── 白名簿にこの文書を足すか、引用をやめるか。
**引用をやめた。** 白名簿を増やすほど番人は弱くなり、本物の古い主張が紛れ込む余地が増える。

★ 番人に説明を書くときは、**禁じた文字列そのものを本文に置かない**。

## 直す

### 13. 同じ判断が N 箇所にあると、M 箇所だけ直る（片配線）

処方は「**両方直す**」ではない。

- **1 つの関数に畳んで、呼び出し側に判断を持たせない**
- 番人も **1 本の試験で全経路を縛る**（変異させたとき同時に赤くなることを確認する）

実例:

- `.bas` の生成側には「**数値かどうかは種別でなく値そのもので決まる**」と、
  過去の事故つきで書いてあった。**同じ教訓が表示側には配線されていなかった**
- 兄弟の op で `eq` の扱いが違った（片方は文字列を受け、片方は数字を要求した）

### 14. 宣言による門は、軸を見分けられない

「削除を宣言している段が無ければ読み直す」という門は、
**行削除と列削除を区別できない**（どちらも削除を宣言している）。

★ **軸は宣言でなく実表が決める。**
　 名指しの語が見出しに在る → 列／どこかの列の値に在る → 行／曖昧なら決めない。

### 15. 「今まで断っていた所」にだけ枝を足す

条件の解決に枝を 1 本足したとき、**数字が読み取れた回は今までどおりの道を通す**
形に置いた。結果、凍結した 641 件の入出力が **1 件も変わらなかった**。

★ 直す場所を「既存の成功が原理的に通らない位置」に置ければ、
　 退行の検証は「動かないこと」の確認で済む。

### 16. 断定で「やらない」と刻むと、未来が拾えない

見送った案は **保留 ＋ 理由 ＋ 発火条件**で書く。
「やらない」と書くと、前提が変わっても誰も再検討しない。

実例（この repo に発火条件つきで残してある）:

- 読み直しの門の鍵を「比較語」から外す案 →
  発火条件「比較語の無い言い方が実需で来たら／同じ化けが他でも出たら」
- 削除の軸を実表で決める案 →
  発火条件「同じ軸の取り違えが削除以外でも出たら」

## 書く

### 17. 検証は、本体と別実装で書く

同じ関数で作った分母は恒真になる。**検算に述語を持たせない**のがいちばん強い。

- 条件つき書換の検算は、条件を計算しない。**該当する行番号を人が先に数えて直書き**する
- 集計の検算は、合計を足さない。**期待する表を丸ごと直書き**する

★ 実測から期待値を書いた回は、**恒真になっていないかを変異試験で確かめる**
　 （合計が 1 違う／群が 1 つ欠ける／集計せず素通し、が全部落ちること）。

### 18. 改行は、ファイルごとに読んでから書く

1 つの repo に CRLF の紙と LF の紙が混在しうる。「repo の既定はこれ」と決め打ちできない。
置換文字列の中に素の `\n` を書いて、CRLF のファイルを混在させた（pre-push が捕まえた）。

★ 番人が git の index を見ている場合、**作業木を直しただけでは緑にならない**。

### 19. 合否はパイプを通さずに読む

`cmd | tail` は `cmd` の終了コードを食う。赤が素通りする。

### 20. 一括置換は 3 つの形で事故る

- 使わなくなった変数を落としたのに、**使い続ける行が残る**
- 条件を無視して置換し、**別の意図の箇所まで書き換わる**
- 走査の視野が狭く、**片方のディレクトリにしか無い文字列が 0 件になる**

★ 置換の後は必ず静的検査（`pyflakes` 等）を通す。**0 件は「無い」ではなく「探せていない」**。

## この文書の役割（2026-09-04 に決めた）

ここは**抽出元**であって、最終的な置き場ではない。

- **この文書** … 事故の詳細と、実物の在り処。**実演がある側**
- **第二の脳（記憶）** … 一行の索引と発火条件。**別の案件でも引ける側**

後日、台帳（全操作が自動記録されている）からも同じように知見を引き、
まとめて記憶へ注入する。そのときの注意:

- ★ **同じ教訓を 3 箇所に増やさない。** 記憶側は「一行＋この文書への指し」に留める。
  同じ判断が複数箇所に散ると、片方だけ古くなる（この文書の 13 番がまさにそれだ）
- ★ **既にある記憶と突き合わせてから足す。** 今日の事故のいくつかは、
  すでに記憶側に別の名前で入っている。新しく作るのでなく、そこに事件を 1 件足す
- ★ **1 回の事故では一般化しない。** 別の領域で再来したら昇格する
