# dsl-pipeline — 中間命令言語の二段構え

**分類: い（構造は渡るが、翻訳プロンプトと接地は実装ごとに再設計）**

## 挙動

`run` の既定経路。依頼はまず**翻訳**される（LLM・format json・接地 = 実在のシート名+
見出し行のみ）: 語彙 10 op のどれか / CLARIFY（確認質問を表示して exit 3）/
OUT_OF_VOCAB・FREEFORM（従来の自由生成経路へ退避）。語彙内なら **決定論 codegen**
（テンプレ・LLM 不使用・大半は検証済みヘルパへの Call）→ 適用 → **op 別事後条件**
（openpyxl で out を機械検証）→「✓ 達成を機械検証済み」。
確認行（`解釈: 操作:並べ替え 対象:金額 順:降順`）を適用前に必ず表示する。

## なぜ

- LLM の仕事を「Basic を書く」から「一行の定型文への翻訳」に縮めると、7B でも
  battery 実測 op 96.2% / slot 100%（列名接地が決め手）。幻覚の居場所が構造的に狭い
- 「LLM をプロンプトで縛らない。試みさせて、機械と人が判定する」——
  縛りが効かないことは IDFU で実証済み（設計者の実地経験）
- 列参照は**列名を正**とする。数字表記（列2）は 0/1 起点が曖昧なので断定しない
  （両解釈を許す・一意に決まらなければ CLARIFY）— 誤警報事件（2026-08-14）の教訓
- 段階的劣化: 語彙内=機械検証 / 語彙外=自由生成+9 軸+助言 / 不明=聞き返す。
  **床は「DSL 以前の全部」であってゼロではない**

- 出典: commit 23f5305・bench/translation_battery.json（凍結 battery と実測値）

## 検証挙動（GOLDEN 相当の代表）

| 入力 | 期待 |
|---|---|
| 「金額で降順に並べ替えて」 | 解釈行 → SortByColumn → 事後条件（列が実際に降順）→ ✓ |
| 「並べ替えて」（列不明） | 「？ 並べ替えたい列名を教えてください」 exit 3 |
| 「金額列を削除して」（語彙外） | 自由生成経路へ・機械検証済みとは言わない |
