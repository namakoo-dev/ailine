# freeform-gate-helper-sweep — 自由生成の関所とヘルパ総なめの機械検出

**分類: あ（設計原則そのもの — 「検証できないものは人に確認を返す」「プロンプトで縛らず
機械で検出する」は言語非依存）**

## 挙動

**自由生成の関所**: FREEFORM/OUT_OF_VOCAB 経路（DSL 語彙外の依頼を LLM に直接
Basic を書かせる経路）は、この製品で**唯一、事後条件チェッカーが存在しない**経路
である。各修復試行の適用直前に確認関所を挟む（対話なら y/N、非対話なら
**exit 8** で止める。`--allow-freeform` で明示的に承知の上で続行できる・
`ailine undo` で戻せる）。これは「破壊の関所」（既存値上書き検知）とは別の関所で、
対象も判断基準も異なる（README に「W10a の上書き関所の外」と明記）。

**ヘルパ総なめ検出**: 自由生成コードが `Call` している異なるヘルパの種類数を
数え、閾値 `_HELPER_SWEEP_THRESHOLD = 4` 以上なら「依頼と無関係な操作が混じって
いないか確認してください」という助言を、関所の y/N 直前に強調表示する（ブロック
はしない — 誤検知の可能性は残る助言止まり）。

## なぜ（一次資料つき）

operator 第 6 回ブラインド査定（実機・$25-35）で、修復ループが行き詰まると
「何か効くかもしれない」で依頼と無関係な複数のヘルパを全部呼ぶ暴走（ヘルパ総なめ）
が**3 回連続で再現**した。

★ 重要な実測知見: **この暴走はプロンプト強化では止まらなかった**。実際に止めて
いるのは Call 数の閾値による決定論的検出と、その先の関所（人への確認）だけ
——「指示は意図、保証は機械」の実演そのもの。

閾値 4 の根拠は bench の再現実験: 異常系（修復 3 回目のヘルパ総なめ、実機の
「退職済みに書き換えて」依頼で誘発）では異なるヘルパ 7 種
（AutoFitColumns/AlignCenter/FormatThousands/VLookupFromTable/PivotSum/
SummaryTable/StyleBold）を `Call` していた一方、正常な単一操作の自由生成は
0〜1 種しか呼ばない。異常(7)と正常(0〜1)の間の 4 を閾値に採用した（operator の
所見「単一操作で Call が 4 個以上」とも一致）。

## 検証挙動（GOLDEN 相当）

| 入力 | 期待 |
|---|---|
| 語彙外の自由生成が正常に単一操作を書く（Call 0〜1 種） | 総なめ助言は出ない・関所は通常どおり確認のみ |
| 修復ループが行き詰まり異なるヘルパ 4 種以上を Call | 「🚨 疑わしい」助言が y/N の直前に強調表示 |
| 自由生成の適用直前・非対話 | exit 8 で止まる（`--allow-freeform` 無指定時） |
| `--allow-freeform` 指定 | 関所を承知の上で素通し |
