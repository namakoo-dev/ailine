# verification-scope-honesty — 検証が主張する範囲は「計画どおり」であって「依頼どおり」ではない

**分類: あ（設計原則そのもの — 事後条件が何を保証していないかを言語化する話であり、言語非依存）**

## 挙動

事後条件チェッカーは「計画（翻訳が確定した op・args）が宣言した対象」を検証している
のであって、「ユーザーの依頼そのもの」を検証しているわけではない。両者が食い違う
（＝翻訳が誤って解釈した）場合でも、機械はその誤った解釈どおりに動けば「✓」を返す
— **機械は正しく動いているのに、検証していたのが依頼でなく計画だった**、という
ズレが起こり得る。

対処は 3 段構え:
1. ~~**範囲注記**: `✓` の行の直後に、範囲を限定する 1 行を**必ず**添える~~
   ★★ **単位E（2026-08-17）で廃止**: この注記（`_VERIFY_SCOPE_NOTE` /
   複合計画版 `_VERIFY_SCOPE_NOTE_PLAN`）は `✓` が出る**全ての run で必ず**出ていた ——
   発火率 100% ＝ 情報量ゼロで、誤爆する警告を批判している設計側が同じ病気にかかっていた。
   代わりに、**解決された対象を依頼文の語と機械で突き合わせ**、照合できなかった対象だけを
   名指しする run 固有の 1 文にした（照合できた run では何も出ない＝出たときに意味がある）。
   依頼文の語と矛盾する場合は、注記どころか `✓` そのものを出さない。
   詳細は [subject-provenance](subject-provenance.md)
2. **複合計画にも「解釈:」行**: 単発 DSL には元から適用前に確認行があったが、
   複合計画の各段には欠けていた。段ごとに `解釈:` 行を無条件で表示する（警告がある
   時だけ間接的に見えていた状態は不十分と判断）
3. **決定論警告**: 対象列が「この計画の直前の段で新規作成された列」であり、かつ
   依頼文に「見出し」という語がある場合に限り、列名の取り違えの疑いを警告する。
   保守的な発火条件（新規作成列 かつ「見出し」の語）に絞ることで、列名を最初から
   明示したふつうの依頼（BOLD/FILL_COLOR/CENTER_ALIGN 等）では絶対に発火しない

## なぜ（一次資料つき）

ブラインド査定（$15）が実機で再現した致命: 複合依頼「小計に数量×単価を入れて、
見出しを太字にして」で、翻訳が前段（COMPUTE_COLUMN）の演算対象名（`"数量*単価"`）を
2 段目の `BOLD` の `target` に誤って引きずった。COMPUTE_COLUMN は target 無指定
（新規列作成）のとき、見出しをその式表現そのまま（`"数量*単価"`）で書く。この
*実在するが事務上は無関係な*列名に `target` が解決されてしまうと、`check_bold` は
「対象:col:数量*単価」という**計画どおり**の検証には合格する（が依頼＝見出し行の
太字化とは無関係）。機械は嘘をついていない — 「✓ 機械検証済み」というバナーの
**主張範囲**が、実際に検証した範囲（計画）より広く読めてしまう表示側の問題だった。

- 出典: commit 414fdc3（「W10e — 検証が主張する範囲を検証した範囲に合わせる」・
  ブラインド査定 $15・致命1(構造)・E2E で決定論警告が実機誤爆シナリオで発火することを
  確認・`e2e_work/w10e/scenario1_log.txt`・`scenario2_log.txt`）

## 検証挙動（GOLDEN 相当）

| 入力 | 期待 |
|---|---|
| 単発依頼が語彙内で成功・対象が依頼文の語と照合できた | 反映後の `✓` 1 行だけ（★ 単位E: 常時の範囲注記は付かない） |
| 複合計画・全段成功・全段の対象が照合できた | 反映後の `✓` 1 行だけ（段別の行に `✓` は出ない） |
| 対象が依頼文の語と照合できない（②無言） | `✓` ＋ その対象を名指しする 1 行（[subject-provenance](subject-provenance.md)） |
| 対象が依頼文の語と矛盾する（③） | `✓` を出さない ＋ ⚠ ＋ 既存の関所で確認 |
| 複合計画の各段 | 適用前に段番号つき「解釈:」行が必ず出る（単発と同じ扱い） |
| 前段が新規作成した列を後段の target が指し、依頼文に「見出し」の語がある | 決定論警告が発火（列の取り違えの疑い） |
| 列名を最初から明示した通常の BOLD 依頼 | 決定論警告は発火しない（誤検知しない） |
