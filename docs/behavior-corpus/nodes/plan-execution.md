# plan-execution — 複合依頼の計画実行と正直な範囲表示

**分類: あ（設計原則そのもの — どの実装にもそのまま渡る）**

## 挙動

翻訳の出力は **計画 = step の列**（単一依頼は長さ 1）。語彙に無い部分依頼は
`OUT_OF_VOCAB` として**必ず計画に現れる** — 依頼の一部を黙って落とすことを構造的に
禁止する。実行は逐次で、依存つき連鎖（前段が作った列を後段が使う）は段ごとに接地を
更新して解決。報告は**項目別**:

```
1. 小計に数量×単価 → 実行: 3 行を検証
2. 税込み合計   → ⚠ 語彙外のため自由生成で実行（確認してください）
```

**段別の行は evidence（事後条件が実際に何を見たか）だけを述べ、`✓` とは呼ばない。**
総合判定は最弱の段に従う（⚠ 含む → 「⚠ 一部は確認が必要です」/ × 含む → 失敗 /
全段成功 → 総合判定の行そのものを出さない）。全段成功の run で唯一 `✓` を出すのは、
原本（`--copy` なら `.out`）が確定した後の 1 行だけ —
[verified-means-readback](verified-means-readback.md) 参照（C9 で ✓ の発生点を移した）。

## なぜ（一次資料つき）

ブラインド監査（2026-08-14・査定 $35→$20 の下方修正）が実測した欠陥への根治:
複合依頼「小計に数量×単価を入れて、税込み合計を一番下に」で、旧実装は後半を**黙って
落とし**、名指しの小計列でなく新規列に書き、その上で強い成功バナーを出した —
**バナーの主張範囲（依頼全体と読める）が検証範囲（選んだ 1 op）を超えていた**。
教訓の一般形:「言い切る範囲を、検証した範囲に正確に一致させる」。強い成功表示は
正確性が伴わない局面では弱い表示より害（過信の販売）。

| 入力 | 期待 |
