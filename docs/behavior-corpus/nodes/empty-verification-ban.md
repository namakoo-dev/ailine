# empty-verification-ban — 空虚な検証合格の禁止

**分類: あ（設計原則そのもの — どの実装にもそのまま渡る）**

## 挙動

全 9 種の事後条件チェッカーは、検証対象の件数を**必ず数える**。検証対象が 0 件のとき、
「✓ 達成」を返すことを**構造的に禁止**する（0 件は無条件で fail・「意味の無い少数」は
warn）。数値比較系のチェッカーは、非数値/None のセル（合計行・空欄等）を「対象外」として
除外して数え、除外件数を理由文に明示する（例:「5 行を検証（数値でない 1 行は対象外）」）。
チェッカー内部で例外が起きた場合はクラッシュさせず fail に変換する。

MAX_ROWS/MAX_COLS でスナップショットが切り詰められた場合、経路によって注記の意味が
異なることを正直に出し分ける（`_truncation_notice`）:
- DSL 経路（事後条件は openpyxl で out ファイルを直接開いて全行走査＝MAX_ROWS 非依存）
  では「表示のみ切り詰め・検証・適用は全行に対して実施」
- FREEFORM 経路（no-op ガード・advisories が `snapshot()` 頼み）では「検証も先頭
  MAX_ROWS 行のみ」— 検証自体が切り詰めの影響を受けることを隠さない

## なぜ（一次資料つき）

ベースライン D 検体で「三層同時沈黙」（検証対象 0 件を無言で合格扱いにする）が実際に
起きた。3 つの独立したチェッカーが同時に「対象なし」を「✓」と誤読していた —
偶然ではなく、各チェッカーが個別に「0 件なら真」というループの空虚な真（vacuous
truth）に落ちる同型のバグを持っていたということ。「検証した」と「検証すべきものが
無かった」を区別しない設計は、事後条件という安全装置そのものを無効化する。

- 出典: commit 0cf9218（「空虚な検証合格の禁止+事後条件の None 安全+表示切詰の正直化」
  W1.5・テスト 211→231・実機: D 検体が ✓→× exit 1 に、C 式ブックの並べ替えが
  クラッシュ→数値行のみで機械検証に変わったことを確認）

## 設計上の不変条件（削ってはならない線）

- 「0 件 = ✓」を許す近道は**絶対に取らない**。検証対象が無いなら fail（× か warn）で
  正直に言う。この禁止を緩めると、事後条件全体が「何も検証していないのに検証済みと
  名乗る」経路に戻る

## 検証挙動（GOLDEN 相当）

| 入力 | 期待 |
|---|---|
| 対象列が全行 None/非数値 | fail（「機械検証できなかった」・✓ にしない） |
| 対象行の一部が非数値（合計行等） | 除外件数を明示した上で残りの行だけ検証（pass/fail） |
| チェッカー内で例外発生 | クラッシュせず fail に変換 |
| MAX_ROWS 超過ブック・DSL 経路 | 「表示は先頭 N 行のみ・検証は全行」と正直に注記 |
| MAX_ROWS 超過ブック・FREEFORM 経路 | 「検証も先頭 N 行のみ」と正直に注記（限界を隠さない） |
