# progress-and-diff-humanization — 進捗表示と差分の人間可読化

**分類: あ（UI 表示の設計原則 — 出力先や文言は実装ごとに変わるが、方針はそのまま渡る）**

## 挙動

**進捗表示**: 生成中・LibreOffice 適用中・初回準備（正規化パス）の各段階で、開始行を
`stderr` に出す（改行しない＝完了時に経過秒を追記する。`--json` 指定時も常に `stderr`
に出す — `stdout` の機械可読出力を汚さない）。凝った演出（スピナー等）はしない —
Windows コンソール安全第一。複合計画では段番号つきの進捗（例:「⏳ 2 段目 LibreOffice
で適用中…」）になる。

**差分の人間化**: セルの変化は `describe_cell_change` が (値, 数値書式, 背景, 太字,
罫線, 配置) の生 tuple を直接表示せず、**変わったフィールドだけ**日本語ラベルで
列挙する形式（`B2: 値 'りんご'→'リンゴ', 太字 (空)→True`）に変換する。片側のセルが
`snapshot()` の辞書に無い（＝完全に既定状態）場合は、既定 tuple で埋めて比較する —
ただし**全フィールドを None で埋めると「数値書式 None→General」という偽の差分を
作ってしまう**罠が実測で見つかっており、既定値は各フィールドの本当の既定
（`"General"` 等）で埋める。`--json` の構造化出力（生 tuple 相当）はこの人間化と別に
維持される（機械可読性を犠牲にしない）。

## なぜ（一次資料つき）

冷間監査（初見ユーザー役）が実測した 5 つのギャップのうちの 2 つ:
- 生成/適用中の完全な沈黙（何が起きているか分からず不安になる／固まったと誤解する）
- セル差分が Python の生 tuple のまま表示され、初見ユーザーには読めない

進捗表示・差分の人間化はいずれも「保留（GUI 導入で形が動く見込み）」として一時
ノード化を見送られていたが、（当時）GUI は当面作らない方針だったため、CLI 表示として
そのまま挙動を確定し、ここに書く。

- 出典: commit 688eab7（「M1 硬化 — 進捗表示・適用タイムアウト既定 180s・doctor・
  実行履歴・差分の人間化」テスト 28→70）

## 検証挙動（GOLDEN 相当）

| 入力 | 期待 |
|---|---|
| 通常実行（`--json` 無し） | stderr に「⏳ 生成中 (model)…」「⏳ LibreOffice で適用中…」が経過秒つきで出る |
| `--json` 指定 | 進捗は stderr に出続ける・stdout は機械可読 JSON のみ |
| セル値のみ変化（書式は既定のまま） | 差分表示は「値 x→y」だけ（数値書式等の偽の差分行が出ない） |
| 複合計画（2 段） | 各段の進捗が段番号つきで出る（「2 段目 LibreOffice で適用中…」） |
