# run-history — 実行履歴（需要センサー）

**分類: あ（純ロジック・そのまま渡る）**

## 挙動

各 `run` の終わりに `~/.ailine/history.jsonl` へ 1 行 append:
ts(ISO)/book/task/model/ok/attempts/失敗種別(bad_signature|runtime_error|noop|none)/
変更サマリ先頭 3 件/出力パス。`ailine history [--max N]` が新しい順の表で表示。
**履歴の書き込み失敗で run 本体を落とさない**（WARN のみ — 履歴は本体機能の従者）。

## なぜ（設計意図 — 単なるログではない）

履歴は**ヘルパ昇格経済学の需要センサー**を兼ねる（2026-08-14 設計判断）:
どのタスク型が繰り返し失敗するかの実測が、新ヘルパを追加する判定根拠になる。
想像でヘルパを盛らない — カタログはプロンプトを希釈するコストがあるから、
一枠は実測の失敗率だけが正当化する。失敗種別を構造化して記録するのはこのため。
