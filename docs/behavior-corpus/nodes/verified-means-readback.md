# verified-means-readback — `✓` は「あなたのファイルは今こうなっている」1 種類だけを意味する

**分類: あ（設計原則そのもの — 表示が何を主張してよいかの話であり、言語非依存）**

## 挙動

`✓` を出せる場所は **1 箇所だけ**: 原本（`--copy` なら `.out`）への反映が確定した**後**に、
その最終ファイルを openpyxl で開き直して観測できた時。意味は 1 種類に固定する ——
**「あなたのファイルは今こうなっている（機械が読み戻して確かめた）」**。

そのため:

1. **段別の行に `✓` は付かない**。各段は evidence（事後条件が実際に何を見たか。例:
   「3 行を検証（降順）」）だけを述べる。段が成功したことは伝えるが、それを `✓` とは呼ばない
2. **`--dry` は主張を持つ型（Claim）を構築しない**。実行経路と同じレンダラへ
   「成功」相当の status を流し込むのをやめ、プレビュー専用のレンダラに分ける
3. **総合の `✓` は反映が確定した後に 1 回だけ**。`--copy` のときは `.out` を名指しし、
   原本が無変更であることを同じ場所で言う
4. **失敗して終わる run は必ず「原本は変更していません」と、`.out` が残っていることを言う**
5. **読み戻せなかったら `✓` は出さない**（`⚠ … 読み戻して確認できませんでした`）
6. 型で塞ぐ: `Claim(verified=True)` は `observed_after_apply=True` かつ `observed_on`
   （読み戻したファイルのパス）が無ければ**構築できない**。文言ではなく型が禁止する

`✓` に載せる evidence は、**最終ファイルだけから独立に再導出できる事実**に限る
（シート名・行数・列数・値のあるセル数）。

### ★ 採らなかった設計（不健全）

「最終ファイルで全段の事後条件を再実行して `✓` を出す」。`APPEND_TOTAL` の後に `SORT` が
来れば合計行の位置は**正当に**動き、合計行を「対象列に `=SUM(` が最初に現れた行」として
探す事後条件は、**正しい run を偽 fail にする**。読み戻しは「反映が成功したこと」の確認で
あって、検証のやり直しではない。

## なぜ（一次資料つき）

独立したブラインド査定 2 本が、揃って「`✓ 機械検証済み` が **3 つの異なる意味**で出る」と
書いた:

1. 原本に入った
2. **入っていない**（複合計画の別の段が失敗して全段破棄。それでも成功した段に `✓` が出て、
   しかも「原本は変更していません」の行が無い）
3. **そもそも実行していない**（`--dry` が `✓ 機械検証済み（未実行・プレビューのみ）`）

査定者の言葉:「**毎回 openpyxl で開くまでファイルがどうなったか分からなかった。この道具の
一番の売りは検証なのに。**」

真因は**位置**だった。段別 `✓` は段別報告の整形時に、`--dry` の `✓` はプレビューの整形時に
確定しており、どちらも**原本反映の可否が決まる前**だった —— `✓` は最終ファイルを一度も
読み戻していなかった。文言を足す（範囲注記）では直らない種類の欠陥で、`✓` の**発生点**を
「原本が確定した後の 1 箇所」へ動かすのが唯一の根治になる。

## 検証挙動（GOLDEN 相当）

| 入力 | 期待 |
|---|---|
| `--dry`（単発 / 複合計画とも） | `✓` は 1 つも出ない。「実行予定（未実行）」と述べるだけ |
| `--copy` で成功 | `✓` は `.out` を名指しし、直後に「原本 … は変更していません」 |
| 既定（原本直接）で成功 | `✓` は原本を名指しし、直後に「もとに戻す: ailine undo」（undo の案内は 1 回だけ） |
| 複合計画の途中失敗（全段破棄） | `✓` は出ない。「原本 … は変更していません。作業結果は … に残っています」 |
| 単発の事後条件が warn（検証対象不足） | `✓` は出ない（⚠ 側で読み戻し結果だけを述べる） |
| `APPEND_TOTAL` → `SORT` | `✓` が出る（事後条件を再実行する設計なら偽 fail になる並び） |
| 原子的置換が失敗し copy2 へフォールバック | `✓` の意味は変わらない（原本を読み戻して確かめる） |
| 反映後に最終ファイルを開けない | `✓` は出ない（`⚠ … 読み戻して確認できませんでした`） |

★ 上の表は事前登録した合否バーそのもの:「**`✓` が出た全 run について、run 終了後に別プロセスが
openpyxl で原本を開き、claim の evidence を独立に再導出できる — 例外 0 件**」。
機械化は `tests/test_readback_claim.py`（再導出は subprocess で別 python を起動し、
`ailine` を import せず openpyxl だけで行う）。
