# undo-walk-and-edge — 世代バックアップの遡りと履歴の端

**分類: あ（純ロジック・そのまま渡る。置き場のパス規約だけプラットフォーム寄り）**

## 挙動

`run` は原本を上書きする前に必ず `~/.ailine/backups/<フォルダのハッシュ>/` へ世代を退避する。
`ailine undo` はその世代列を**新しい順に 1 段ずつ**遡る。現在地は履歴の位置ではなく
**中身の一致**で決める（book の現在の中身と同じ世代があれば、そのすぐ古い方が次の復元先。
一致するものが無ければ＝実編集の直後なので最新世代へ戻る）。真実の源はバックアップ
ファイル自体で、`history.jsonl` には依存しない（履歴が壊れていても undo できる）。

**端で止まる。** 最も古い世代に着いていたら復元せずに
「これ以上は戻せません（最も古い状態です）」と言って**非零**（既存体系の 1＝汎用の失敗。
新しいコードは足さない）で終える。押し続けても状態は動かない。

**undo 自身の退避は遡りに数えない。** undo は「復元前の現状」を必ず退避するが、置き場は
`backups/<ハッシュ>/undo/` で、遡りの世代列（名前空間ディレクトリ直下）とは分ける。
`undo --list` は世代の一覧に加えて棚の件数を 1 行だけ添える（数えないが捨ててはいない）。

**「あと N 回戻せます」は残り段数**（バックアップの総数ではない）。現在地が世代列の i 番目なら
`len-1-i`、現在地がどこにも無ければ `len`。最後の 1 段を戻すと `あと 0 回` になり、次は端で止まる。

## なぜ（実測した壊れ方 — 数え方と参照点の問題として直した）

盲検査定 A が致命に挙げ、合成データで再現した（編集 2 回のあと undo 4 回）:

| | 中身 | 表示 | |
|---|---|---|---|
| undo1 | v1 | あと 3 回 | 正しい |
| undo2 | v0 | あと 4 回 | 正しい（多段で遡れている） |
| undo3 | v0 | あと 5 回 | ★ 何も変わらないのに「✓ 復元した」 |
| undo4 | **v1** | あと 6 回 | ★ 打ち消したはずの変更が復活 |

**多段 undo 自体は成立していた。壊れていたのは履歴の端に着いた後**。原因は二つの重なり:

1. **端で止まらない** — 最古に着くと『そのすぐ古い方』が無いので同じものを復元し、成功を名乗っていた
2. **undo 自身の退避を同じ棚に積んでいた** — 端の後は「現在の中身と同じ退避」が最新世代として
   並ぶため、中身一致で決める参照点が i=0 に吸い寄せられ、その 1 つ内側＝**直前に打ち消した状態**を
   釣り上げる。表示の「あと N 回」も総数を数えていたので押すほど増えていた

★ **症状の「3 回目で復活」は編集回数で変わる**（N=1 なら 2 回目で復活）。バーは症状の数字でなく
構造で書く: **編集 N 回 → undo N+2 回**、1〜N は一段ずつ、N+1 で止まり、N+2 でも動かない。
`tests/test_ailine.py::test_undo_walks_back_then_stops_at_the_oldest` が N=1,2,3 で固定する。

★ **バックアップを消す方向では直していない。** 安全網（＝undo を可逆にする退避）は
そのまま残し、**数える場所と遡りの参照点から外した**だけ。既存のバックアップ資産は
形式も置き場も変わらないので、そのまま遡りの対象として読める（移行不要）。
