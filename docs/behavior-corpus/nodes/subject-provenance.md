# subject-provenance — 解決された対象の「出所」を3段階に分け、`✓` の強さを変える

**分類: あ（設計原則そのもの — 「どこを操作するか」を LLM に確定させず機械で照合する、
という A' 原則の適用範囲の話であり、言語非依存）**

## 挙動

翻訳（LLM）が決めた**対象スロット**（どの列・どの行・どのシートを操作するか）について、
解決値が依頼文の語と機械照合できるかを判定し、出所を3段階に分ける。

| 段階 | 意味 | 振る舞い |
|---|---|---|
| ① 照合できた | 解決値が依頼文の語と機械照合できた | `✓` 満額（何も足さない） |
| ② 無言 | 依頼文はその対象について何も言っていない（ブックの実体・既定から機械決定） | `✓` は出す ＋ その run 固有の1文で範囲を狭める |
| ③ 矛盾 | 依頼文にその対象を指す語があるのに、解決値と一致しない | **`✓` を出さない** ＋ ⚠ ＋ 既存の関所で確認 |

- **② は主張の範囲を狭めるだけ・③ だけが止める。**「証拠が無い」ことを「反証がある」ことと
  同じに扱うと、まっとうな run が軒並み止まる。
- ③ の確認は**既存の関所を再利用**する（原本へ直接反映する時だけ聞く・`--dry`/`--copy`/
  `--ask`/`--overwrite` では素通し・拒否は 1・非対話は 7）。**新しい終了コードは作らない。**
- ③ で人が「続行」を選んでも `✓` は出さない。`✓` は「機械が確かめた」の意味であり、
  人の承諾は機械の照合の代わりにならない。
- 対象シートは**複数シートのブックだけ**が判定対象（1枚のブックに「どのシートか」の曖昧さは
  存在しない＝単一シート帳票の出力は1バイトも変わらない）。

### 照合の定義（凍結。数字を見てから動かさない）

解決値 `V`（実在列名・実在シート名）が依頼文と照合できたとは:

1. `V` が依頼文に部分文字列として現れる（既存の3箇所の慣行と同じ規則）。ただし
   **その出現が、他の実在名の一部としてしか説明できないなら証拠にしない**、または
2. `V` の長さ2以上の連続部分文字列 `s` が依頼文に現れ、かつ **`s` が他のどの実在名にも
   現れない**。

(2) は「人は実在名を短く言う」（実列名『小計金額』を「小計の列」）を拾うため。
無条件の双方向部分一致にしないのは、`数量*単価` の断片『数量』が**別の実在列**でもあり、
それを証拠に認めると症状そのもの（下記）が①として素通りするため。**曖昧な断片は証拠に
しない**、という一点だけが両方向の要求を同時に満たす。

(1) の但し書きは**単位B（2026-08-18）で足した**。列が『商品/金額/税込金額』のブックで
「税込金額で並べ替えて」→ 解決値『金額』が①になり、**税抜きの列が並べ替えられたまま `✓` が
出ていた**（事後条件は「2 行を検証（昇順）」と正しく通る ―― 計画どおりではあるから）。
『金額』は依頼文に確かに現れるが、その出現は『税込金額』の一部としてしか説明できない。
逆向き（依頼「金額で」→ 解決値『税込金額』）は元から③で正しく、**片方向だけ抜けていた穴**
だった。同じ排除は「依頼文が指している対象」（designator）側にも当てる ―― 当てないと ⚠ が
「照合できません（依頼文が指しているのは: 金額・税込金額）」と自己矛盾して読め、さらに
『税込金額』を拾った次の段が、そこに埋まっているだけの『金額』で誤って③に落ちる。

### 反証は「誰も拾わなかった語」だけ

素朴に「依頼文にどれか対象の語がある」を③の条件にすると、複合依頼で必ず誤爆する
（実測: 依頼「金額で降順に並べ替えて」＋計画 [SORT 金額 / BOLD row:1] の2段目）。
そこで①になったスロットが照合した語を**消費**として記録し、消費されずに残った語が
ある時だけ③とする。計画が実際に使った入力列（`COMPUTE_COLUMN` の演算対象）も消費する
—— これが無いと「売上から原価を引いた利益列を作って、利益で降順に」という**正しい**連鎖で、
誰にも拾われないままの『売上』『原価』が2段目の反証に化ける（実測で掴んだ誤爆）。

### 金額の性質の限定（税込み/税抜き）

依頼文が金額の性質を限定しているのに、解釈のどこにもその限定が現れていない場合も③
（`APPEND_TOTAL` のラベル）。率が機械確定していれば「率:1.1（依頼文: …）」として解釈行に
出ているので問わない。対象列そのものが『税込金額』なら限定は解釈に現れているので問わない。

## なぜ（一次資料つき）

ブラインド査定2本が**独立に**致命の筆頭に置いた症状:

```
$ ailine run 注文書.xlsx "数量と単価をかけた金額列を作って、見出しを太字にして"
  2段目: 解釈: 操作:太字 対象:col:数量*単価
2. 操作:太字 対象:col:数量*単価 → 実行: 4 セルが太字
✓ …機械検証済みの内容です
```

読み戻すと見出し行は太字でなく、新規列 E がまるごと太字だった。
**依頼文には「見出し」という語がある。解決された対象は `col:数量*単価`。この2つは矛盾して
いるのに、機械はそれを一度も突き合わせていなかった。** 足場は既にあった —— 倍率・書き込む値に
対する `_sources`（出所の記録）と「LLM の値 vs 機械抽出の値の食い違い警告」は同じ形の仕掛けで、
**値**にしか適用されていなかった。それを**対象スロット**へ広げたのがこのノード。

同じ回で、`✓` の直後に必ず出ていた常時注記（旧 `_VERIFY_SCOPE_NOTE` /
`_VERIFY_SCOPE_NOTE_PLAN`）を廃止した。**`✓` が出る全ての run で必ず出る＝発火率 100% ＝
情報量ゼロ**であり、誤爆する警告を批判している設計側が同じ病気にかかっていた。
範囲を明示するという役割そのものは否定されていないので、②の run 固有の1文として残した。

- 出典: 単位E（2026-08-17）・単位B の残り2件（2026-08-18）。電池は
  `tests/test_subject_provenance.py`（事前登録したバー2本＋部分文字列の両方向の対照の対を
  凍結）・端末トランスクリプトは `tests/golden/f9_transcripts/subject_contradiction.txt` /
  `subject_substring_contradiction.txt` / `subject_unspoken_note.txt`

### ⚠ は同じスロットについて1本だけ（単位B）

手書きの決定論警告（[verification-scope-honesty](verification-scope-honesty.md) の③・
`_maybe_warn_header_col_mismatch`）と一般則の③が**同じスロット**で同時に鳴ると、意味の違う
⚠ が2行並び、しかも前者が助言欄にも再掲されていた（同じ事実を3回言う）。今は前者が持つ固有の
事実を後者の注記へ畳み込み、**⚠ は1本**にする ―― 「対象『col:数量*単価』（この計画の直前の段で
新規作成された列）は依頼文の語と機械照合できません（依頼文が指しているのは: 見出し）」。
畳み込んだ場合は助言欄への再掲もしない。★ 手書きの `if` を**消したのではない**: 一般則が沈黙
する反例（下記「残っている限界」）では今までどおり単独で鳴り、助言欄にも従来どおり載る。
文言の出どころは `ailine_core/dsl_step.py` の `NEW_COLUMN_ORIGIN` 1箇所（両者が同じ定数を
読むので、片方だけ書き換わって食い違うことがない）。

## 検証挙動（GOLDEN 相当）

| 入力 | 期待 |
|---|---|
| 「見出しを太字に」→ 対象が前段の新規列 `col:数量*単価` | `✓` を出さない・⚠「対象『col:数量*単価』（この計画の直前の段で新規作成された列）は…依頼文が指しているのは: 見出し」**1本だけ** |
| 「税込金額で並べ替えて」→ 解決値『金額』（同じブックに両方の列が在る） | `✓` を出さない・⚠「依頼文が指しているのは: 税込金額」 |
| 「金額で並べ替えて」→ 解決値『税込金額』（上の逆向き） | `✓` を出さない・⚠「依頼文が指しているのは: 金額」 |
| 「金額を降順に」＋ 同名シート『金額』との衝突で1枚目へ後退 | `✓` を出さない・⚠「対象シート『売上データ』は依頼文の語と機械照合できません」 |
| 「税込み合計を出して」→ ラベル『合計』・率は未確定 | `✓` を出さない・⚠「金額の性質を限定していますが…」 |
| 「税込金額の合計を出して」→ ラベル『合計』（対象列に限定がある） | `✓` は出る（誤爆しない） |
| 「小計の列を太くして」→ 実列名『小計金額』 | `✓` は出る・注記も出ない（①） |
| 「売上から原価を引いた利益列を作って、利益で降順に」 | `✓` は出る ＋「対象『売上-原価』は依頼文の語と機械照合していません」（②） |
| 「太字にして」→ `row:1` | `✓` は出る ＋ ②の1文 |
| 「金額の列を太字にして」→ `col:金額` | `✓` は出る・何も足さない（①） |
| 1枚だけのブック | 対象シートは判定対象にしない（出力は従来どおり） |

## 残っている限界（正直に）

- 前段が作った新規列の名前が**依頼文にそのまま出ている**場合（「…税込金額の列を作って、
  見出しを太字にして」）、一般則は『税込金額』を①と判定して沈黙する。依頼文のどの語が
  どの段に属するかは、DSL 段が段ごとの依頼文を持たない以上、機械では分けられない。
  この1件だけは手書きの決定論警告（[verification-scope-honesty](verification-scope-honesty.md)
  の③）が拾うので、その手書きの `if` は**残した**（実測で確認した反例が
  `tests/test_subject_provenance.py::TestGeneralRuleVsHandWrittenIf` にある）。
- 判定結果は表示にだけ効き、`--json` には出していない（`claims` の型を変えないため）。
