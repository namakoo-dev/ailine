# destruction-gate-declarative — 破壊の関所と OP_WRITE_TARGET の宣言駆動

**分類: あ（設計原則そのもの — 「op ごとの if でなく宣言を読む」は言語非依存の骨格）**

## 挙動

原本へ直接反映する既定経路で、**既存データへの上書きが起きる操作**は
`--ask` 無指定でも確認を挟む（「破壊の関所」）。確認では上書きされる既存値の件数を
表示し、対話なら y/N、非対話なら **exit 7** で止める（`--overwrite` で明示的に
承知の上で続行できる・`ailine undo` で戻せる）。複合計画では段ごとにこの関所を通し、
原本（book）はどの段が拒否されても無傷のまま止まる（`out_book` はコピーで作業して
いるため）。

この関所が「どの op のどの引数が書き込み先か」を知る方法は、**`OP_WRITE_TARGET` と
いう宣言テーブルを読むこと**であって、op ごとの `if` 分岐ではない。新しい op を追加する
開発者はこの宣言に必ず登録しなければならない — それを**機械的に強制するテスト**
（`test_op_write_target_declares_all_ops`）が「`OP_SCHEMA` の全 op が
`OP_WRITE_TARGET` に宣言を持つ」ことを検査する。同じ宣言は、新規列/新規行/新規シート
作成のゴースト警告の中立化（意図した新設を誤警報しない判定）や、参照専用シートの
「変更されていません」の抑制でも共有される（検出ロジックを二重管理しない）。

### 宣言の中身は「列」でなく「領域」

各 op は次の 4 つを宣言する。

| 項目 | 意味 |
|---|---|
| `writes` | **書く領域の種類**（既存列 / 新規列 / データ末尾の新規行 / 新規シート / 書式のみ / 行の挿入 / 並べ替え）。空は不可 |
| `col_key` | 書き込み先**列**を指す引数キー（既存列を書く op だけが持つ＝破壊の関所の対象） |
| `sheet_key` | 対象シート名を指す引数キー（無指定なら解決済みの対象シート） |
| `reads_only` | **参照専用**シートを指す引数キー（そのシートが無変更なのは正常） |

初代の宣言は `(col_key, sheet_key)` か `None` の 2 択で、**「どこに書くか」を列でしか
言えなかった**。そのため助言の側は宣言を読めず、依頼文の表層語や列の形で代用し、
毎回・確実に再現する誤警報を 2 種類出していた:

- **合計行**（`APPEND_TOTAL`）は定義上ずっと元データの使用範囲の外に出るため、
  成功するたび「★ 疑わしい: 変更が元データの範囲外です」が出ていた。
- **新規シートにしか書かない op**（`AGGREGATE` / `PIVOT`）は、名指しされた入力シートを
  読むだけなのに「★ 依頼で言及された『〜』は…変更されていません」が出ていた。

どちらも `writes` / `reads_only` の**宣言**で消した（op ごとの条件分岐を足すのではなく）。
中立化は保守的に留める — 例えば「データ末尾の新規行」の宣言があっても、元データの
**列範囲より外**へ出たセルが混ざっていれば警告は出したままにする。

宣言が宣言として成立していること（未知の領域種類・空の `writes`・「既存列を書くと
言いながら書き込み先列を指さない」等の自己矛盾）も番人テストが検査する
（`test_op_write_target_declarations_are_well_formed`）。

### 宣言した領域には「前提」がある（単位F）

`writes` は「どこに書くか」を宣言する。**その宣言には、成立していなければならない前提が
ある**。関所はその前提が破れた時に鳴る。

| `writes` | 前提 | 破れたら |
|---|---|---|
| `new_column` | その列は空 | 上の関所（書き込み先列の既存値を数える） |
| `new_row_at_end` | 書き込んだ行は適用前に空だった | 同じ関所へ |
| `new_sheet` | その名前のシートは適用前に存在しない | 同じ関所へ |
| `existing_column` | （前提なし＝上書き前提） | 上の関所 |
| `format_only` | 値が 1 つも変わらない | 同じ関所へ |
| `row_shift` / `reorder` | 値の多重集合が保存される | 同じ関所へ |

初代の関所は `col_key`（書き込み先**列**）を持つ op しか守れなかった — 入口の 1 行
`if not write_target.col_key: return None` により、**16 op 中 13 op が素通り**していた。
行に書く op も、シートに書く op も、守る腕が無かった。実測された致命が 2 件:

- 既存の合計行（A 列が空）があるブックへ「合計を出して」 → その行の値 116600 を
  `=SUM(...)` で**上書き**して 106000 になった（差 10,600）。画面には
  `D4: 値 116600→'=SUM(...)'` と**破壊が表示されている**のに関所は鳴らず、
  `✓ 機械検証済み（式・キャッシュ値・ラベルとも一致）` が出て exit 0。
- 無関係な手作りの『集計』シート（年度/予算）があるブックへ集計を依頼 →
  `SummaryTable` の `If oDoc.Sheets.hasByName("集計") Then removeByName("集計")` で
  中身が全滅。y/N も無く exit 0、しかも
  「（既存シート『集計』の更新は意図どおりです）」という**肯定文**まで出ていた。

#### 関所は 1 つ・鳴る理由が 2 種類

前提の判定は「適用前の予測」ではなく「**適用後の実測**」で行う。全工程は `out_book`
（原本のコピー）の上で走り、原本への反映は最後の 1 手なので、**before/after が両方
手元にあって原本はまだ無傷**という窓が必ず存在する。検査はそこに置く（Basic の
コード生成には 1 行も触らない）。

この結果、関所を呼ぶ時点が 2 つになる（適用**前**＝書き込み先列の既存値を数える／
適用**後・反映前**＝宣言した領域の前提を突き合わせる）。**これは関所が 2 種類ある
という意味ではない**:

- 呼ぶ関数は同じ（`_confirm_overwrite_or_gate`）
- exit code は同じ（対話で拒否 = 1・非対話で確認できない = 7・新しい code は作らない）
- 素通しの条件も同じ（`--copy` / `--dry` / `--ask` / `--overwrite`）
- 文言の形も同じ（`★ …（上書きします）` と同じ位置・同じ調子の 1 行）
- 段種への配線も同じ（単発 `cmd_run_dsl` と複合計画 `_run_dsl_plan_step` の両方。
  複合計画は**段ごとの** before/after で見る — 宣言は段ごとに違うので、突き合わせも
  段ごとでなければ前の段の書き込みを次の段の前提破れと読み違える）

違うのは**何を材料に鳴るか**だけで、`_maybe_warn_target_overwrite`（適用前）と
`_maybe_warn_write_precondition`（適用後）は同じ関所への 2 つの入力にすぎない。
前提の判定本体は `ailine_core/write_precondition.py`（純ロジック・`ailine` を
import しない）。番人は 2 つ: **すべての領域種類が「前提あり」か「前提なし」かを
宣言していること**と、**1 つの op が両者を混ぜないこと**（混ざると
「片方では破れ・もう片方では正常」という判定不能が生まれる）。

★ 判定は保守的に置いた: 事後条件が `fail` の段はこの関所より**手前**で止まる
（壊れた結果に「承知して続行しますか」と聞くのは、壊れた結果の適用を勧めることになる）。
並べ替え/行挿入の多重集合は**数式を除いて**比べる（行が動けば `=D2-C2` は `=D3-C3` に
なる — 移動の正常な副作用であって破壊ではない）。増えた値は見ない（それは破壊ではなく、
幽霊データ検出の領分）。

### 「変更されていません」を抑える 2 つ目の出所（宣言ではない）

依頼文の語が**シート名と列名の両方に一致する**ブック（`sheets=['売上データ','金額']` に
「金額を降順に並べ替えて」）では、対象シートを決める側が「この語は列名とも一致するので
曖昧＝既定(1枚目)へ後退する」と**既に判断し、記録している**。ところが助言側はその記録を
読まず、独立に「依頼文にシート名『金額』が出てくるのに、そのシートは変更されていない」と
警告していた ── **同じことを 2 箇所が別々に決める**形の誤爆で、後退したのが正しい判断で
あるほど確実に出た。

これで「変更されていません」の抑制の出所は 2 つになる（①`reads_only` の宣言
②対象シート決定側が残した衝突の記録）が、**判定する場所は増やさない**: 助言側は
「その語が曖昧か」を判定し直さず、決めた側の記録を受け取って除外の和に足すだけにする
（判定を助言側にも書くと 3 箇所目が増える）。記録が無ければ抑制はゼロ＝従来どおり警告する。

## なぜ（一次資料つき）

初代実装（W10a）は関所を `COMPUTE_COLUMN` にしか適用しない事実上の白名簿
（`if op != "COMPUTE_COLUMN": return None` の 1 行）だった。W10c の実機査定
（$25）で、「単価表を見て単価を入れて」という自然な依頼に対し、`LOOKUP_FILL` が
対象列名を無関係な既存列（「数量」）へ解決し、**関所を素通りして無警告のまま
上書きした**事故が実測された。原因は「白名簿方式は op が増えるたびに人間が
if を書き足すことを要求する」構造そのもの — 忘れれば静かに脆弱になる。

宣言駆動への一般化はこの構造的欠陥を消す。★ これが「op を増やしても壊れない」
唯一の形だった、という判断がコミットメッセージに明示されている: 白名簿方式は
「足し忘れ」という人為ミスを許す余地が本質的にあり、宣言＋番人テストの組だけが
その余地を構造的に閉じる。

- 出典: commit 2b5afbe（W10a — 破壊の関所の初出・COMPUTE_COLUMN 限定）・
  commit ab34711（W10c — 「op ごとの if の白名簿だったのを OP_WRITE_TARGET 宣言の
  読み取りへ一般化。再発防止の本体は全 op が宣言を持つことを検査するテスト」・
  実機査定 $25 での事故再現）・commit 476f1ae（W10d — 新規列ゴースト警告の中立化も
  同じ宣言テーブルへ一般化 + 全 op を動的にループする番人テスト）・
  **単位C（2026-08-17 — 宣言を「列」から「領域」へ広げ、`writes` / `reads_only` を追加。
  盲検査定 2 本が独立に「★ 警告の誤爆率が実害率を上回っており、3 回誤爆を見た時点で
  ★ を読まなくなる＝安全網が自分で自分を無効化している」と指摘したことが動機。
  同時に、助言側が別に持っていた op 名集合（新規シートを作る op の白名簿）をこの宣言へ
  畳んだ ── 宣言が 2 箇所にあると片方だけ更新されて食い違うため）**・
  **誤爆#3（2026-08-17 — 同じ査定系列の 3 種目。こちらは宣言ではなく、対象シートを決めた側の
  衝突の記録を助言側まで運ぶことで消した。ゴールデンは同じ before/after で衝突の記録の
  有無だけを変えた 2 本で凍結）**・
  **単位F（2026-08-18 — 宣言に「前提」を足した。盲検査定の致命 2 件（既存の合計行の
  上書き・無関係な『集計』シートの全滅）はどちらも `col_key` を持たない op で起き、
  関所の入口 1 行で return されていた。検体は実装より先に書いて赤を確認した
  （`tests/test_write_precondition.py` — 真陽性 5 + 偽陽性 5 系統）。★ 表の下端の判定
  （`_scan_last_row_basic`）は触っていない — 前提の突き合わせだけで致命 2 件は止まる）**

## 検証挙動（GOLDEN 相当）

| 入力 | 期待 |
|---|---|
| COMPUTE_COLUMN が既存列 target を指す | 上書き件数を表示して確認（非対話は exit 7） |
| LOOKUP_FILL が既存列へ解決される | 同じ関所が発火する（COMPUTE_COLUMN 専用だった旧実装では素通りしていた） |
| `OP_SCHEMA` に op を新規追加し `OP_WRITE_TARGET` への登録を忘れる | 番人テストが fail する（登録漏れの機械検出） |
| `--overwrite` 指定 | 関所を承知の上で素通し（`ailine undo` で戻せる） |
| 複合計画・1 段目で拒否 | 原本は無傷のまま計画全体が止まる |
| `APPEND_TOTAL` が末尾に合計行を足す | 「（表の末尾への追記は意図どおりです）」＝警告にしない |
| `APPEND_TOTAL` の変更に元データの列範囲より右のセルが混ざる | 従来どおり「★ 疑わしい」を出す（抑制しすぎない） |
| `AGGREGATE` / `PIVOT` が名指しの入力シートを読むだけ | そのシートについて「変更されていません」を言わない |
| 依頼文の語がシート名と列名の両方に一致し、対象シートが既定へ後退した | その語（同名シート）について「変更されていません」を言わない |
| 同じ before/after で衝突の記録を渡さない | 従来どおり「★ 依頼で言及された『〜』は…変更されていません」を出す |
| 宣言に未知の領域種類を書く・`writes` を空にする | 番人テストが fail する |
| `APPEND_TOTAL` が**既存の**合計行の値を上書きした | 前提が破れる → 同じ関所（非対話は exit 7・原本は無傷） |
| `APPEND_TOTAL` が空の行に合計を書いた（既存の合計行の**下**を含む） | 鳴らない（前提は破れていない — 二重計上は別の根） |
| `AGGREGATE` / `PIVOT` が**既存の**同名シートを書き換えた | 前提が破れる → 同じ関所（op ごとの if は無い） |
| `AGGREGATE` / `PIVOT` が新しいシートだけを作った | 鳴らない（従来どおり中立表示） |
| `format_only` の op でセルの値が変わった | 前提が破れる → 同じ関所（★ 左上以外に値がある範囲の `MERGE` はここで鳴る） |
| `SORT` / `INSERT_ROWS` で値が消えた | 前提が破れる → 同じ関所（数式の参照書き換えは除外） |
| 事後条件が `fail` の段 | この関所より手前で止まる（exit 1・確認は出さない） |
| 領域種類を 1 つ足して前提の宣言を忘れる | 番人テストが fail する |
