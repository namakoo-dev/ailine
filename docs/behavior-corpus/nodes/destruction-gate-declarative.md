# destruction-gate-declarative — 破壊の関所と OP_WRITE_TARGET の宣言駆動

**分類: あ（設計原則そのもの — 「op ごとの if でなく宣言を読む」は言語非依存の骨格）**

## 挙動

原本へ直接反映する既定経路で、**既存データへの上書きが起きる操作**は
`--ask` 無指定でも確認を挟む（「破壊の関所」）。確認では上書きされる既存値の件数を
表示し、対話なら y/N、非対話なら **exit 7** で止める（`--overwrite` で明示的に
承知の上で続行できる・`ailine undo` で戻せる）。複合計画では段ごとにこの関所を通し、
原本（book）はどの段が拒否されても無傷のまま止まる（`out_book` はコピーで作業して
いるため）。

この関所が「どの op のどの引数が書き込み先か」を知る方法は、**`OP_WRITE_TARGET` と
いう宣言テーブルを読むこと**であって、op ごとの `if` 分岐ではない。新しい op を追加する
開発者はこの宣言に必ず登録しなければならない — それを**機械的に強制するテスト**
（`test_op_write_target_declares_all_ops`）が「`OP_SCHEMA` の全 op が
`OP_WRITE_TARGET` に宣言を持つ」ことを検査する。同じ宣言は、新規列/新規行/新規シート
作成のゴースト警告の中立化（意図した新設を誤警報しない判定）や、参照専用シートの
「変更されていません」の抑制でも共有される（検出ロジックを二重管理しない）。

### 宣言の中身は「列」でなく「領域」

各 op は次の 4 つを宣言する。

| 項目 | 意味 |
|---|---|
| `writes` | **書く領域の種類**（既存列 / 新規列 / データ末尾の新規行 / 新規シート / 書式のみ / 行の挿入 / 並べ替え）。空は不可 |
| `col_key` | 書き込み先**列**を指す引数キー（既存列を書く op だけが持つ＝破壊の関所の対象） |
| `sheet_key` | 対象シート名を指す引数キー（無指定なら解決済みの対象シート） |
| `reads_only` | **参照専用**シートを指す引数キー（そのシートが無変更なのは正常） |

初代の宣言は `(col_key, sheet_key)` か `None` の 2 択で、**「どこに書くか」を列でしか
言えなかった**。そのため助言の側は宣言を読めず、依頼文の表層語や列の形で代用し、
毎回・確実に再現する誤警報を 2 種類出していた:

- **合計行**（`APPEND_TOTAL`）は定義上ずっと元データの使用範囲の外に出るため、
  成功するたび「★ 疑わしい: 変更が元データの範囲外です」が出ていた。
- **新規シートにしか書かない op**（`AGGREGATE` / `PIVOT`）は、名指しされた入力シートを
  読むだけなのに「★ 依頼で言及された『〜』は…変更されていません」が出ていた。

どちらも `writes` / `reads_only` の**宣言**で消した（op ごとの条件分岐を足すのではなく）。
中立化は保守的に留める — 例えば「データ末尾の新規行」の宣言があっても、元データの
**列範囲より外**へ出たセルが混ざっていれば警告は出したままにする。

宣言が宣言として成立していること（未知の領域種類・空の `writes`・「既存列を書くと
言いながら書き込み先列を指さない」等の自己矛盾）も番人テストが検査する
（`test_op_write_target_declarations_are_well_formed`）。

## なぜ（一次資料つき）

初代実装（W10a）は関所を `COMPUTE_COLUMN` にしか適用しない事実上の白名簿
（`if op != "COMPUTE_COLUMN": return None` の 1 行）だった。W10c の実機査定
（$25）で、「単価表を見て単価を入れて」という自然な依頼に対し、`LOOKUP_FILL` が
対象列名を無関係な既存列（「数量」）へ解決し、**関所を素通りして無警告のまま
上書きした**事故が実測された。原因は「白名簿方式は op が増えるたびに人間が
if を書き足すことを要求する」構造そのもの — 忘れれば静かに脆弱になる。

宣言駆動への一般化はこの構造的欠陥を消す。★ これが「op を増やしても壊れない」
唯一の形だった、という判断がコミットメッセージに明示されている: 白名簿方式は
「足し忘れ」という人為ミスを許す余地が本質的にあり、宣言＋番人テストの組だけが
その余地を構造的に閉じる。

- 出典: commit 2b5afbe（W10a — 破壊の関所の初出・COMPUTE_COLUMN 限定）・
  commit ab34711（W10c — 「op ごとの if の白名簿だったのを OP_WRITE_TARGET 宣言の
  読み取りへ一般化。再発防止の本体は全 op が宣言を持つことを検査するテスト」・
  実機査定 $25 での事故再現）・commit 476f1ae（W10d — 新規列ゴースト警告の中立化も
  同じ宣言テーブルへ一般化 + 全 op を動的にループする番人テスト）・
  **単位C（2026-08-17 — 宣言を「列」から「領域」へ広げ、`writes` / `reads_only` を追加。
  盲検査定 2 本が独立に「★ 警告の誤爆率が実害率を上回っており、3 回誤爆を見た時点で
  ★ を読まなくなる＝安全網が自分で自分を無効化している」と指摘したことが動機。
  同時に、助言側が別に持っていた op 名集合（新規シートを作る op の白名簿）をこの宣言へ
  畳んだ ── 宣言が 2 箇所にあると片方だけ更新されて食い違うため）**

## 検証挙動（GOLDEN 相当）

| 入力 | 期待 |
|---|---|
| COMPUTE_COLUMN が既存列 target を指す | 上書き件数を表示して確認（非対話は exit 7） |
| LOOKUP_FILL が既存列へ解決される | 同じ関所が発火する（COMPUTE_COLUMN 専用だった旧実装では素通りしていた） |
| `OP_SCHEMA` に op を新規追加し `OP_WRITE_TARGET` への登録を忘れる | 番人テストが fail する（登録漏れの機械検出） |
| `--overwrite` 指定 | 関所を承知の上で素通し（`ailine undo` で戻せる） |
| 複合計画・1 段目で拒否 | 原本は無傷のまま計画全体が止まる |
| `APPEND_TOTAL` が末尾に合計行を足す | 「（表の末尾への追記は意図どおりです）」＝警告にしない |
| `APPEND_TOTAL` の変更に元データの列範囲より右のセルが混ざる | 従来どおり「★ 疑わしい」を出す（抑制しすぎない） |
| `AGGREGATE` / `PIVOT` が名指しの入力シートを読むだけ | そのシートについて「変更されていません」を言わない |
| 宣言に未知の領域種類を書く・`writes` を空にする | 番人テストが fail する |
