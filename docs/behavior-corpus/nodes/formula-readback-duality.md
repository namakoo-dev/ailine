# formula-readback-duality — 式で書いた列を読み戻すときの二重性

**分類: い（構造は渡るが、openpyxl の式ビュー/値ビューという実装ライブラリ固有の
API 形に依存する部分は再設計が要る）**

## 挙動

openpyxl でブックを開くとき、`data_only` 未指定（既定 False）は**式ビュー**
（セルに書かれた式文字列そのもの）を返し、`data_only=True` は**値ビュー**
（LibreOffice/Excel が最後に保存時計算したキャッシュ値）を返す。この 2 つは別の
読み方であって、片方だけでは式列の実効値を正しく検証できない。

`use_formula=True` の事後条件チェッカー（`check_compute_column` /
`check_compute_column_single_factor` / `check_aggregate` / `check_sort`）は、
検証対象（operand・分類列・集計列・並べ替え対象列）を**必ず `data_only=True` の
値ビュー側から読む**。前段が式で作った計算列（例: 小計列）を後段の operand に
使う複合計画では、raw（式ビュー）側から読むと式文字列のまま「数値でない」扱いに
なり、対象が丸ごと除外される。

さらに、「対象が無い」（本当に非数値・空欄）と「対象はあるが値が読めない」（式は
あるがキャッシュ値が無い＝ LibreOffice をまだ一度も通していない）は**別カウント**
で扱う（空虚な検証合格の禁止の趣旨を保つ — 前者は正当な除外、後者は検証不能の
別種）。

行独立の検証（COMPUTE_COLUMN 系）とクロス行の検証（SORT/AGGREGATE 等、全行の
関係性そのものが判定対象）では、値が読めない行の扱いが異なる:
- **行独立**の演算は**部分採点**（読めない行は除外し、残りの行だけで判定）
- **全行をまたぐ**検証（SORT の相対順序・AGGREGATE の合計）は、キャッシュ値が
  無く読めない行が 1 件でもあれば、その時点の期待値そのものが信頼できないため
  **打ち切り fail**（見逃しより止まる側に倒す）

## なぜ（一次資料つき）

複合計画で「前段が式で計算した小計列 → 次段でその列を対象に演算/並べ替え/集計」
という連鎖が実機・純関数レベルの双方で再現された。原因は 4 チェッカー共通の
同型バグ: `use_formula=True` でも対象列を raw（式ビュー）から読んでいた。
COMPUTE_COLUMN 系は「対象が無い→検証対象 0 件 fail」で計画ごとロールバックし、
`check_aggregate` は「value_col が数値でない→0 扱い」に落ちて偽の不一致 fail に
なっていた（値の丸め自体は正当なケースのために残すが、それは「本当に非数値/空欄」
の行専用に絞った）。

- 出典: commit d7200c3（「W10f — 事後条件が operand を式ビューから読む欠陥 4 件」・
  純関数レベルで再現を確認・`tests/test_compute_column_chain_local.py` に局所回帰・
  実機 basrun を通す E2E を新設・「対象が無い」と「対象はあるが値が読めない」を
  分離する判断はこの commit で確定）

## 検証挙動（GOLDEN 相当）

| 入力 | 期待 |
|---|---|
| 前段が式で作った小計列を次段 COMPUTE_COLUMN の operand にする | data_only 側から読んで検証（式ビュー由来の偽 fail が起きない） |
| 同じ連鎖を SORT の対象列にする | 1 行でもキャッシュ値未読があれば打ち切り fail（部分採点しない） |
| 同じ連鎖を AGGREGATE の集計列にする | 同上（全行をまたぐ検証のため打ち切り扱い） |
| 演算対象が本当に非数値・空欄（合計行等） | 「対象が無い」として除外・件数表示（打ち切りにはしない） |
