# PDF の帳票を読む ── 設計（2026-09-12）

## §0 なぜ

実務で受け取る請求書は **PDF が圧倒的に多い**（Namakoo の判断）。ailine が読むのは xlsx だけなので、
需要①（帳票の山から項目を抜く）の射程がそこで切れている。

構造は有利だった。`form_grid` `form_read` `field_record` `forms_collect` `forms_suspect` `date_compare`
の **1872 行のうち、Excel を知っているのは 13 行**。残りは `Grid` の 8 つの口
（`right_of` / `below_of` / `text_cells` …）の上に載っている。

## §1 測ってから決めたこと（探針の実測・2026-09-12）

87 冊を LibreOffice で PDF 化し、**答えは Excel と同じもの**で採点した。器官（`form_read`）は 1 行も変えず、
PDF → `Grid` の変換器だけを書いた。

| 版 | 正 | 誤報 | 宛先 | 請求元 |
|---|---|---|---|---|
| 素朴な変換器 | 53 (31%) | **14** | 1/40 | 11/57 |
| ＋ 宛先未確定なら請求元を出さない（済・`967316c`） | 44 | 3 | 1/40 | 2/57 |
| ＋ **空白を捨てるのをやめた** | **142 (83%)** | 4 | **40/40** | **55/57** |

### 1.1 ★ 空白は「ここまでが同じセル」の証拠

```
PDF の中身   '合' '　' '　' '計'      ← Excel のセルなら「合　　計」
既定の抽出   '合' | '計'   ← 別の語になり「合計」の照合が永久に当たらない
keep_blank_chars=True → '合　　計' → norm が空白を落として '合計' ○
```

`x_tolerance` を広げても直らない（空白**文字**が実在するので位置の閾値の問題ではない）。
日本語の帳票は**均等割付**（合　　計・品　　名・請 求 書）が普通で、ここを外すと
帯も明細の見出しも一生見つからない。**このフラグ 1 つで 31% → 83.6%。**

### 1.2 実物 2 社で共通した罠

1. **`pdftotext`（poppler）は日本語を 1 文字も返さない。** 数字と記号は返すので「空でない＝成功」に見える
2. **漢字が康熙部首に化ける。** `請求⽇` の「⽇」は U+2F47（`請求日` は U+65E5）。
   Adobe 16 枚・Wondershare 1 枚のすべてで発生。見た目は同じなので目でも diff でも気づけず、
   **ラベル照合が全部外れるのにエラーは 1 件も出ない** → 取ったら**何より先に NFKC**

### 1.3 残った 6 件の正体 ── 2 種類に分かれた

★★ **最初の帰属は 2 件間違えていた。** 「T18・T24 は式が無いせい」と書いたが、
Excel 側で何が起きているかを実測したら違った。**commit 前に一拍疑って測り直して直した記録**として残す。

**(a) PDF が物理的に持っていない ── 直せない（4 件）**

| 失う情報 | Excel での振る舞い | PDF で起きること | 冊 |
|---|---|---|---|
| 数値 vs その通りの文字 | 「D13 の金額が**数値ではなく文字**（`¥1,320,000-`）」で**拒否** | 数に復元して値を出す | T21 |
| 同（全角） | 「D13 の金額が文字（`１，３２０，０００`）」で拒否 | 0 を出す | T34 |
| エラー状態 | 「D22 が `#REF!`（式が壊れています）」で拒否 | もっともらしい値を出す | T33 |
| 表示で丸められた精度 | 確 13579.5 | 13,580 と出す | T23 |

★ ここで見えた設計の含み: Excel 側は「金額の欄に**文字**が入っていたら拒否する」を
**意図してやっている**（人が手で打った数字は疑う）。PDF ではその区別が原理的に付かない ──
つまり **PDF から読む時、この番人は 1 つ失われる**。正直に台帳へ書く（D10）。

**(b) 格子の忠実さ ── 直せる（2 件）**

| 冊 | Excel での理由 | PDF で落ちた所 |
|---|---|---|
| T18 | `conflict=True`「明細の合計 45,000 と小計 30,000 が合わない（34 行目の税率が空）」 | 明細の列の割り当てが甘く、**食い違いを見つけられていない** |
| T24 | 3 つの根拠が食い違う（E12=109999／L36=109999／小計+消費税=110000） | 3 つ目（小計＋消費税）を組めていない |

★ どちらも**明細表の列をどう割るか**に帰する。ここが甘いと
「食い違いを見つけて拒否する」という一番強い番人が黙る。

## §2 決めたこと

### D1 置き場所 ── `ailine_core/pdf_grid.py`（新規）

`form_grid.Grid` は**格子の定義**のまま。`Grid.read(ws)` は openpyxl 用の名前付きコンストラクタとして残し、
`pdf_grid.grid_from_page(page)` を並べる。★ pdfplumber の import は `pdf_grid` の中だけ
── 任意依存を 1 モジュールに隔離する（居なければそのモジュールだけが使えない）。

### D2 空白と位置 ── 閾値は 2 つだけ、どちらも実測の谷から

- 空白文字がある所は**同じマス**（`keep_blank_chars=True`）
- 行は y の差 **4pt** でまとめる（本文 10〜11pt の半分弱）
- 列は中心の並びを **40pt** の隙間で切る（実測: 列内のばらつき ≤31 < 列間の隙間 ≥57 の谷）

★ 閾値を増やさない。増やしたくなったら、それは列挙で当てにいく合図。

### D3 値の復元 ── 描画の逆算だけ（推測しない）

| 描かれた文字 | 復元 | 理由 |
|---|---|---|
| `¥32,400-` `330,000円` `1,234` `1` | 数 ＋ 書式 | Excel なら「数値＋表示形式」だったもの |
| `000-0000` `00-0000-0000` `S-202504-001` `1個` `2025年4月30日` | 文字のまま | 数ではない |

★ 「裸の 1 を数に戻すと番号や年を壊す」と最初は恐れたが、**測ったら起きなかった**
（請求番号はラベルから文字として読み、日付は日付として読むので、裸の数が化けて入る経路が無い）。
逆に戻さないと**数量の列が空に見え**、器官が「単価は在るのに数量が空」と読んで合計を信じなくなる。

### D4 ★★ 写しを見分けられない時は「裏が取れた」を名乗らない

これが設計の核心。**PDF 固有の話ではない**ことを測って確かめた:

```
Excel を式なしで開く（read_book(wb) ── wb_formula を渡さない）
  → B01 の請求額の根拠が 2 つ → 3 つ に増える（写しを独立と数えている）
  → 87 冊では区分が変わる冊は 0 ★ 壊れている経路は在るが、この検体では点数に出ない
  → PDF では出る（下の「観測された被害者」）
```

★ **観測された被害者**（2026-09-12 に測り直して確定）:
  - Excel: **0 冊**（87 冊で区分が変わる冊は無い）── 壊れた経路は在るが、いまの検体に被害者は居ない
  - PDF: **在る** ── Wondershare の雛形で請求額が **確 32,400** を名乗った。
    上部の欄と帯の合計は（元の Excel なら）式で繋がった同じ事実のはずで、**裏取りは earned でない**

**処置**: 区分の導出に「写しを見分ける手段が在るか」を渡す。

- `field_record.Record` に `copies_indistinguishable: bool = False`（＋ 理由）
- `grade_of(evidences, swept, conflict, copies_indistinguishable)` は、真なら**裏取り済みの区分を出さない**
- ★ 区分の語も導出も `field_record` の中だけ（AST の番人が縛っている契約を守る）

**どこで真になるか（1 箇所に畳む）**:

| 入口 | 値 |
|---|---|
| Excel ＋ 式のブック | False |
| **Excel ＋ 式のブックなし** | **True**（潜在欠陥をここで塞ぐ） |
| **PDF** | **True**（式が存在しない） |

★ 片配線を作らない ── 「PDF だから」でなく「**写しを見分ける手段が無いから**」で書く。
  次に別の入口（CSV・OCR）が来ても同じ 1 箇所で決まる。

### D5 番地の書き方

PDF は `2頁12行3列`（人が原本を開いて指で追える形）。Excel は今までどおり `H20`。
★ 検分シートと所見に出るので、**原本に戻れる**ことが条件。

### D6 どのページを読むか ── シート選びと同じ線

`invoice_signals(grid)` が 2 つ以上の印を返すページで、単独勝ちのものだけ。
★ 答えから受け取る口は作らない（Excel 側で一度やって消した過ち）。

★ **明細が複数ページにまたがる形は設計しない。** 検体に 1 冊も無いので測れていない。
発火条件つき保留 ── 2 頁目に明細の続きがある実物が来たら、その時に測ってから決める。

### D7 テキスト層が無い PDF（スキャン）

読めないと**名指しで**言ってスキップする。**OCR はしない**（射程外）。
★ 「読めなかった」と「請求書ではなかった」を混ぜない ── 理由を分けて出す。

### D8 pdfplumber は**必須依存にする**（Namakoo 決裁 2026-09-12）

俺の初案は「任意のまま」だったが、**PDF が本流なら主機能が既定で使えないのはおかしい**という
判断で必須にする。増える環境依存の実測:

```
pdfplumber 0.11.9
  ├ pdfminer.six  9.4 MB ─ cryptography 10.9 MB（コンパイル済み）─ cffi, pycparser, …
  ├ pillow        16.1 MB
  └ pypdfium2      8.2 MB（コンパイル済み）
合計 47.5 MB / 9 パッケージ  ── 宣言は openpyxl 1 本 → 10 本
```

普通の pip（Windows / macOS / Linux・x86-64 / arm64）なら全部 wheel が在るので一発。
引っかかるのは air-gapped の社内機・古い Python・変わったアーキテクチャで、
コンパイル済みの 2 本（cryptography・pypdfium2）がそこに効く。

★ **入れると得が 2 つ増える（PDF を読む以外に）**:

1. `ailine export-pdf` の検算が**常に**効く ── いまは pdfplumber が任意なので、
   居ない環境では PDF を作っても「✓ を名乗らない（⚠ 機械保証はありません）」で終わっている
2. **Pillow が宣言済みになる** ── 「写真の印は PDF に残る」は Pillow が在る時だけの真実で、
   宣言していない以上**買い手の環境では嘘**だった（`ci_parity` を作った時に掴んだ製品のバグ）。
   宣言することで構造的に閉じる

**配線**: `pyproject.toml` の `dependencies` と `requirements-dev.txt` の両方。
★ 後者は素の環境の番人（`scripts/ci_parity.py`）が読む正なので、片方だけでは片配線になる。

### D9 `ailine forms` の入口

`multifile.classify_folder_contents` が `.pdf` も候補にする。
★ Excel と PDF が混ざったフォルダでも**束で疑える** ── 同じ取引先が月によって
PDF と Excel で来ても照合できる（むしろ利点）。

### 8.2 ★★ 3 冊が正しかったのは、一文字のバグのおかげだった

Excel の誤区分 3 冊（T28 備考の再掲・T38 通貨 USD・X03 見積書 ESTIMATE）は、
器官の初版（`34b3e90`）が「開いていない第三の口」として**既に名指ししていた冊**そのもの。
明細と一致しても、それは**明細という 1 つの口**を掃いただけだ。

★ **一文字の取りこぼしが掃き出し自体を壊していたから、この 3 冊は over-claim せずに済んでいた**
── 番人が間違った理由で効いていた。いちばん脆い形。だから G1 と G3 は**一緒に**出す。

さらに T15（値引き行 −5,000 の陰性対照）は `値引` が帯の開始語に入っていたせいで明細から落ち、
偽の食い違いを出していた。**一文字が検出を隠し、検出が罠を隠していた。**

### 8.4 入れたもの（G1〜G3 は一緒に・実測で確かめて）

- **G1** `norm()` が中黒を 1 つに寄せる（`• · ･ ‧ ∙ ⁃ → ・`）── 閉じた**文字クラス**
- **G2** `値引/値引き` を帯の開始語から外す（帯は 小計/合計/消費税 で開く）
- **G3** `unswept_mouths(grid, total)` ── 在れば**裏取り済みを名乗らない**（値は出す・名指しで開示）

  同じ日に二つ目の理由が出たので、三つ目（CSV・OCR…）で真偽値を足す形をやめた

### 8.5 ★★ 出す前に「偽の疑い」を測って、もう 1 つ足した

G1〜G3 を入れると PDF が 152 → 138 に落ちた。全部 安全（空欄＋理由）だが、中身を測ったら:

```

    本物（Excel でも食い違う）                 5 件
```
