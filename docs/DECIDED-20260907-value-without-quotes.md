## なぜ

「」を要求しているのは**小型モデルの限界への回避策**で、能力の線ではない
（Namakoo:「単語の説が qwen に読み取れるか怪しかった。『』は値を指すという暗黙の
ルールもある。値なのか操作なのか、属性なのかを判別出来るなら『』はいらない」）。

★ 実務で断られた記録がこの形に集中していた（09-04 以降・一度も成功していない依頼）:

    メモを全部確認済にして / 備考を全部確認済にして
    金額の列を全部 0 にして / 締め日を全部 2026/09/30 にして

## 測ったこと（→ 開発手法 §6d）

モデル（16/20・6 倍遅い）より良く、手で書いた規則（10/20）は話にならなかった。
★ **モデルの差し替えは要らない。** no thinking で組む。

## 決めた形

    ① op を決める        いまどおり（抽出・書式はここで分かれる。実測の誤りの 2/3 はここで消える）
    ② 値を取る           LLM（no thinking・約 3 秒）★ もう返している値を、捨てずに使う
    ③ 拒否する           機械: 実表の列名 / シート名 / op の語彙 / 消す語（空・空欄・クリア）
    ④ 日付を解く         「今日」「本日」「今月末」等は**この PC の時計**から機械が決める
                         ★ 生成させない（実測: 7b は 2023/10/05 を捏造した）
                         ★ 書き方は**実表の同じ列**に合わせる
    ⑤ 見せる             解釈行に出所つきで（例:「2026/09/07（この PC の時計）」）
                         ★ 閉域網では時計がずれうるが、**書く前に見せれば人が気づける**
    ⑥ 決まらなければ     いまの断り（「」で囲んでください）を**最後の砦**として残す
                         ★ 要求から**逃げ道へ格下げ**するだけで、消しはしない
