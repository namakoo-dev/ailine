## ① グラフ ── `addNewByName` は役割を**物理的な左右**で決める

```
Sub InsertChart(..., catCol, valCol, ...)
    oRanges(0) = catCol の列    ' 項目名のつもり
    oRanges(1) = valCol の列    ' 値のつもり
    oCharts.addNewByName(sName, oRect, oRanges(), True, True)
                                          ^^^^ 「先頭列＝項目名」
```

LibreOffice は「先頭列」を**配列の順序でなく、シート上で左にある方**で決める。

★ 同じ依頼文「月ごとの金額を棒グラフにして」で、列の並びだけを変えて実測した:

```
A 項目が右（月=D > 金額=C）   InsertChart(oDoc, 0, 3, 2, "bar", 5)
    系列名 $D$1（月）／項目名 $C$2:$C$6（金額）／値 $D$2:$D$6（月）  ★ 3 つとも反転

B 項目が左（月=B < 金額=C）   InsertChart(oDoc, 0, 1, 2, "bar", 5)
    系列名 $C$1（金額）／項目名 $B$2:$B$6（月）／値 $C$2:$C$6（金額）  正しい
```

**宣言（解釈行）は両方とも正しい**（値列:金額 横軸列:月）。ずれているのは実体だけ。

### 揺れて見えた理由

発火は「LLM がどの列を項目に選ぶか」で決まる。だから同じ表でも依頼の言い方で変わる:

```
「部門ごとの金額を棒グラフにして」  項目=部門(A) < 金額(C)  → 通る
「金額の棒グラフを作って」          項目=月(D)  > 金額(C)  → 壊れる
```

### 実害の範囲

項目名の列が値の列より**右**にある表で、グラフを頼んだ時だけ。経理の表は普通ラベルが
左端にあるので、多くの場合は当たらない。

### 直し方（次の版で）

```
1  chart2 API で役割を明示する（SequenceMapping）  ★ 正攻法・生きた参照も保たれる
   見積もり: 実機で反復しながら 1〜3 時間。外すと静かに別の壊れ方をするので、
   ★ 検分は「列の並びを入れ替えた 2 検体で同じ結果になること」から入る
2  項目列が値列より右のときは断る（30 分）── できることが減るので次善
```

★ **発火条件**: 次に chart 周りへ手を入れる時、または「グラフが変」という報告が来た時。
Namakoo 判断（2026-09-10）「3 から 1 が丸いな」＝ **今回は開示だけ・次の版で 1 を実装**。
