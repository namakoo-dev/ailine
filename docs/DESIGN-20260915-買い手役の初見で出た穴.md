## §3 ③ 自分が作った計算列で絞れない ── 直した

```
計算列『過不足』を作る → ✓（事後条件は「式・キャッシュ値とも一致」と言っている）
「過不足がマイナスの行を抜き出して」 → 出力は正解 3 行なのに「6行中0行が一致」で × ・exit 1
```

原因を特定した。抽出の検算が式のセルを**文字列のまま**読んでいる:

```
data_only=False → ['過不足', '=C2-D2', '=C3-D3', …]   ← 検算はこちらを読んでいる
data_only=True  → ['過不足', -5, -12, 80, -33, 12, 4000]   ← キャッシュ値は同じファイルに在る
```

`'=C2-D2' < 0` は常に偽なので 0 行。★ 計算列の検算はキャッシュ値を読めているのに、抽出の検算は
読めていない ── **経路で読み方が揃っていない**（片配線）。
★ 実害は「安全側の嘘」（正しい答えを × にする）だが、買い手の仕事は完遂しない。

### 3.1 穴の在り処（全経路を数えてから直した）

| 経路 | 述語・鍵の読み方 | |
|---|---|---|
| `check_extract` の述語 | **式ビュー** | ★ 穴（買い手が踏んだ） |
| `check_dedup` の鍵 | **式ビュー** | ★ 穴（兄弟・鍵が式だと重複が永久に見つからない） |
| `check_set_where` / `check_sort` / `check_aggregate` / `_rows_matching` / `extract_multi` | 値ビュー | 既に正しい |

★ 片方だけ直さない ── 同じ形を数えてから両方直した。
★ ついでに塞いだ潜在の穴: 「写す側が実際に写す値」のヘルパが `bv.cell_formula(row, col)` を
**シート名なし**で呼び、BookView の既定（1 枚目）を見ていた。対象が 2 枚目以降のブックでは
**別のシートの式**を読む。`src.title` から取る（呼び出し側の変更は不要）。

### 3.2 実測

```
前: 「過不足がマイナスの行を抜き出して」→ 「6行中0行が一致」→ × ・exit 1・原本に入らない
後: 「6行中3行が一致 → 3行を抽出（値・型とも保存・元シート無変更）」→ ✓ ・exit 0
```
変異 3 通り全部赤。全件 4516 緑。

### 3.3 ★ 番人が 2 度 嘘をついた（測り方の記録）

初版の変異試験は **2 つとも緑のまま**で、しかも 1 つは**偽の赤**だった:

- **偽の赤**: 存在しない試験ファイル名を指していて「1 本も走らずに exit≠0」→ 赤に見えた。
  → 台本に `no tests ran` を見たら止める assert を入れた
- **鈍い検体（シート指定）**: 「キャッシュが無ければ元の値に落とす」フォールバックが、
  間違ったシートを読んだ回まで救ってしまう。1 枚目に**式とキャッシュの両方**が在る状態を
  作って初めて番人になった
- **鈍い検体（重複削除）**: 鍵の式の**文字列が全行同じ**だと、式ビューを読む壊れた版でも
  同じ鍵になる。★ 文字列は行ごとに違い、計算後の値は同じ、にして初めて鳴る
- **半分の変異**: ヘルパのシート指定を 1 行だけ戻しても、もう 1 行が正しいシートを渡すので
  答えが変わらない。元の穴は**両方**がシート名なしだった ── 変異は元の形に忠実に当てる

★ 教訓: 変異が緑なら、まず**検体を疑う**（規則が効いていないのでなく、効く場面を作れていない）。

## §5 ② 道具が自分で置いたファイルで詰む ── 直した（2026-09-16）

買い手の言葉: **「事務職に配れる品質ではありません」**。再現すると形は 3 つ重なっていた。

```
1 回目 集計 → ✓（『集計』ができる）
2 回目 別の集計 → 上書きの関所 exit 7
        ★ 画面は「作業結果を .out に残した」と**言わない**
        ★ フォルダに 9月売上.out.xlsx が残る
3 回目 以降 → 「この道具が書いた記録がありません（人が置いたファイルか…）」で全部 exit 7
        ★ run に上書き許可のフラグが無く、道具の中から抜け出せない（行き止まり）
```

### 5.1 原因 ── 仕組みは既に在り、関所だけが通っていなかった

`_finish_run` は `result["out"]` が在れば指紋 `out_sha` を履歴に残し、次の run は
「俺が置いたまま」と分かって作り直す。**関所で断つ 4 経路だけが `_finish_run` を通らず**、
指紋が残らないので自分の物と分からなくなっていた。
★★ これは **2026-08-26 に `_finish_failed_apply` で直したのと同じ形**。あの時直したのは
「反映に**失敗**した」経路だけで、「関所で**断った**」兄弟が残っていた。
★ 失敗の出口は 10 箇所以上が `_untouched_original_line` で残した物を言っているのに、関所だけ黙る。

処置: 器官 `_finish_gated` を 1 つ作り、4 経路が全部そこを通る。
① 残したことを**言う** ② 履歴に指紋を残す。★ 消さない ── 作業結果は人の物で、道具が黙って捨てない。

### 5.2 ★ 同じ家系をもう 1 つ見つけた（関所が端末の無い場で落ちる）

関所は `input()` の **`EOFError` だけ**を捕まえていた。実測すると「聞けない」の飛び方は環境で違う:

```
stdin が /dev/null   → EOFError      （捕まえていた）
stdin が閉じている   → ValueError    ★ 素通り
pytest の捕捉下      → OSError       ★ 素通り
```

つまり **GUI や捕捉下では、逃げ道（--overwrite / --copy）を出さずに落ちていた**。
起きうる 3 つを数えてから `except (EOFError, OSError, ValueError)` に広げた
（`except Exception` にはしない ── 関所の中の別の異常まで「聞けなかった」に化けさせない）。

## §6 ⑤ 『集計』シートを作ると「集計して」と言えなくなる ── 直した（2026-09-16）

買い手の引用:
```
「担当者ごとの金額をピボットで集計して」
  操作するシート: 2枚目『集計』（依頼文から判断・このブックは4シート）
  ？ できませんでした / 止めた理由: 列『担当者』がありません。ある列: 取引先, 合計 - 金額
```
★ 買い手の言葉:「**一度『集計』というシートを作ったら、二度と「集計して」と言えない。
  これは事務の言葉づかいでは避けようがありません**」── 月末に 2 種類の集計は必ず作る。

### 6.1 原因 ── 危険はコメントに書いてあったのに、対処が半分だった

`resolve_target_sheet` は依頼文に現れるシート名を**裸の部分文字列**で拾う:
```
if len(named) > 1:  マーカー付き（〜シート/タブ）が 1 つならそれを採る   ← 2026-08-24 の処置
if len(named) == 1: マーカーが無くても、列名と衝突しなければ **採用**   ← ★ ここが残っていた
```
★★ 同じ関数のコメントに「依頼文の**動詞**『集計して』がシート名と一致して」と**既に書いてある**。
  それでも対処は「言及が 2 つの時」だけだった ── **在っても鳴らない番人**の形。
  ★ 危険を書いた時に、その危険が単数でも起きることを数えていなかった。

### 6.2 処置 ── 語の形で決める（op は使えない）

`resolve_target_sheet` は**翻訳の前**に呼ばれ、操作がまだ決まっていない。だから op には頼れない。
**名前の直後がサ変動詞なら、シートの名指しと読まない**:
```
落とす: 集計して / 集計する / 集計します / 集計した / 集計しろ / 集計しよう / 集計せよ
残す  : 集計シートを…（マーカー付きは無条件で勝つ）／ 集計を並べ替えて（助詞は動詞ではない）
```
★ 狭く取った ── 「ピボット**で**集計して」の『で』は手段とも場所とも読め、実文が無いので触らない
（断定で刻まない）。

### 6.3 測定
```
前: 「担当者ごとに金額を集計して」→ 対象『集計』→ 列『担当者』がありません
後: 対象 1 枚目『9月売上』→ 担当者別の集計ができる
```
番人 10 件（事故そのもの 5 形＋陰性対照 4＋マーカーと動詞が同じ文に在る回）。変異 3 通り全部赤。

## §7 ④ 集計を 2 種類持てない ── 別サイクルにする（理由つき）

`OP_DECLARED_SHEET_NAME = {"AGGREGATE": "集計", "PIVOT": "ピボット"}` ── 出力先が**固定の 1 名**。
2 回目の集計は必ず既存の『集計』を潰しに行き、関所で止まる（止まるのは正しい）。
買い手の言葉:「`--overwrite` は前の集計が消える、`--copy` はファイルが分かれる。
**両方を 1 冊に並べる道が無い**」。

★ これは欠陥でなく**能力の不足**で、直すと出力先の名前が変わる ── 連鎖（`plan_chain_sheet_of`）・
事後条件・ゴールデン・検体の広い面に触る。★ 1 サイクル 1 変更なので、⑤を閉じてから
別途 凍結して測る。案は「分類列を名前に混ぜる（『集計_担当者』）」だが、**測る前に決めない**。
