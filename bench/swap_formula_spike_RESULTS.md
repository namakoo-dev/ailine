# 実測: 行/列を動かした時、式の参照はどう追随するか（2026-08-27）

★ なぜ測ったか: architect の査読が「入れ替えと列挿入は**設計で決められない・実験しろ**」と
指摘した。LibreOffice が相対参照をどう扱うかは実機に聞くしかない。

検体: 商品/数量/単価/金額（金額は `=B{行}*C{行}`）の 3 行。実 LibreOffice 経由（basrun）。

| | やり方 | 結果 | 判定 |
|---|---|---|---|
| **Q1** | セルごと**式を文字として**入れ替える | みかんの行が `=B3*C3`→**1000**（りんごの値）／りんごの行が `=B2*C2`→**2400**（みかんの値） | **✗ 壊れる** |
| **Q2** | `Columns.insertByIndex` で列を途中に挿す | `=B2*C2` → **`=B2*D2`** に自動で追随 | **✓ 安全** |
| **Q3** | `moveRange` で行を移す | みかん `=B2*C2`→**2400**（自分の値）／りんご `=B3*C3`→**1000** | **✓ 安全** |

## 設計への帰結（これで③の作り方が決まった）

1. **入れ替えを「値の交換」で実装してはいけない。** Q1 が示すとおり、式を運ぶと
   **各行の計算結果が他の行の値になる** ── しかも見た目は正しく並んでいるので、
   人が気づけない。この repo が最も嫌う「静かに壊れる」形。
2. **`moveRange` を使う。** LibreOffice 自身が参照を付け替えるので、式は自分の行を指し続ける。
   行の入れ替えは「片方を退避 → moveRange → 戻す」の 3 手で書ける。
3. **列の途中挿入は素直に `insertByIndex` でよい**（Q2）。追随は LibreOffice がやる。
4. ★ **事後条件は式の文字列を比べてはいけない。** Q2/Q3 では式の文字列が**正しく変わる**
   （`=B2*C2` → `=B2*D2`）。2026-08-25 に SORT で踏んだのと同じ形 ──
   比較は「式は行が動けば変わるのが正しい」を前提に組む。
   ★ 代わりに**計算結果（キャッシュ値）**が自分の行の値になっているかで見る。

# 追試: 位置の解決を **Basic 側**でやれるか（2026-08-27・Namakoo の問い）

> 「Basic から判断できないのか？」

Python が実表を読んで行番号を決める代わりに、生成する Basic に**名前で**渡して
Basic に走査させられるか。できるなら住所リゾルバの一般化（見積もり 180 行 + 一週間）が縮む。

| | 試したこと | 結果 |
|---|---|---|
| **A** | `FindRowByName` で「みかん」を探し、その下に値つきの行を足す | **✓** ぶどうの式も `=B5*C5` に追随 |
| **B** | 名前で 2 行を入れ替え（空行を挿す → `moveRange` → 空行を消す） | **✓** ぶどう `=B3*C3`→3600・みかん `=B4*C4`→2400（**自分の行の値**） |
| **C** | `FindColByName` で「数量」を探し、その右に列を挿す | **✓** 金額の式が `=B2*C2` → `=B2*D2` に追随 |
| **D** | 見つからない時に Basic から知らせる | **✓** 判別できる（-1 / -2 を返せる） |

## 分かった制約
- **`moveRange` は使用範囲の外へは動かせない**（空の行へ直接は移せない）。
  先に `insertByIndex` で行を作ってから移す ── Q3 で効いたのはこの形だった。
- Basic の `createCursor().gotoEndOfUsedArea()` で**物理の使用範囲**が取れる。
  Python 側で今日 3 箇所直した「走査が最初の空で止まる」問題は、Basic 側では起きない。

## 設計への帰結
1. **住所の語彙は「名前 + 向き」で足りる。** 行番号を LLM にも Python にも出させない。
2. **Python の役割は 2 つに絞れる**: ①名前が実在するかの関所（断りと開示）
   ②適用後の事後条件（before/after から**独立に**導く）。
   ★ 今より**恒真から遠い** ── 今は Python が番号を決めて自分の番号と突き合わせている。
3. **式の破壊は構造的に避けられる**（moveRange と insertByIndex が LibreOffice 側で追随する）。
   ★ 逆に言えば「値を交換する」実装だけは絶対に採らない（Q1 で壊れることを実測済み）。
