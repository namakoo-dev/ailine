# ailine

**自然言語のタスクを、ローカル LLM が LibreOffice Basic に書き起こし、[basrun](https://github.com/namakoo-dev/basrun) で文書に適用し、★ 効果を読み戻して検証する。**

**何が頼めるかは `ailine ops` で出る**（一覧は登録簿から自動生成 — この文書の表とずれない）。
★ freeform 最終決定（2026-08-21）: 一覧に無い依頼は、生成に入らず断る（理由・要望として
記録した旨・`ailine ops`/言い換え/2冊の突き合わせという次の手を言う）。以前の版はここで
AI が直接生成を試していたが、機械検証できない操作は行わない方針に変えた（廃止は git から
復活できる・悪印象は不可逆という非対称を踏まえた判断）。
★ 断るまでの判定は二段構え（W10 便C2、上記の日付より後に追加）: ①別名ストアへの直行 ②語
としての厳格一致（`suggest_ops`）はどちらも LLM を呼ばず即座（0秒）。①②が空振りした時
だけ③「もしかして」判定器（LLM 呼び出し1回・実測 +3秒前後）に一度だけ回してから、提案
するか断るかを決める。①〜③のどこで終わっても**生成には入らない**（機械検証できない操作は
書かない、という方針自体は不変）。
依頼が曖昧なだけで聞き返された（？ CLARIFY）場合は、言い方の問題か未対応かをここで確かめる。
（複数の操作をまとめた依頼のうち一部だけが語彙外の場合に限り、その段だけは今も AI が
直接生成する — 下の「自由生成の関所」参照。）

「Excel の見積に金額と合計を入れて」を、平文の Basic に翻訳し、`.xlsx` に適用する。
書いたコードは平文で残り、`git diff` で読める。外部にデータは送らない。

> **状態: 骨格（PoC）。** 中核のパイプライン（生成 → 適用 → 検証 → 修復）は動き、
> 純ロジックのユニットテストは CI で毎 push 緑を確認（件数は手で書かない — python -m pytest tests -q が正）。参照ライブラリの拡充と、
> 実機 LibreOffice を通した自動の通し試験は `@pytest.mark.local` 配下に1件着手済み
> （太字の `.bas` 層が本当に効いているかの通し試験。詳細は下の「CI」）。
> 実運用の前に下の「限界」を必ず読むこと。

> **姉妹版**: [ailine-ts](https://github.com/namakoo-dev/ailine-ts) — この repo の Python
> ソースを一切読まずに、挙動コーパスだけから実装された TypeScript 移植（移行手法実験の
> 成果物・テスト 61 件）。本 repo が正典で、両者は独立に保守される。

## 何をするか

```
    自然言語のタスク
        │  ローカル LLM (ollama, 既定 qwen2.5-coder:7b)
        ▼
    LibreOffice Basic  Sub Run(oDoc As Object)   ← 平文。レビューできる
        │  basrun apply（LibreOffice を headless で駆動）
        ▼
    文書に適用（★ 既定=原本に直接。検品ゲート+世代バックアップ+undo の3重安全網つき。
                --copy で従来のコピー .out 方式も選べる）
        │  適用の前後で snapshot して差分を取る
        ▼
    ★ 変化したか？ ── しなければ「何もしていない」とみなし修復に回す
```

**`✓` の意味は 1 行で**: `✓` は「あなたのファイルは**今**こうなっている」（適用後に読み戻して
確かめた事実）であって、「あなたの指示に従った」ではない。詳しくは後述の設計判断「`✓` は「あなたのファイルは今こうなっている」だけを意味する」。

```bash
# 1) ailine 本体（tag を指定して固定する）
uv tool install git+https://github.com/namakoo-dev/ailine@v0.1.0
#    uv が無ければ: pipx install git+https://github.com/namakoo-dev/ailine@v0.1.0

# 2) 文書に適用する土台（別 repo・MIT）。clone して環境変数で場所を教える
git clone https://github.com/namakoo-dev/basrun
setx BASRUN "%CD%\basrun\basrun.py"       # Windows。bash なら export BASRUN=...

# 3) 診断（python / openpyxl / ollama / モデル / LibreOffice / basrun / demo を一度に見る）
ailine doctor
```

LibreOffice と ollama（既定モデル `qwen2.5-coder:7b`）は別途入れる ── どちらも
`ailine doctor` が在否を名指しで教える。

repo から直接動かす場合は install 不要で `python -m ailine ...`（以下の例の `ailine` を
これに読み替える）。

## 使い方

### まずこれを打つ

```bash
ailine demo
```

同梱のサンプルを**今いる場所に置いて**、次に打つ行まで見せる。
★ 足りないもの（LibreOffice / basrun / ollama / モデル）があれば、**落ちるコマンドを勧めずに**
何が無いかと直し方を先に言う。repo から動かす場合も install した場合も同じに動く。

以下の例の `sample.xlsx` は `ailine demo` が置いたファイル。自分のファイルで読み替えてよい。

```bash
# 生成 → 検品ゲート → 原本に反映 → 変化を検証 → 差分を表示（既定=原本直接・自動バックアップ+undo つき）
ailine run sample.xlsx "売上から原価を引いた利益の列を作って"

# 生成して見せるだけ（レビュー用。適用しない）
ailine run sample.xlsx "..." --dry

# ★ W8b-2: 既定で原本に直接反映する（反映前に自動でバックアップを作る）。
# 何もつけなくてよい
ailine run sample.xlsx "..."

# 原本には触らず <book>.out に結果を作りたいとき（旧既定・原本は無変更）
ailine run sample.xlsx "..." --copy

# LibreOffice 往復だけで失われる飾り（条件付き書式・図形・ピボット・VBA 等）を
# 検出したら、原本に触る前に申告して止まる（exit 4）。承知の上で続けるか
# （バックアップから ailine undo で戻せる）、.out に切り替えるか選ぶ
ailine run sample.xlsx "..." --accept-loss
ailine run sample.xlsx "..." --copy   # ゲートも走らせず原本に触らない

# ★ W10a: 既存データを持つ列への上書きが起きる場合（列名の数字誤解決を含む）は
# --ask 無指定でも確認を挟む（対話可なら y/N・非対話なら exit 7）。承知の上で続ける
ailine run sample.xlsx "..." --overwrite

# ★ freeform 最終決定（2026-08-21）: 単発の依頼が DSL 語彙に分類できない場合、以前は
# ここで AI が直接生成（自由生成）していたが今は生成に入らず即座に断る。--allow-freeform は
# 後方互換のため受理するだけ（廃止告知 1 行が足されるだけで断り自体は変わらない）
ailine run sample.xlsx "..." --allow-freeform

# 別のモデルに載せ替える（天井を上げたいとき）
ailine run sample.xlsx "..." --model qwen2.5-coder:32b

# 参照ライブラリ / ヘルパのディレクトリを差し替える（既定は ./refs, ./helpers）
ailine run sample.xlsx "..." --refs my_refs --helpers my_helpers

# 生成の温度・修復の最大回数・適用タイムアウト秒を調整する
ailine run sample.xlsx "..." --temperature 0.1 --repair 3 --timeout 60

# 見出しが何行目か機械が確信を持てず「？ 見出しが何行目か分かりません」で止まったとき、
# 見出し行(1起点)を明示して自動検出をスキップする
ailine run sample.xlsx "..." --header-row 3

# ★ 対象シートをシート名で明示指定する（省略時は依頼文中のシート名の言及 → 1枚目。
# 複数シートのブックで「〇〇シートで」「N枚目のシートで」と依頼文に書けば、指定しなくても
# 機械的な名前照合で解決する。適用前に必ず
# 「操作するシート: 2枚目『工事台帳』（依頼文から判断・このブックは3シート）」と明示する）
ailine run demo/請求書.xlsx "工事台帳シートで取引先ごとの売上を集計して"
ailine run demo/請求書.xlsx "取引先ごとの売上を集計して" --sheet 工事台帳

# 結果を JSON でも出す（changes/advisories/out などを機械可読で受け取る）
ailine run sample.xlsx "..." --json

# 起動した LibreOffice を落とす
ailine stop

# セットアップを診断する（python/openpyxl/ollama/モデル/LibreOffice/basrun/demo）
ailine doctor

# 実行履歴を見る（新しい順。既定 10 件）
ailine history --max 20

# 原本への反映前のバックアップから復元する（復元前の現状も自動で退避＝復元自体も可逆。
# 退避先は backups/<フォルダのハッシュ>/undo/ で、遡りの段数には数えない）。
# ailine undo が restore の昇格版（あと何段遡れるかを表示・restore は互換のため残す）。
# 最も古い世代まで戻ると「これ以上は戻せません」と言って止まる（終了コード 1）
ailine undo sample.xlsx
ailine undo sample.xlsx --list   # 一覧だけ表示（復元しない）

# 用語集（税率等の取り決め値）に語を登録する。「税込み合計」等で率が本文にも
# 用語集にも無い場合、この形のコピペ可能な1行が CLARIFY のメッセージに出る
ailine vocab add 消費税 1.1

# ★ 独自の言い回しの登録（2026-08-22〜）: 依頼が操作一覧に照合できなかったとき、
# 「もしかして: 並べ替え？」と候補+解釈（+反映されない部分の名指し）を見せる。
# y と答えるとその場で実行され、**その言い回しが自動で登録**されて次回からは聞かずに通る。
# 登録は解釈への同意であって白紙委任ではない ── 登録済みでも確認・関所は一切スキップしない。
# 手動でも登録/取り消しできる（対応する操作名は ailine ops の左端の英字）:
ailine alias add "大きい順にして" SORT
ailine alias list
ailine alias undo      # 直近の登録を取り消す
ailine alias remove "大きい順にして"
ailine vocab list
```

`~/.ailine/vocab.json` に平坦な `{"語": 値}` で保持する（グローバルのみ・ブック別上書きは
無い）。テンプレは `vocab.template.json`（値は空・古びた法定値を焼き込まない。値を埋めて
`~/.ailine/vocab.json` にコピーするか `vocab add` で登録する）。
環境変数 `AILINE_HOME` を設定すると `~/.ailine` の代わりの置き場所を指定できる（既定は不変・上級者向け）。

試せる表を `demo/` に同梱している: `sample.xlsx`（商品×金額の一覧）・
`sales.xlsx`（部門×金額 — ピボット/集計表向き）・`lookup.xlsx`（明細＋単価表 — VLOOKUP 向き）。

## 複数ファイル（フォルダごと・2026-08-21〜）

需要の一番大きい場所は「ブックのあいだ」にある ── フォルダ単位の操作を段階的に足している。
どれも**原本は読むだけ**（1 バイトも変更しない・sha256 で機械検証）。出力は常に新しいブック。

```bash
# フォルダの棚卸し（書き込みゼロ）: 何冊読めるか・列は揃っているかを分母つきで報告
ailine scan 請求書2026-07

# 縦積み: フォルダ内の同じ形のブックを 1 冊に積む（合計行は自動で除外・出所列つき）
ailine stack 請求書2026-07 --out まとめ.xlsx

# 条件抽出: run にフォルダを渡すと、条件に一致する行を全ブックから 1 冊に抜き出す
ailine run 請求書2026-07 "金額が40000以上の行を抜き出して"

# 検算の単独再実行: 出力ブックと元フォルダだけで、行数・Σ・行の帰属を検算し直す
# （あとから誰かが編集した箇所を、どの行がいくつ→いくつまで名指しで特定する）
ailine verify 請求書2026-07_金額40000以上.xlsx 請求書2026-07
```

**報告の約束**（「漏れゼロ」ではなく「黙る漏れゼロ」）:
- 分母つき: 「40 ファイル中 38 照合 → 38 中 32 冊で計 60 行一致」。読めない冊は名指し+理由
- 行の完全会計: データ行 = 一致 + 不一致 + 合計行の除外 ── 行がどの勘定に入ったか必ず言う
- 合計行（小計・消費税・総計）は積まない。値が明細の和と合わない冊は両側の数字つきで ⚠
- 出力の右端に出所列（元ファイル・元行）── 1 行だけ抜き打ちで確かめられる
- 出力 2 枚目に**検分シート**: 所見（どのファイルのどのシートのどのセルか+両側の数字+次の手）
  をクリックで元セルに飛べるリンクつきで同梱。疑わしいファイル由来の行は薄赤の帯
- 検算は書いた経路と別実装（zip+XML 直読み）── 検算が本体と同じ口から出ない

**今の範囲（正直に）**: 対象はフォルダ直下の .xlsx（.xls は名指しで断る・サブフォルダは見ない）。
列名は基準ファイルと完全一致のみ（並び違いは可・ゆるい寄せはしない）。フォルダへの操作は
今は抽出だけ ── それ以外を頼むと名指しで断って 1 冊指定を案内する。

**Google スプレッドシートは？** ファイル → ダウンロード → Microsoft Excel (.xlsx) で
落とせば、そのまま使える（こちらからスプシに接続する機能は無い ── データを外に出さないため）。

## CSV（読み取り検疫つき・2026-08-22〜）

CSV を Excel で開くと壊れるもの ── 先頭ゼロの品番（0123 → 123）・16 桁以上の数字列の
桁溢れ・`=` で始まるセルの数式化け ── を、**壊さずに** .xlsx へ持ち込む。

★ 正直に言う限界（2026-08-24 の実測）: 数字だけの列を文字列として守る閾値は **16 桁**。
実物の JAN は **13 桁**なので数値として読み取られる。値そのものは壊れない（13 桁は
浮動小数の有効桁に収まる）が、**Excel の表示は列幅次第で 4.9E+12 になる**。
「コード列は必ず文字列」にすると、本物の数量列まで文字列にしてしまうため、今は閾値を
下げていない。★ 発火条件: 13 桁の実データで**値そのものが壊れた**実測が出たら、
見出し語（JAN/コード/品番）を手掛かりにする形で作り直す。

```bash
# CSV → xlsx 変換（LLM 不使用・0 秒起動）。<元名>.xlsx を CSV の隣に作る
ailine csv 売上一覧.csv

# run に .csv を渡すと、同じ検疫で <元名>.xlsx を作ってから通常の操作を適用する
# （出力は常に xlsx・元の CSV には 1 バイトも書かない）
ailine run 売上一覧.csv "金額で降順に並べ替えて"
```

- 文字コードは BOM → UTF-8 → cp932 の順で判定して**開示**する（EUC/JIS/UTF-16 は対象外と正直に言う）
- 列ごとに 数値/日付/文字列 を**列単位・一票拒否権つき**で判定して開示する。先頭ゼロ・
  16 桁超・`=`/`@` 始まり・全角数字・△/括弧の会計負数は文字列のまま保持（解釈しない）
- `✓` が言うのは**転送**だけ ──「読み取った N 行×M 列を 1 セルも変えずに書いた
  （欠落0・不一致0・余剰0）」。「正しく読み込みました」とは言わない。文字列で保持した列は
  「Σ で検算していません」と明示する
- 判定に迷うデータ（暦として成立しない日付・桁区切りの不整合など）は ⚠ で
  **セルの値と物理行まで名指し**し、`✓` を `△` に落とす
- 元 CSV の sha256 を照合して「原本無変更」を機械で確かめる
- 対象外（正直に）: CSV への書き出し・フォルダ内 CSV の一括処理（scan/stack は対象外として件数を名指しし、
  1 本ずつ `ailine csv` を案内）・区切り文字の自動判定（拡張子 .csv のカンマ区切りのみ）

## 帳票を作る（表 → 書類）

請求書・見積書・領収書のように、**表の 1 行を 1 枚の書類にする**。
★ **雛形は人が作る。機械は埋めるだけ。** 機械が触ってよいのは印のあるセルだけで、
それ以外は 1 セルも変えない（変わっていないことを読み戻して確かめる）。

### 印（プレースホルダ）の書き方

雛形シートの、**値を入れたいセル**に `{{列名}}` と書く。列名はデータシートの見出しと同じ綴りにする。

```
雛形シート（人が作る・書式も罫線も自由）
  A1: 請 求 書
  A3: 宛先        B3: {{取引先}}
  A5: ご請求金額  B5: {{金額}}          ← 数値書式はそのまま残る
  A9: 備考        B9: 毎度ありがとうございます   ← 印が無いセルは触らない
```

```bash
ailine run 売上表.xlsx "売上表から取引先ごとに請求書を作って"
```

- 1 セルに置ける印は **1 つまで**。`{{取引先}} 様（担当: {{担当者}}）` のように 2 つ書くと、
  埋める側が同じセルに 2 回書いて片方が消えるため、**埋めずに断る**（雛形を直してもらう）
- 印が指す列がデータシートに無ければ、埋める前に名指しで断る
- シート名は取引先名から機械が作る（Excel の禁止文字 `\ / ? * [ ] :` は `_`・31 文字で切る・
  同名は `_2`）

### 様式に写す（表 → 別の様式の表）

列の並び・名前・単位が違う「別の様式」へ機械的に写す（受注 CSV → 出荷 CSV、出納帳 → 会計ソフト様式）。
雛形シートの **見出し行の直下**に `{{列名}}` を並べる。

```bash
ailine run 出納帳.xlsx "出納帳を様式シートの形に写して"
```

### 1 セルに詰まった値を分ける

```bash
ailine run 一覧.xlsx "URL列を改行ごとに別のセルに分けて"
```

区切りは 改行 / カンマ / 、 / スペース / ・ など。★ `✓` の根拠は 1 つだけ ──
**割った断片を同じ区切りで繋ぎ直すと元と一致する**（「それらしく分かれた」では出さない）。

### 期間で絞って集計する

```bash
ailine run 日報.xlsx "2026/3/26から2026/4/25までの分だけ現場ごとに売上を集計して"
```

締め日の期間は**両端を含む**。時刻つきの列でも「4/25 23:00」は 4/25 に入る。
★ 日付が**文字列**で入っている列は、辞書順で比べると狂うので正直に断る。
★ 抽出と集計のような**複数段**の依頼では、後段は**前段の出力シートを対象にする**
（「3/26〜4/25 だけ現場ごとに集計して」が 1 コマンドで通る）。連鎖したことは
「（1段目の出力『日付2026_3_26以上』を対象にしました）」と毎回出す ── 黙って対象を変えない。
依頼文に「〜シート」とはっきり書いた場合は**人の指定が勝つ**。その指定が前段の出力でない
時は ⚠ で名指しし、`✓` は `△` に落ちる。
## 書き出し（出したものを読み戻して確かめる）

```bash
# シートを CSV へ（会計ソフト取り込み用。0 落ちを作らない）
ailine export-csv 出納帳.xlsx --sheet 出納 --encoding cp932

# ブックを PDF へ（紙で出す・添付する）
ailine export-pdf 請求.xlsx --sheet 請求 --fit-to-width
```

どちらも「書き出した」ではなく **「書き出したものに元の値が入っている」** を主張する。

- `export-csv`: 書いた CSV を読み戻して元シートと突き合わせ、**欠落 / 不一致 / 余剰**を数える
- `export-pdf`: 出した PDF の**テキスト層**を読み戻し、元の値が載っているかを数える
  - ★ 実測（2026-08-24）: 既定のまま出すと**列幅で文字が切れて PDF から消える**
    （「あかつき商事」が落ちた）。読み戻しがそれを掴んで `✓` を出さない。
    `--fit-to-width` を付けると列幅を中身に合わせて出し直せる
  - 読み戻しには `pdfplumber` が要る（任意の依存）。入っていなければ PDF は作るが
    **`✓` を名乗らず**、何を入れれば保証できるかを言う
## 終了コード

自動化や CI から**何が起きたか**を番号で見分けられるようにしてある。特に
「⚠ が出た（道具は正常）」と「道具が壊れた/前提が無い」は別の番号にした。

| コード | 意味 | 典型 |
|---|---|---|
| 0 | 成功 | ✓ または △（⚠ つきで宣言どおり）で終わった |
| 1 | 検証の失敗 | 適用したが事後条件を満たさない・no-op のまま直せない |
| 2 | 引数の誤り | argparse が出す使い方のエラー |
| 3 | 聞き返し（CLARIFY） | 見出し行が決まらない・語彙外で断った・2 冊目のパスが無い |
| 4 | 往復忠実度ゲート | LibreOffice 往復で失われる飾りを検出して止めた（`--accept-loss`/`--copy`） |
| 5 | 検算の不一致 | `verify` が行数・Σ・帰属の食い違いを見つけた |
| 6 | 並行実行の拒否 | 別の ailine が実行中（run.lock） |
| 7 | 上書きの関所 | 既存データを消す操作を非対話で止めた（`--overwrite`/`--copy`） |
| 8 | 自由生成の関所 | 複合計画の語彙外の段を非対話で止めた |
| 9 | 実行の前提が無い | openpyxl 未導入・basrun 不在・ollama 不通・モデル未取得・LibreOffice が開けない・文書が無い |

★ 9 は 2026-08-23 に 1 から切り出した。それ以前は依存の欠落も検証の失敗も同じ 1 で、
CI から区別できなかった（外部 repo の取り込み調査が実測で見つけた穴）。

## 設計判断（なぜこうしたか）

計測に基づく（`basrun_spike` 2026-08-10、qwen2.5-coder:7b）。

- **モデル非依存** — `--model` で差し替える。天井はモデルの大きさでなく
  「正しい参照例の供給 ＋ 効果の検証」で上げる。実測で **7B が正解例 1 本で
  苦手層（新シート・ソート・グラフ）を 0% → 67%** まで上げた（残ったソートの
  取り違えは、のちに下の「ヘルパ」方式で解決）。
- ★ **検証をループに（no-op ガード）** — 適用の前後で文書を snapshot し、
  値・数値書式・背景色・太字・**罫線・結合・列幅・行高・水平配置**・シート・グラフの変化を見る
  （構造や装飾だけの変更も取りこぼさない）。LibreOffice + LLM は
  **「実行時エラー無しで成功と報告し、実際は何もしない」**ことがある（もっともらしい
  UNO の幻覚）。変化ゼロなら失敗として修復に回す。
- ★ **既定で原本にそのまま反映（W8b-2）** — 「壊さない」の担保は、もう「コピーにしか
  書かない」ことではない。反映前の**検品と関所**・**世代バックアップ**・`ailine undo`
  の組み合わせでまかなう:
  ①**往復忠実度ゲート** — LibreOffice に一度通すだけ(何もしないマクロ)で失われる飾り
  （条件付き書式・入力規則・図形・ピボット・VBA・_rels）を検出したら、原本に触る前に
  申告して止まる（exit 4。`--accept-loss`/`--copy` で選ぶ・喪失ゼロなら無言）。
  ②★ **破壊の関所（W10a・W10c で全 op へ一般化）** — 既存データを持つ列への上書きが
  起きる操作（列名の数字誤解決等で実データ列を対象にしてしまうケースを含む）は、
  `--ask` 無指定でも確認を挟む（対話可なら y/N・非対話なら exit 7 で
  `--overwrite`/`--copy` を案内。新規列作成・末尾追記・書式のみの変更は素通し）。
  ★ W10c より前は COMPUTE_COLUMN の target だけが対象で、転記(LOOKUP_FILL)はこの
  関所を素通りしていた（監査実測の事故）。今は「どの op がどの引数を書き込み先の列と
  するか」を `OP_WRITE_TARGET` に宣言し、関所はその宣言を読む一般形（新しい op を
  足すとき宣言漏れが無いかを機械テストで検査する）。
  ★ **転記(LOOKUP_FILL)の対象列の前提** — 指定した対象列が対象シートにまだ無い場合、
  依頼文にその列名が書かれていれば新規作成する。書かれていなければ、実在する別の列に
  黙って解決して上書きすることはせず（それ自体が実測した事故の原因）、確認を求めて
  止まる。実在する列を指名した場合も、依頼文にその列名が無く、参照表（source_sheet）
  の値の列（常に2列目・`VLookupFromTable` ヘルパの仕様）とも一致しなければ、上書き
  対象の取り違えを疑って同様に止まる。③**世代バックアップ + `ailine undo`** —
  反映のたびに自動でバックアップし、残っている世代の数だけ `ailine undo` で1段ずつ遡れる
  （`~/.ailine/backups/<フォルダのハッシュ>/`＝同名ファイルが別フォルダにあっても
  取り違えない）。最も古い世代まで戻ったらそこで止まる（「これ以上は戻せません」と
  言って非零で終わる・何もしていないのに `✓` は出さない）。④**機械検証** — no-op ガード・事後条件チェッカーで「変化したか」
  「（DSL経路は）正しいか」を見る。原本には触らず従来どおりコピーで試したい時は
  `--copy` を使う（`<book>.out.xlsx` に生成・原本は無変更・ゲート/関所も走らせない）。
  ⑤★★ **freeform 最終決定（2026-08-21）— 単発の語彙外は生成に入らず即座に断る。**
  旧 W10b「自由生成の関所」（依頼が DSL 語彙に分類できず AI が直接作成した場合、事後条件
  チェッカーが無く「変化したか」しか機械確認できない・生成コードを見せた直後・適用の
  直前に y/N を挟む・非対話なら exit 8）は**単発の依頼からは廃止した**。理由:
  不完全な機能が見えたままだと信頼感が失われる・警告は査定から守らない（実測）・
  可逆性の非対称（廃止は git から復活できるが悪印象は不可逆）・恩恵層が実測上不在
  （詳細は `DESIGN-20260821-multifile.md`「freeform 最終決定」節）。今は語彙外の依頼を
  `ailine ops`/言い換え/2冊の突き合わせへ即座に案内し、依頼文を要望として記録する
  （頻度×原始性で今後の開発キューに使う）。`--allow-freeform` は後方互換のため受理する
  だけで、廃止告知が1行足されるだけ。
  ★ **複合計画（`ailine run <book> "A して B もして"`）の一部だけが語彙外の場合に限り**、
  旧 W10b の仕組み（y/N の関所・exit 8・ヘルパ総なめ検出の強調表示）はその段だけ今も
  健在（`run_freeform_plan_step`）── 単発への昇格は意図的に見送った実装判断。
- ★ **その他の安全機構（W8b）** — ①**Excel ロック検出**: 同フォルダの `~$`
  ロックファイルと書き込み可否を run の最初に見る。②**原子的な置換**: `os.replace()`
  で torn write（書きかけの状態が外から見える窓）を塞ぐ（失敗時は copy2 にフォールバック
  し、その旨を表示）。③**グローバル run ロック**: 基盤の LibreOffice が単一インスタンス
  前提のため、`ailine run` は同時に1本だけ（別プロセスが実行中なら待たせず即エラー）。
- **参照ライブラリ** — `refs/*.bas` を few-shot に供給。苦手な操作（並べ替え・
  グラフ・新シート）の**動作検証済みの正解例**を渡して補う。追加は `refs/` に置くだけ。
- ★ **達成検証層（M2a）** — 「✓ の下に隠れた失敗」（幽霊データ・無関係なすり替え・
  1 行の静かな欠落）への機械的対抗。差分の後に助言として表示する（ブロックはしない）。
  - **幽霊データ検出** — 変更セルの全部が原本の使用範囲外に集中している場合だけ
    「★ 疑わしい: 変更が元データの範囲外です（Z2:Z6）」。
  - **一様埋め検出** — 変化前が全部空欄・変化後が全部同一値（特に 0/空文字）の場合だけ
    「★ 疑わしい: 空欄への同一値の一括書き込みです（値 0 × 5 セル）」。
  - **件数の突き合わせ** — 変更が単一列に集中している場合、「列 C: データ 3 行のうち
    2 行を変更（1 行は未変更）」を添える（りんご欠落型を1秒で見えるように）。
  - **依頼文と変更範囲の重なりチェック** — タスク文言に「列Z」「行5」「シート名」等の
    明示的な言及があるのに、変更が全く重ならない場合だけ「★ 依頼で言及された『列Z』
    は存在しません/変更されていません」。言及ゼロのタスクでは何も言わない。
  - ★ **既存シートの中身の丸ごとすり替え検出（W10e）** — 自由生成が依頼と無関係な内容で
    既存シートを丸ごと上書きしても、以前は「依頼にない新しいシートが作成されました」
    （別シートの新設）しか申告せず、破壊された既存シートには無言だった（実測事故）。
    原本にあった非空セルが**全部**別の値に変わった場合だけ「★ 疑わしい: 既存シート
    『集計』の中身が置き換わりました」を出す（一部だけの更新・再計算は対象外）。
    `AGGREGATE`/`PIVOT` が同名シートを宣言どおり再生成する正常系（既存の「集計」
    シートを再集計する等）は中立表示に落とす（オオカミ少年防止・W10c/W10d と同じ形）。
  - ★ **宣言済みの効果は警告にしない（誤爆を条件分岐でなく宣言で消す）** — 各 op は
    「どこに書くか（既存列/新規列/データ末尾の新規行/新規シート/書式のみ）」と
    「どのシートを読むだけか」を `OP_WRITE_TARGET` に宣言する。助言はその宣言を読み、
    合計行の追記（`APPEND_TOTAL`。合計行は定義上ずっと元データの範囲外に出る）と、
    新規シートにしか書かない操作（`AGGREGATE`/`PIVOT`）が名指しの入力シートを読むだけで
    無変更であること、については★を出さない。どちらも以前は成功するたび毎回出ていた。
    抑制は保守的 — 例えば末尾追記の宣言があっても、元データの列範囲より外へ出たセルが
    混ざっていれば従来どおり★を出す。
  - どれも保守的（両条件とも全セルがそれに該当した時だけ発火）＝誤検知回避優先。
- ★ **倍率(税率等)は LLM に計算させない** — 「消費税10%」を LLM に自分で 1.1 へ換算
  させると幻覚する（実測: 8% と誤ることがあった）。`APPEND_TOTAL` の倍率は
  ①依頼文の明示率（10%/1.1倍 等）を機械の正規表現で抽出 ②無ければ用語集
  （`vocab add`）を引く、の2段で**LLM を介さず**確定する。ラベルが「税込み」等
  なのに倍率が確定できない場合は断定せず確認を返す（税抜き金額に「税込み」の
  ラベルが付く恒真の誤りを防ぐ）。
- ★ **「機械検証済み」＝計画どおり。依頼どおりとは別（W10e）** — 事後条件チェッカーが
  検証しているのは「翻訳が組んだ計画（対象・値）どおりに実行されたか」であって、
  「その計画が依頼を正しく解釈しているか」ではない。複合依頼では、翻訳が前の段の
  対象を引きずって別の段の target に混入することがある（実測: 「数量と単価をかけた
  金額列を作って、見出しを太字にして」で、2段目の対象が1段目の新規列名に化けた）。
  この時チェッカーは「計画どおり」に合格するため、対策は3段構え:
  ①複合計画は各段の対象を「◯段目: 解釈: ...」として適用前に必ず表示する（単発は元から
  表示済み）。②**解決された対象を依頼文の語と機械で突き合わせ、その結果を `✓` の強さに
  反映する**（次項）。
  ③さらに、BOLD/FILL_COLOR/CENTER_ALIGN の対象がこの計画で直前に新規作成された列を
  指していて、かつ依頼文に「見出し」とある場合だけ、対象の食い違いを名指しで警告する
  （fewshot・プロンプト側の作り込みでは 7B に効き切らないため、機械側の決定論チェックで守る）。
  ★ ②と③が同じ対象について同時に鳴るときは、⚠ を並べず**1本にまとめる**（「対象『col:数量*単価』
  （この計画の直前の段で新規作成された列）は依頼文の語と機械照合できません…」）。
- ★ **対象が依頼文の語と照合できたかを、`✓` の強さに反映する** — 上の実測事故では、
  依頼文に「見出し」という語があり、解決された対象は `col:数量*単価` だった。**この2つは
  矛盾しているのに、機械は一度も突き合わせていなかった。** 倍率や書き込む値に対して既に
  やっていること（LLM に確定させず機械で照合する）を、**どこを操作するか**へ広げた。
  対象の出所を3段階に分け、段階に応じて主張の強さを変える:
  ①**依頼文の語と機械照合できた** → `✓` 満額（何も足さない）。
  ②**依頼文はその対象について無言**（ブックの実体・既定から機械決定した） → `✓` は出すが、
  その run 固有の1文で範囲を狭める（「★ ただし対象『row:1』は依頼文の語と機械照合して
  いません」）。以前ここには**成功した全ての run で必ず出る**注記があったが、発火率 100% ＝
  情報量ゼロなので廃止し、実際に照合できなかった対象だけを名指しする形にした。
  ③**依頼文にその対象を指す語があるのに、解決値と一致しない** → **`✓` を出さない**。
  適用前に ⚠ を出し、既存の関所（原本へ直接反映する時だけ確認を挟む・新しい終了コードは
  作らない）で確認を求める。人が続行を選んでも `✓` は出さない（`✓` は「機械が確かめた」の
  意味であって、人の承諾は機械の照合の代わりにならない）。
  照合の材料は実在物だけ（実在列名・実在シート名・行番号・見出し行）で、依頼文から自由に
  名前を切り出すことはしない。実在名を短く言った場合（実列名『小計金額』を「小計の列」）は
  照合できたと見なすが、その断片が**他の実在列も指しうる**なら証拠として採らない
  （`数量*単価` の『数量』は別の実在列でもあるので、照合の根拠にならない）。同じ理由で、
  依頼文に現れてはいても**他の実在名の一部としてしか説明できない**出現も証拠にしない
  （『金額』と『税込金額』が両方ある帳票で「税込金額で並べ替えて」と頼んだのに『金額』列が
  選ばれた run では、以前 `✓` が出ていた ―― 税抜きで並べ替えたまま「機械検証済み」と
  言っていた。事後条件は「計画どおり」なので正しく通ってしまう）。
  反証になるのは、**ここまでのどのスロットも拾わなかった語だけ**（「金額で降順に並べ替えて
  見出しを太字に」の『金額』は1段目が拾っているので、2段目の反証にはならない）。
  ★ 「証拠が無い」（②）と「反証がある」（③）を同じ扱いにしない — 止めるのは③だけ。
- ★ **`✓` は「あなたのファイルは今こうなっている」だけを意味する** — 以前は `✓ 機械検証済み`
  が3つの違う意味で出ていた（①原本に入った ②入っていない（複合計画の別の段が失敗して
  全段破棄）③そもそも実行していない（`--dry`））。原因は位置で、`✓` が**原本への反映が
  決まる前**に確定していた＝最終ファイルを一度も読み戻していなかった。現在は `✓` を出せる
  場所が1箇所しかない: **反映が確定した後に、その最終ファイルを openpyxl で開き直して
  観測できた時**。段別の行と `--dry` からは `✓` を外し（段は「実行: 3 行を検証（降順）」の
  ように evidence だけ述べる）、失敗して終わる run は必ず「原本は変更していません」と
  作業結果の在り処を言う。読み戻せなければ `✓` は出さない。
  ★ 事後条件の**再実行**はしない（`APPEND_TOTAL` の後に `SORT` が来れば合計行は正当に動き、
  正しい run が偽 fail になるため）。読み戻すのは「反映が成功したこと」だけ。
- ★ **一括定数書き換え（`SET_COLUMN_VALUE`・W10e）** — 「備考列を全部『確認済み』に
  して」のような、既存列を同じ1つの値で埋める依頼は DSL 語彙に無く、常に自由生成
  （事後条件チェッカー無し）へ落ちていた（実測: 総務事務の頻出操作に信頼できる経路が
  無かった）。書き込む値は LLM に確定させない（A' 原則）— 依頼文の「」/『』で囲まれた
  引用を機械抽出し、ちょうど1つに絞れない場合は CLARIFY。既存列への書き込みなので
  「破壊の関所」の対象になる（既存値があれば上書き確認を挟む）。
- ★ **対象シートの決定（複数シートのブック）** — 実務の請求書・工事台帳・取引先マスタは
  複数シート構成が普通で、以前は書き込み対象が常に**1枚目固定**だった（依頼文でシート名を
  名指ししても無視される・エラー文が誤って1枚目の列名を出す誤誘導つき）。今は
  ①`--sheet` 明示指定 ②依頼文中の実在シート名の言及（完全一致・複数一致は長い方だけ残す）
  ③「N枚目」の序数表現 ④既定=1枚目、の優先順位で対象シートを機械的に決める（LLM に
  シート名を確定させない・A' 原則）。複数シートのブックでは、適用の前に必ず
  「操作するシート: 1枚目『請求明細』（このブックは4シート）」のように対象シートを
  明示し、実行を確かめる「解釈:」行の先頭にも
  「シート:『請求明細』(1枚目)」として載せる（1枚だけのブックは曖昧さが無いため沈黙・
  出力は従来どおり）。
  `LOOKUP_FILL`（転記）は元々 `target_sheet`/`source_sheet` を名前で受け取っており、
  以前は転記先が1枚目でないと拒否していた制限を撤廃した。
- ★ **シート名と列名の衝突（対象シートの取り違え）** — 上の②は「列を指したつもりの語」も
  拾ってしまう: `売上データ`/`金額` の2シート構成に「金額を降順に並べ替えて」と頼むと、
  2枚目『金額』シートが対象になっていた（`明細`/`合計` に「合計行を追加して」も同型）。
  対象シートにも同名列があれば**間違ったシートを並べ替えて「成功」してしまう** —
  エラーで止まるより後で気づきにくい。今は:
  **明示マーカー付きの言及**（そのシート名の直後が「シート」「タブ」、または「N枚目」の
  序数表現）は無条件に採用し、**裸の言及**はその語がどこかのシートの列見出しにも存在する
  なら曖昧と判断して**既定(1枚目)へ後退**する（`--sheet` は常に最優先で、この判定と無関係）。
  後退したときは、翻訳が終わって**操作が確定してから**（＝具体的な日本語で選べる状態で・
  原本にはまだ触れずに）3択で聞く: ①上の解釈のとおり実行する ②もう一方のシートを対象に
  翻訳からやり直してプレビューを見る（見てから y/N）③やめる。
  ★ **聞くのは標準入力が端末のときだけ。** `--json`・パイプ/リダイレクト・CI・`--dry`
  では**入力を待たず**、告知だけ出して既定(1枚目)で進む（＝従来どおりの挙動。ここで
  止めると、動いていたスクリプトが黙って壊れる）。
  ★ 既知の限界（衝突検出）: 衝突の判定に使う列見出しは「全シートの物理1行目」を見た結果。
  タイトル行があって見出しが5行目にあるブックでは衝突を見逃す（＝この機能が無かった頃と
  同じ挙動になるだけで退行はしない）。見出し行の確定は**対象シートが決まった後**にしか
  できないため、順番として避けられない。
  ★ 既知の限界（見出し行検出）: 見出し行の自動検出（StructDump）は対象シートが翻訳より
  前に決まる必要があるため、依頼文が対象シートでなく`LOOKUP_FILL`の参照シート名だけを含む
  ような書き方だと、見出し行検出が参照シート側に寄ることがある（対象シートへの
  書き込み先そのものは常に正しい — 影響するのは見出し行の自動検出精度のみ・
  物理1行目でない見出しの参照シートで起こりうる稀なケース。`--header-row` で
  明示すれば回避できる）。

## ★ 限界（正直に）

- **珍しい UNO 操作は外しやすい。** LibreOffice Basic + UNO は学習データが薄い。
  参照ライブラリで補う設計だが、載っていない操作は当たり率が落ちる。
- **no-op ガードが保証するのは「変化したこと」だけ。**「**正しいか**」は保証しない ──
  出力の差分を人が見て判断すること。ツールは必ず「差分を見て判断せよ」と促す。
  M2a の助言（★ 疑わしい 等）も同じ層 — 「変化」の機械保証であって、「依頼を
  達成したか」は助言＋人の確認が要る。
- **timeout kill 後に固まった LibreOffice** は、稀に手動で `ailine stop`
  （または OS のタスクマネージャ）から止める必要がある場合がある。
- ★ **倍率の機械確定は DSL 経路(APPEND_TOTAL)に限る。** 依頼が `APPEND_TOTAL` として
  分類されなかった場合（列が曖昧・見慣れない書き方等で翻訳が `OUT_OF_VOCAB`/FREEFORM に
  分類された場合）、倍率の機械抽出・用語集・CLARIFY 番人は一切効かない。
  ★ freeform 最終決定（2026-08-21）: **単発の依頼はこのリスクごと消えた** — 語彙外は
  生成せず即座に断るので、LLM が税率を自分で仮定する機会自体が単発では無い（実機確認:
  以前は同じ「小計」列を持つ表でも "税込み合計を出して" のように依頼文だけでは対象列が
  一意に決まらない書き方だと自由生成に落ち、「消費税率は10%として計算」等をコードに
  直接書くことがあった）。**複合計画の一部だけが語彙外の場合に限りリスクは残る**
  （その段だけ今も AI が直接生成する）── ★ 生成コード中の率らしい数値リテラル
  （0.05〜0.2 / 1.05〜1.2 の小数）が依頼文にも用語集にも出典が無い場合は「★ 率らしい
  数値 (0.08) が依頼に無いのに使われています — 検算してください」を助言として添える
  （`scan_rate_literals`）。ただし機械的なブロックではなく、あくまで検算を促す助言止まり。
- **人が同ファイルを開いたまま実行した場合は未検証。** ロックや競合の扱いは
  基本の LibreOffice/OS の挙動に委ねている。
- **ローカル完結。** ollama と LibreOffice が要る。**外部にデータは送らない。**

## ヘルパ（`helpers/`）— 難所は「呼ぶだけ」

参照例（few-shot）だけでは確度が上がりきらない操作がある。典型が**並べ替え**で、
7B は正しい例を見せても `ContainsHeader` の真偽を半分ほど滑らせた（判断ミスで、知識では直らない）。

そこで **arcane な操作は人が検証したヘルパに閉じ込め、モデルには `Call` で呼ぶだけ**させる。
`helpers/*.bas` は生成コードと同じライブラリに同梱され、`Sub Run` から呼べる。

| ヘルパ | モデルが書くのは | 隠している難所 |
|---|---|---|
| `SortByColumn(oDoc, headerRow, lastCol, col, ascending)` | `Call SortByColumn(oDoc, 0, 4, 1, False)` | 範囲検出・`SortFields`・`ContainsHeader=False` |
| `InsertChart(oDoc, headerRow, catCol, valCol, kind, maxDataRow)` | `Call InsertChart(oDoc, 0, 0, 1, "bar", 4)` | 見栄えのするグラフ(棒/折れ線/円)。タイトル・系列色を見出しから自動導出（棒/折れ線は横軸タイトルも。データラベルは付けず読ませる清潔な既定。LO native の表現力を自前で引き出す）。`maxDataRow` は省略可（合計行のある表でだけ codegen が渡し、合計行をグラフ範囲から除く） |
| `MergeCells(oDoc, c1, r1, c2, r2)` | `Call MergeCells(oDoc, 0, 0, 1, 0)` | 範囲を渡さず単一セルに merge する誤りを封じる |
| `InsertRows(oDoc, atRow, count)` | `Call InsertRows(oDoc, 1, 1)` | `Rows.insertByIndex`・0起点の位置 |
| `DrawTableBorders(oDoc)` | `Call DrawTableBorders(oDoc)` | データ範囲を自動検出・`TableBorder2` の格子 |
| `AutoFitColumns(oDoc)` | `Call AutoFitColumns(oDoc)` | 使用列を自動検出・`OptimalWidth` |
| `AlignCenter(oDoc, headerRow, lastCol)` | `Call AlignCenter(oDoc, 0, 4)` | 表全体を中央揃え。セル配置は `HoriJustify`（`CharHorizontalAlignment` は段落用で効かず 7B が滑る罠を封じる） |
| `FormatThousands(oDoc, headerRow, col)` | `Call FormatThousands(oDoc, 0, 4)` | 指定列に3桁区切り `#,##0`。`queryKey` の -1 を `addNew` で拾い Locale を正しく構築（7B は addNew を落として滑る） |
| `VLookupFromTable(oDoc, headerRow, keyCol, resultCol, lookupSheet)` | `Call VLookupFromTable(oDoc, 0, 0, 2, "単価表")` | Basic 側で照合（数式 `=VLOOKUP` はこの経路で `#VALUE!`）。参照表は 列0=キー/列1=値 |
| `PivotSum(oDoc, groupCol, valueCol)` | `Call PivotSum(oDoc, 0, 1)` | 本物のピボット（DataPilot）を新「ピボット」シートに。分類×合計を自動。★LO は開くたび再描画してセル書式を撥ねる（罫線・カンマが出ない）＝清潔な表が欲しければ下の `SummaryTable` |
| `SummaryTable(oDoc, headerRow, groupCol, valueCol)` | `Call SummaryTable(oDoc, 0, 0, 1)` | 分類×合計を新「集計」シートに**普通の表**として出す（格子罫線・カンマ・中央揃え・見出し/合計太字を native で。DataPilot でないので全部残る） |
| `StyleBold(oDoc, c1, r1, c2, r2)` | `Call StyleBold(oDoc, 0, 0, 4, 0)` | native 太字。★`CharWeight`＋**`CharWeightAsian`**（日本語）＋`CharWeightComplex` をセルに直接。text cursor は数値を壊すので使わない |

ユーザは `SortByColumn` を知らなくてよい。**「金額で降順に並べ替えて」と自然文で頼むだけ**で、
モデルが列と向きを選んでヘルパを呼ぶ。難所に触れないので滑らない（実測で完全降順を確認）。

★ **W9: `InsertRows`/`DrawTableBorders`/`AutoFitColumns`/`PivotSum` は DSL 語彙にも昇格済み**
（`INSERT_ROWS`/`DRAW_BORDERS`/`AUTOFIT`/`PIVOT`）。「3行目の前に1行挿入して」「表にけい線を
引いて」「列幅を内容に合わせて」「部門ごとにピボットテーブルで集計して」のように頼むと、
自由生成(LLM任せ)でなく決定論の DSL パイプライン（②検証→③確認→④codegen→⑤適用→⑥事後条件）
で機械検証まで通る。「ピボット」と明示しない集計依頼（「まとめて」「小計」等）は引き続き
`AGGREGATE`（`SummaryTable`・書式つき）になる。

★ **W10e: `SET_COLUMN_VALUE`（一括書換）を DSL 語彙に新設**。ヘルパは無し（既存列への
`setString` ループを直接 codegen）。「備考列を全部『確認済み』にして」のように既存列を
1つの値で埋める依頼は、以前は DSL に無く常に自由生成へ落ちていた。書き込む値は依頼文の
「」/『』の引用から機械抽出する（LLM には確定させない）。

**ヘルパも必ず basrun で動作検証してから置くこと。** 呼び方は `Call 名前(引数)`
（括弧つきで `Call` 無しは LibreOffice Basic が誤動作する）。

★ **このヘルパ表 / ailine.py のカタログ / helpers/*.bas 実体は `tests/test_helper_catalog_sync.py`
で自動突合している**（引数の個数が3者で食い違うと CI が落ちる。過去に headerRow 追加時、
README だけ古いまま6件残った実例への回帰防止）。太字（`BoldRange` の `CharWeightAsian`）は
CharWeight と揃ってセットされているかを同ファイルで静的検査するが、これは「書いてある」
ことしか保証しない。実際に日本語へ効いているかは `tests/test_bold_local.py`
（`@pytest.mark.local`・要 LibreOffice）で実測する。
